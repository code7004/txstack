# @txstack/ui

**Tx\* 컴포넌트 49종.** 쉬운 사용법과 쉬운 커스터마이징을 노린 React UI 세트다.

- **스타일시트는 한 줄이다** — `import "@txstack/ui/styles.css"`
- **겉모습은 CSS 변수로 바꾼다** — 컴포넌트마다 `--tx-*` 토큰을 내보낸다. 다크모드는 그 토큰이 뒤집히는 것이라 부품마다 손볼 것이 없다
- **런타임 의존은 `clsx` 하나** — `react` · `react-dom` 은 peer 다. 무거운 것(ag-grid · react-day-picker)은 **서브패스로 갈라** 두어 루트를 import 해도 딸려오지 않는다

이 페이지를 위에서 아래로 따라가면 한 화면을 세울 수 있다. 부품 하나하나의 이야기는 왼쪽 목록에 있다.

## 1. 설치

```sh
pnpm add @txstack/ui
```

`react` · `react-dom` 은 **peer** 라 앱이 이미 갖고 있는 것을 쓴다(`>=18`). 앱의 진입점에서 스타일시트를 **한 번** 불러온다.

```tsx
// main.tsx · App.tsx · layout.tsx — 앱에 한 번이면 된다
import "@txstack/ui/styles.css";
```

컴포넌트가 자기 CSS 를 import 하지 않는다. 그래서 번들러·SSR 환경에 따라 깨지는 경로가 생기지 않는다.

## 2. 첫 화면

폼 한 장이 가장 빠른 확인이다. **캡션 · 에러 · 필수 표시가 컨트롤과 이어져 있다** — 캡션을 누르면 포커스가 가고, 에러는 스크린리더에도 전달된다.

```tsx
import { TxButton, TxForm } from "@txstack/ui";

export function SignUp() {
  return (
    <TxForm className="max-w-md" onSubmit={submit}>
      <TxForm.Input caption="이름" placeholder="홍길동" required />
      <TxForm.Input caption="메일" type="email" error={errors.email} />
      <TxForm.Dropdown caption="나이" data={AGES} placeholder="고르세요" />
      <TxForm.CheckBox caption="약관" label="이용약관에 동의합니다" />

      <TxButton type="submit" label="가입" />
    </TxForm>
  );
}
```

`TxForm.*` 이 아니라 `TxInput` · `TxDropdown` 을 직접 써도 된다 — 폼 계층은 **이름과 메시지를 이어 주는 자리**일 뿐이다.

## 3. 겉모습 바꾸기 — 세 층

**CSS 를 덮어쓰지 않는다. 토큰을 바꾼다.** 아래로 갈수록 좁은 범위다.

```css
/* ① 앱 전체 — 브랜드 색·반경·포커스 링 */
:root {
  --tx-color-primary: #16a34a;
  --tx-radius: 0.5rem;
}

/* ② 부품 한 종류 — 그 부품이 내보내는 토큰 */
.tx-button {
  --tx-button-padding: 0.5rem 1.25rem;
}

/* ③ 한 자리만 — 인라인으로 */
```

```tsx
<TxTable style={{ "--tx-table-max-height": "20rem" }} />
```

어떤 토큰이 있는지는 **부품 페이지의 Docs 탭**에 적혀 있다. 전역 토큰은 `--tx-color-*` · `--tx-radius` · `--tx-focus-ring` · `--tx-state-*` 다.

### 다크모드

`<html>` 에 `dark` 클래스를 걸면 **토큰이 뒤집힌다.** 토글 시점은 앱이 정한다.

```tsx
document.documentElement.classList.toggle("dark", isDark);
```

부품 CSS 에는 다크 분기가 **한 줄도 없다.** 색 하나를 바꿀 때 라이트·다크를 따로 찾아다니지 않게, 재정의는 토큰 한 곳에서만 한다. 이 카탈로그 위쪽의 **테마 버튼**으로 지금 확인해 볼 수 있다.

## 4. Tailwind 와 같이 쓰기

**`className` 은 기본 클래스를 교체하지 않고 덧붙는다.** 그래서 자리·여백은 소비자가 정한다.

```tsx
<TxButton label="저장" className="w-full" />
<TxCard className="max-w-sm shadow-lg" />
```

Tailwind 를 쓴다면 **한 줄이 필요하다.** 우리 스타일은 `@layer tx` 안에 있어서, 레이어 순서를 이렇게 선언해 두면 `className` 으로 준 유틸리티가 이긴다.

```css
@layer theme, base, tx, components, utilities;

@import "tailwindcss";
@import "@txstack/ui/styles.css";
```

`tx` 는 **preflight(`base`) 뒤, 유틸리티 앞**이어야 한다. 앞에 두면 preflight 가 버튼의 배경과 여백을 지우고, 뒤에 두면 `className` 이 안 먹는다.

순수 CSS · Sass · CSS Modules 를 쓰는 쪽은 **아무것도 안 해도 된다** — 레이어를 안 쓰는 CSS 는 특이도와 상관없이 항상 이긴다.

## 5. 무거운 것은 서브패스에 있다

루트 배럴(`@txstack/ui`)은 이 둘을 **참조하지 않는다.** 쓰는 사람만 설치한다.

```tsx
// 표 · 그리드 — peer: ag-grid-community, ag-grid-react
import { TxAgGrid } from "@txstack/ui/aggrid";

// 앱에서 한 번. 필요한 모듈만 고르거나 enterprise 를 쓰는 선택을 라이브러리가 뺏지 않는다
import { AllCommunityModule, ModuleRegistry } from "ag-grid-community";
ModuleRegistry.registerModules([AllCommunityModule]);
```

```tsx
// 날짜 — peer: react-day-picker
import { TxDayPicker, TxFormDayPicker } from "@txstack/ui/daypicker";
```

**쪽 번호(`TxPagination`)는 루트에 있다** — 그리드와 무관해서, 카드 목록이나 손수 짠 표에도 쓴다.

## 6. 화면 골격

`TxAppShell` 이 자리를 잡고, 그 자리에 내비게이션 부품을 꽂는다. 좁아지면 셸이 `left` 를 **서랍으로** 옮긴다.

```tsx
import { TxAppShell, TxNavBar, TxSideNav } from "@txstack/ui";

<TxAppShell header={<Brand />} top={<TxNavBar>{gnb}</TxNavBar>} left={<TxSideNav>{snb}</TxSideNav>} panels={{ left: { resize: true, collapse: true, defaultSize: 280 } }}>
  <Outlet />
</TxAppShell>;
```

**`<nav>` 랜드마크 · sticky · 서랍은 셸이 갖는다.** 그래서 셸 안의 내비게이션 부품에는 `label` 을 주지 않는다 — 주면 랜드마크가 둘로 읽힌다.

가로로 도는 줄은 `TxNavBar`(항목에 `panel` 을 주면 메가메뉴), 세로로 서는 줄은 `TxSideNav`(아이콘만 남기고 접힌다)다. **자리가 아니라 방향으로 갈랐다.**

## 7. 라우트에서 메뉴를 뽑는다

`@txstack/route-meta` 를 함께 쓰면 **트리 하나**에서 라우터 · 메뉴 · 브레드크럼이 나온다. 경로를 바꿀 때 고칠 곳이 한 곳이다.

```tsx
const menu = getNavigableRoutes(routes, canAccess);

<TxSideNav>
  {menu.map((item) => (
    <TxSideNav.Item key={item.key} icon={item.meta?.icon} label={item.meta?.label ?? item.key} as={NavLink} to={item.path} />
  ))}
</TxSideNav>;
```

두 패키지는 서로를 import 하지 않는다 — 이어 붙이는 코드는 **소비자 몫**이고, 그 15줄은 <a href="?path=/docs/recipes-routemeta--docs" target="_top">Recipes/RouteMeta</a> 에서 실제로 돌아간다.

## 알아 두면 편한 것들

- **문구는 소비자가 준다.** 번역 키를 넘기는 것이 아니라 **번역된 글자**를 준다(`labels` prop). 어느 쪽이 맞는지 헷갈리는 이중 경로를 만들지 않는다
- **`data-tag` 가 붙어 있다.** `[data-tag="TxButton"]` 으로 테스트에서 찾거나 스타일을 걸 수 있다
- **포커스는 지우지 않는다.** 모든 누를 것에 `--tx-focus-ring` 이 걸려 있고, 마우스로 누를 때는 뜨지 않는다(`:focus-visible`)
- **움직임을 줄이는 설정을 따른다.** `prefers-reduced-motion` 이면 애니메이션이 멈추고, 저절로 도는 것(`TxTicker` · `TxCarousel`)은 스스로 서 있는다
- **controlled · uncontrolled 둘 다 된다.** `value` 를 주면 앱이 쥐고, `defaultValue` 를 주면 부품이 쥔다
