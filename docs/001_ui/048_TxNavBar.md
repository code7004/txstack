# 048 · TxNavBar

> 가로로 도는 내비게이션 줄. 항목에 `panel` 을 주면 **메가메뉴**가 된다.

|        |                                                               |
| ------ | ------------------------------------------------------------- |
| 진입점 | `@txstack/ui`                                                 |
| 소스   | [`packages/ui/src/TxNavBar/`](../../packages/ui/src/TxNavBar) |
| 테스트 | 26개                                                          |
| 짝     | 세로는 [049_TxSideNav](049_TxSideNav.md) 가 갖는다            |

## 개발 목적

사이트형 화면의 GNB 다. 세 앱이 각자 만들 때마다 같은 자리에서 같은 것을 빠뜨렸다 —
키보드로 못 열고, 항목 사이를 지나갈 때 깜빡이고, 좁은 화면에서 메뉴가 사라지거나
가로로 넘쳤다.

**`TxDropMenu` 를 여러 개 나란히 두는 것으로는 안 된다.** 네 가지가 어긋난다.

1. **규약이 다르다.** `TxDropMenu` 속은 `role="menu"` · `menuitem` 이고 **Tab 은 닫기**다.
   사이트 내비게이션은 그 규약이 아니다(APG 의 _Disclosure Navigation_) — 메가 패널 안에는
   링크 목록 · 설명 · 그림 · 검색창이 오는데, `role="menu"` 안에서는 그것들이 제대로 읽히지 않는다
2. **패널이 항목 폭이 아니다.** 메가메뉴는 **줄 전체 폭**으로 펼쳐진다. 앵커에 붙는
   `TxPopup` 으로는 그 폭을 낼 수 없다
3. **항목 사이를 지나갈 때 닫히면 안 된다.** 각자 독립이면 A 의 닫힘 지연과 B 의 열림이
   엇갈려 **깜빡인다.** 열림은 줄 전체가 하나로 쥐어야 한다
4. **하나로 두면 다섯 가지를 겸한다.** 세로로 세우는 것 · 아이콘만 남기고 접는 것 ·
   하위메뉴를 트리로 접는 것까지 얹으면 `TxCard` 를 자를 때 본 모양이 된다 —
   그래서 **세로는 `TxSideNav` 로 갈랐다**(아래 "가로와 세로를 갈랐다")

## 경계 — `TxAppShell` 이 이미 가진 것

4차에서 "`TxNavBar` 가 맡을 것은 셋(sticky · 데스크톱↔모바일 전환 · 메가메뉴)" 이라고
적었는데, **앞의 둘은 그 뒤에 셸이 가져갔다.** 확인하고 적는다.

| 무엇                            | 누가            | 근거                                  |
| ------------------------------- | --------------- | ------------------------------------- |
| 메뉴가 놓이는 자리              | **셸**          | `top` — "헤더 아래에 붙는 전체 폭 띠" |
| `<nav>` 랜드마크                | **셸**          | `top` · `left` 에 셸이 붙인다         |
| sticky · 내리면 숨기            | **셸**          | `sticky` · `"hide"`                   |
| 좁아지면 서랍                   | **셸**          | `left` 를 같은 노드 그대로 서랍으로   |
| **항목 · 패널 · 키보드 · 방향** | **이 컴포넌트** | 셸에 없다                             |

그래서 만들 것은 **띠 안의 메뉴 그 자체**뿐이다.

## 쓰는 법

```tsx
import { TxAppShell, TxNavBar } from "@txstack/ui";

const menu = (
  <>
    <TxNavBar.Item label="제품" panel={<ProductPanel />} />
    <TxNavBar.Item label="가격" as={NavLink} to="/pricing" />
    <TxNavBar.Item label="문서" panel={<DocsPanel />} />
    <TxNavBar.Item label="회사" as={NavLink} to="/about" />
  </>
);

<TxAppShell header={<Brand />} top={<TxNavBar>{menu}</TxNavBar>}>
  <Page />
</TxAppShell>;
```

**패널 안은 소비자 것이다.** 라이브러리가 메가 패널의 속을 정하지 않는다 —
그 배치가 곧 그 사이트의 정보 구조라 도메인이다. 있는 부품으로 짠다.

```tsx
const ProductPanel = () => (
  <TxGrid columns={3}>
    <section>
      <h3>업무</h3>
      <NavLink to="/products/crm">CRM</NavLink>
      <NavLink to="/products/erp">ERP</NavLink>
    </section>
    …
  </TxGrid>
);
```

혼자 쓸 수도 있다. 그때만 `label` 을 준다.

```tsx
// 셸 밖 — 스스로 <nav> 가 된다
<TxNavBar label="주 메뉴">{menu}</TxNavBar>

// 셸의 top 안 — label 을 주지 않는다. 셸이 이미 <nav> 다
<TxNavBar>{menu}</TxNavBar>
```

좁은 화면에서는 **셸이 `left` 를 서랍으로 옮기고 그 안에 `TxSideNav` 가 선다.**
이 부품은 스스로 접히지 않는다 — 상황이 하나만 남는다.

```tsx
<TxAppShell top={<TxNavBar>{menu}</TxNavBar>} left={<TxSideNav>{sideItems}</TxSideNav>} />
```

## 열고 닫는 규칙

- **마우스는 얹으면 열린다.** 항목 사이를 지나가면 **닫히지 않고 갈아탄다** — 열림을 줄이
  하나로 쥐기 때문이다. 밖으로 나가면 `120ms` 뒤에 닫는다(`TxDropMenu` 와 같은 값)
- **누르면 열리고 다시 누르면 닫힌다.** 터치에는 hover 가 없다
- **Escape 는 닫고 포커스를 그 항목으로 되돌린다**
- **Tab 은 패널 안으로 들어간다.** 메뉴 규약(Tab = 닫기)과 다른 점이다 — 패널은 메뉴가
  아니라 문서 조각이다. 패널 밖으로 나가면 닫는다
- **← → 로 항목 사이를 옮긴다.** 열려 있으면 옮긴 항목이 열린 채로 이어진다.
  `Home` · `End` 로 양 끝
- 항목이 링크면(`panel` 없음) 그냥 링크다. 열 것이 없다

## 접근성

- 패널을 가진 항목은 `<button aria-expanded aria-controls>` 다. **`role="menu"` 를 쓰지 않는다**
- 줄은 `<ul>` 이고 항목은 `<li>` 다. `label` 을 주면 `<nav aria-label>` 로 감싼다
- 지금 있는 자리는 링크가 `aria-current="page"` 로 알린다 — 라우터가 주는 것을 그대로 쓴다

## 정한 것 — 셋

### 1. 이름은 방향으로 간다

`TxMegaMenu` 는 하는 일이 또렷하지만 **패널 없이 링크만 쓸 때 이름이 과장된다** —
그러면 소비자가 "이건 메가가 아닌데" 하며 따로 만들기 쉽다. `TxNavBar` 는 4차에서 적어 둔
이름인데 **바(sticky · 자리)를 셸이 가져갔으므로** 이제 실제보다 크다.

`TxNavBar` 는 **패널을 주면 메가메뉴, 안 주면 링크 줄** 둘을 다 덮는다.
세로 짝은 `TxSideNav` 다 — 둘 다 **자리(GNB·SNB)가 아니라 방향**을 이름에 담는다.

### 2. 가로와 세로를 갈랐다 (다시 정했다)

처음에는 한 부품이 `orientation` 으로 둘을 겸하고 `collapseAt` 으로 스스로 접기까지 했다.
**되짚어 정했다** — 두 물건의 기능이 실제로 안 겹친다.

|           | 가로 (`TxNavBar`)                          | 세로 (`TxSideNav`)                                   |
| --------- | ------------------------------------------ | ---------------------------------------------------- |
| 하는 일   | **큰 패널이 떠오른다**                     | **아이콘 rail 로 접힌다 · 하위메뉴가 트리로 접힌다** |
| 겹치는 것 | 항목 · 활성 표시 · `as` 주입 · 키보드 이동 | 같음                                                 |

한 부품에 다섯 가지를 얹는 것보다 갈라 두는 것이 낫고, **`TxDropMenu`·`TxContextMenu`**
(공개는 둘, 속은 하나)라는 전례가 이미 있다.

**이름은 방향으로 간다.** 역할 이름(`GNB`·`SNB`)을 쓰면 _1차 내비게이션을 세로로 두는_
요즘 화면에서 "이걸 SNB 라고 불러야 하나" 하는 자리가 매번 생긴다. `TxAppShell` 도 슬롯
이름을 `GNB·LNB·SNB` 로 되돌릴지 따져 보고 방향으로 갔다 — 그 결을 잇는다.

**속은 아직 합치지 않았다.** 메뉴 2종도 _둘 다 올린 뒤에_ 겹치는 것을 세어 보고 합쳤다.
같은 순서를 따른다 — 지금 합치면 무엇이 공통인지 모르는 채로 추상화를 먼저 만드는 것이 된다.

좁아지면 **셸이 `left` 를 서랍으로 옮기고 그 안에 `TxSideNav` 가 선다.** 그래서 이 부품에서
`collapseAt` 을 뗐다 — 접히는 길이 하나면 상황도 하나다.

### 3. 패널 폭은 `panelWidth` — 기본은 줄 전체 폭

`"bar"`(기본)는 메뉴 줄 전체 폭으로 펼쳐진다. 흔히 말하는 메가메뉴다.
`"item"` 은 항목 아래에만 붙는다 — 항목이 많고 패널이 작을 때 쓴다.

**DOM 은 같고 CSS 만 갈린다.** 패널을 항목 안에 두되, `"bar"` 면 자리의 기준이 줄이 되고
`"item"` 이면 항목이 된다.

## 만들며 정한 것

### 열림은 줄이 쥐고 항목은 자기 자리만 그린다

항목마다 열림을 쥐면 A 의 닫힘 지연과 B 의 열림이 엇갈려 **깜빡인다.** 줄이 `openId`
하나를 쥐고 항목은 문맥에서 받아 읽기만 한다.

**닫는 시계도 줄이 쥔다.** 손이 항목과 패널 사이를 지날 때는 여전히 줄 안이므로 아무 일도
일어나지 않고, 줄 밖으로 나갈 때만 `120ms` 뒤에 닫힌다.

### 패널은 열릴 때만 그린다

감춘 채로 두면 그 안의 링크가 `Tab` 에 잡히고 스크린리더가 닫힌 메뉴의 내용을 읽는다.
`aria-controls` 도 열렸을 때만 가리킨다 — 없는 `id` 를 가리키면 거짓이 된다
(`TxDayPicker` 에서 세운 것과 같은 규칙).

### 알림은 상태 갱신 함수 밖에서 부른다

`setOpenId(prev => …)` 안에서 `onOpenChange` 를 부르면 **갱신 함수가 두 번 불릴 때
두 번 알린다.** 마지막으로 알린 것을 ref 에 두고 달라졌을 때만 부른다 —
`TxCarousel` 과 같은 방식이다.

### 항목은 세 모양이다

| 준 것          | 나오는 것                                                            |
| -------------- | -------------------------------------------------------------------- |
| `as` 만        | 그냥 링크                                                            |
| `panel` 만     | 제목 자체가 **여는 버튼**(`<button aria-expanded>`)                  |
| `panel` + `as` | **링크 + 옆에 `▾` 버튼** — 제목을 누르면 이동하고 버튼이 패널을 연다 |

```tsx
<TxNavBar.Item label="Documents" as={NavLink} to="/docs" panel={<Panel />} />
```

셋째는 **`apps/site` 를 만들면서 요구된 것**이다. 그전에는 `panel` 이 있으면 소비자가 준
`as` · `to` · `onClick` 이 **조용히 버려졌다** — 제목을 눌러도 아무 일이 없었다.

제목이 진짜 링크라 새 탭으로 열기 · 주소 복사 · 가운데 클릭이 되고, **여는 일은 버튼이
맡아 `aria-expanded` 가 거짓이 되지 않는다**(APG _Disclosure Navigation with Top-Level Links_).
`▾` 버튼은 `"<항목 이름> 하위 메뉴"` 로 읽히고, 그 문구는 `toggleLabel` 로 바꾼다.

화살표 키는 `▾` 버튼도 찾아간다 — 여는 항목만 옮겨 다니고 링크는 `Tab` 이 맡는 규칙 그대로다.
