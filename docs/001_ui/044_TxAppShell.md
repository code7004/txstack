## 개발 목적

화면 전체를 짜는 껍데기. 헤더 · 사이드 · 푸터를 앱마다 다시 짜던 것을 한 셸로 모은다. 3차에서 자른 `TxLayout` 과 따로 두려던 GNB 를 **둘 다 흡수했다** — 한 화면에 셸이 둘일 일이 없다.

## 기능

`header` · `top` · `left` · `right` · `bottom` · `footer`, 그리고 `children` 이 본문이다.
좁을 때만 화면 아래에 붙는 **하단 탭바 `tabBar`** 도 있다 — 아래 "하단 탭바 — `tabBar`".

### 쓰는 법

```tsx
<TxAppShell header={<Brand />} top={<MainNav />} left={<SideNav />} bottom={<Console />}>
  <Outlet />
</TxAppShell>
```

자리는 이렇게 쌓인다 — **`좌 · (본문 · 아래) · 우`.**

```text
┌──────────────────────────────┐   bottomSpan="screen" 이면
│ header                       │   아래 패널이 좌우까지 덮는다
│ top                          │
├────────┬───────────┬─────────┤   ├────────┬───────────┬────────┤
│ left   │ children  │ right   │   │ left   │ children  │ right  │
│        ├───────────┤         │   ├────────┴───────────┴────────┤
│        │ bottom    │         │   │ bottom                      │
├────────┴───────────┴─────────┤   ├─────────────────────────────┤
│ footer                       │   │ footer                      │
└──────────────────────────────┘   └─────────────────────────────┘
```

**슬롯은 prop 으로 받는다.** 자식을 뒤져 무엇이 헤더인지 찾지 않는다 — 그렇게 하면
조건부 렌더나 `memo` 한 겹에 못 찾고 엉뚱한 자리에 들어간다.

이름은 방향이지만 **랜드마크는 셸이 붙인다** — `top` · `left` 는 `<nav>`,
`right` 는 `<aside>`, `bottom` 은 `<section>` 이고 각각 이름이 다르다.
좌우는 글 방향을 따른다(`inline-start` · `inline-end`).

셸이 맡는 것은 여섯이다.

1. **랜드마크** — 제자리에 두고 이름을 붙인다. 이름이 없으면 스크린리더가 "탐색" 여럿을
   구분하지 못한다
2. **본문으로 건너뛰기** — 첫 Tab 에 나타난다. **본문이 어디인지는 셸만 안다**
3. **머무는 헤더** — 붙어 있거나(`true`), 내리면 숨거나(`"hide"`), 같이 굴러간다(`false`)
4. **좁아지면 `left` 를 서랍으로** — 헤더에 햄버거가 생기고 **같은 노드**를 그대로 그린다
5. **크기 조절** — `resizable` 을 준 자리는 끌어서 바꾼다. 한계를 안 줘도 **본문이 남을
   만큼만** 늘어난다
6. **접기** — `collapsible` 을 준 자리는 경계선의 스위치로 접는다. 다시 펴면 **접기 전
   크기로** 돌아온다

로고 · 메뉴 구조 · 로그인 상태는 **전부 슬롯이다.** 그것이 앱마다 다른 부분이고,
넣는 순간 범용이 아니게 된다.

## 정한 것 · 고친 것

5차에서 가장 큰 것이고, 잘라낸 `TxLayout`(447줄 · 앱 사용 0회)의 자리를 대신한다.
**셸이 맡는 것은 넷뿐이다** — 랜드마크 · 본문으로 건너뛰기 · 머무는 헤더 · 좁을 때 서랍.
로고 · 메뉴 구조 · 로그인 상태는 전부 슬롯이다. 그것이 앱마다 다른 부분이고,
넣는 순간 범용이 아니게 된다.

### 이름은 방향으로 간다 (결정됨 · 다시 따져 보고 유지)

`header` · `top` · `left` · `right` · `bottom` · `footer`. `GNB`·`LNB`·`SNB` 로 되돌릴지
한 번 더 따졌고 방향으로 남겼다. 근거 넷이다.

- **네 번째 자리에서 약어가 무너진다.** `GNB`·`LNB`·`SNB` 는 셋까지만 있는 말이고,
  아래 패널을 `BNB` 라 부르면 업계에서 그건 **모바일 하단 탭바**를 뜻해 콘솔 패널과 어긋난다
- **이제 탐색이 아니다.** `right` 에는 목차·상세가, `bottom` 에는 콘솔이 들어간다.
  `SNB`(Sub **Navigation** Bar)는 사실이 아닌 이름이 된다
- **npm 에 올리는 물건이다.** 한국 웹 업계 관용어라 MUI·Radix 문서 어디에도 없다
- 코드가 이미 방향으로 짜여 있다 — `--tx-app-shell-left-width`, `.tx-app-shell__left`

세 번째 길(역할 이름 — VS Code·AWS 의 `sidebar`·`panel`)도 봤지만, 좌우가 CSS 변수까지
방향으로 짜여 있어 지금 바꾸는 값이 컸다.

값은 하나 치렀다 — **방향 이름은 랜드마크 역할을 이름에서 지운다.** `left` 만 보고는
`<nav>` 인지 `<aside>` 인지 알 수 없다. 그래서 **역할을 셸이 못 박는다**: `top`·`left` 는
`<nav>`, `right` 는 `<aside>`, `bottom` 은 `<section>`, 각각 다른 이름이 간다.
좌우는 물리 방향이 아니라 **글 방향(`inline-start`/`inline-end`)에 붙어** RTL 에서 뒤집힌다.

### 슬롯은 prop 이다 — 자식을 뒤지지 않는다 (결정됨)

여섯 자리를 전부 prop 으로 받는다. 자식을 훑어 무엇이
헤더인지 알아내는 길도 있었지만 **원본에서 이미 두 번 부러진 방식**이다 —
`TxCard` 는 `displayName` 을 봤고 조건부 렌더나 `memo` 한 겹에 못 찾았으며,
`TxLayout` 은 `txLayoutSlot` 표식을 달게 했다. 표식을 달게 할 것이면 prop 이 낫다.

**안 준 자리는 그리지 않는다.** 자리를 남기면 빈 패널이 생긴다.

### `TxLayout` 과 섞인 것은 맞다 — 가르는 선은 컴포넌트가 아니라 prop 이다 (결정됨)

셸 하나에 **사이트 재주**(랜드마크 · 건너뛰기 · 머무는 헤더 · 좁으면 서랍)와
**IDE 재주**(크기 조절 · 접기)가 같이 있다. 그래도 컴포넌트를 다시 가르지 않는다 —
**한 화면에 셸은 하나**고, 둘로 나누면 소비자가 무엇을 골라야 하는지 모른다.
안 준 prop 은 런타임 비용이 0이다: `panels` 를 안 주면 손잡이도 스위치도 안 생긴다.
**비용은 배우는 데 있지 도는 데 있지 않다.**

그래서 고친 것은 컴포넌트가 아니라 prop 묶음이다. 패널 하나를 다루는 데 **평행한 맵이
넷**(`resizable`·`collapsible`·`collapsed`·`sizes`)이라 같은 자리 이름을 네 군데에
적어야 했다. `panels` 하나로 묶어 **prop 19개 → 14개**가 됐다.

```tsx
panels={{
  left:   { resize: true, collapse: true, defaultSize: 280 },
  right:  { resize: { min: 200, max: 520 }, collapse: true, defaultCollapsed: true },
  bottom: { resize: { min: 100 } }
}}
onPanelChange={(slot, { size, collapsed, settled }) => settled && save(slot, size, collapsed)}
```

묶으면서 **구멍 하나가 같이 막혔다.** `collapsed`/`sizes` 는 제어 prop 이라 주는 순간
셸이 손을 떼서, **"처음엔 접힌 채로, 이후는 사용자가"** 를 할 방법이 없었다 —
AWS 의 Console-to-Code 패널이 그 모양이다. `defaultCollapsed`·`defaultSize` 가 그 자리다.

콜백도 셋(`onResize`·`onResizeEnd`·`onCollapsedChange`)에서 하나로 줄였다.
끄는 중간과 끝은 **`settled`** 가 가른다 — 저장은 `settled` 일 때만 하면 된다.

### 크기 조절은 셸이 맡는다 (결정됨)

`left` · `right` · `bottom` 을 끌어서 바꾼다. **독립 부품(`TxResizable`)으로 뺄지를
먼저 따졌고, 셸로 정했다.** 근거는 셋이다.

- **폭 소유권이 갈린다.** 지금 패널의 폭은 셸이 갖는다(`--tx-app-shell-left-width`).
  슬롯 안의 부품이 제 폭을 정하려면 패널이 자식 크기에 맞춰 줄어야 하는데,
  **셸은 자식이 무엇인지 보지 않기로 했으므로**(슬롯이 prop 인 이유) 알 방법이 없다
- **셸만 아는 값이 있다.** 한계를 안 줘도 본문이 `240px` 은 남도록 조인다 — 이건
  패널과 본문을 다 보는 자리에서만 계산된다. 브라우저에서 확인: 왼쪽 패널을 끝까지
  끌면 정확히 451px 에서 멈추고 본문이 240px 로 남았다
- **좁아지면 서랍으로 간다.** 그때 손잡이는 사라져야 하고, 폭은 `TxSlidePanel` 것이다

셸 밖에서 쓸 자리가 실제로 생기면 그때 손잡이를 꺼낸다. **지금 공개하면 되돌리기 어렵고,
그 자리는 아직 목록에 없다** — `TxLayout` 을 자른 이유가 정확히 그거였다.

원본 `TxLayout` 도 `left`·`right`·`bottom` 셋에 `resizable`·`minSize`·`maxSize`·`onResize`
를 갖고 있었다. **거기 없던 것 둘을 채웠다.**

- 손잡이가 `role="separator"` 인데 **키보드로 못 움직였다.** 화살표 16px · `Home`/`End`
- `aria-valuemax` 가 없었다. 없으면 스크린리더가 **기본값 100 을 읽는다** — 폭이 298px 인데
  100 이라고 읽는 셈이다. 화면을 재야 알 수 있는 값이라 잰 김에 같이 남긴다

**저장은 소비자 몫이다.** `onPanelChange` 로 주고 `defaultSize`·`defaultCollapsed` 로
돌려받는다 — 어디에 남길지는 앱이 정할 일이고, 런타임 정책을 패키지가 고르지 않는다는
규약이 여기에도 걸린다.

### 아래 패널의 폭은 고르게 열어 두었다 (결정됨)

**업계가 갈리는 자리였다.** VS Code 의 패널은 전체 폭이고, AWS 콘솔의 상세 패널은
왼쪽 좌우 패널을 비켜 본문 안에서만 올라온다. 한쪽으로 못 박을 근거가 없어 `bottomSpan` 을
두었다 — 값은 CSS 자리바꿈과 테스트 두 갈래뿐이라 싸다.

```text
bottomSpan="screen" (기본)          bottomSpan="main"
header · top                        header · top
left │ children │ right             left │ children │ right
bottom                              left │ bottom    │ right
footer                              footer
```

`"screen"` 이면 `bottom` 이 패널 줄(`__body`) 밖이라 좌우가 그 위에서 끝나고,
`"main"` 이면 본문과 한 칸(`__center`)을 이뤄 좌우 패널이 바닥까지 선다.

**크기를 빌려 오는 곳도 따라 간다** — 좌우 패널은 늘 본문의 폭에서, 아래 패널은 전체 폭이면
패널 줄의 높이에서 · 본문 폭이면 본문의 높이에서 빌린다. 브라우저에서 확인: 같은 패널이
전체 폭에서는 632px 까지, 본문 폭에서는 440px 까지 커졌다.

### 접기 스위치는 셸이 그린다 (결정됨)

`collapse: true` 를 준 자리의 경계선 가운데에 작은 탭이 생긴다. 누르면 **완전히 사라지고**
다시 누르면 **접기 전 크기로** 돌아온다 — `useResize` 가 쥔 값을 접을 때 건드리지 않는다.

- **접히면 내용을 그리지 않는다.** 폭만 0 으로 두면 보이지 않는 곳에 탭 정거장이 남는다
- **접히면 크기 손잡이도 사라진다.** 폭 0 인 것을 끌게 두면 안 된다
- **스위치는 남는다.** 같이 사라지면 다시 펼 길이 없다
- 접혔는지는 `aria-expanded` 가 말한다. **이름까지 바꾸면 두 번 말하는 것이 된다**

손잡이 가운데에는 **짧은 막대(그립)** 를 둔다. 손잡이는 경계선 전체지만 눈에는 안 보여서
끄는 자리인 줄 모른다 — AWS 콘솔의 상세 패널이 같은 표시를 쓴다. 스위치가 있는 자리는
스위치가 그 위를 덮는다.

`collapse` 없이 `collapsed` 만 주면 **스위치를 직접 그리는 길**이 된다.
원본 `TxLayout` 의 `visible` 이 그 자리다.

### 스크롤이 스위치를 잘랐다 (브라우저에서 잡았다)

아래 패널에 `overflow: auto` 를 주었더니 **경계선 위에 얹힌 스위치가 같이 잘려 나갔다.**
눈으로는 있는지 없는지 애매했고, `elementFromPoint` 로 눌러 보니 스위치가 아니라 본문이
잡혔다. 넘치는 것은 **한 겹 안쪽(`__pane`)이 감춘다.**

같은 자리에서 스위치의 손 닿는 폭도 넓혔다. 경계선에 얹는 탭이라 **14px 보다 넓게 그릴
수가 없어서**, 그리는 것은 그대로 두고 `::before` 로 24px 을 잡는다.

### 좌우 패널은 화면에 붙는다 — `panelSticky` (기본 켜짐)

```tsx
<TxAppShell left={<SideNav />}>…</TxAppShell>                     {/* 패널이 헤더 아래에 붙어 따라온다 */}
<TxAppShell left={<SideNav />} panelSticky={false}>…</TxAppShell> {/* 본문과 같이 굴러간다 */}
```

셸은 **창이 스크롤되는 구조**다. 그래서 그전에는 좌우 패널이 본문 높이만큼 길게 서 있을 뿐이라
본문을 내리면 메뉴도 같이 올라갔다 — `apps/site` 의 왼쪽 메뉴에서 드러났다. 메뉴는 셸 안쪽의
`overflow` 칸에 들어 있어 소비자가 `sticky` 를 줘도 창에 붙지 않는다. 셸이 풀 자리다.

**패널 전체를 붙인다** — 안쪽 내용만이 아니라. 접기 스위치가 패널 세로 가운데에 있어서, 내용만 붙이면
긴 페이지에서 스위치가 화면 밖으로 밀려난다. 패널을 붙이면 패널이 늘 **보이는 자리(헤더 아래부터
화면 끝까지)**를 차지하고, 경계선 · 손잡이 · 스위치가 함께 따라온다. 내용이 그보다 길면 패널 안에서
스크롤된다.

| 헤더             | 패널이 붙는 곳                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `sticky` (기본)  | 헤더 바로 아래 — **헤더 높이는 셸이 잰다**(`ResizeObserver` → `--tx-app-shell-header-height`). `top` 이 있든 없든 맞는다 |
| `sticky="hide"`  | 헤더가 숨으면 맨 위로 따라 올라간다. 같은 속도로 움직인다                                                                |
| `sticky={false}` | 화면 맨 위                                                                                                               |

몸통 줄 안에서만 붙어 있으므로 **footer 에 닿으면 거기서 멈춘다.** 좁은 화면의 서랍은 상관없다.
기본을 켜 둔 것은 왼쪽 메뉴를 둔 화면이라면 거의 늘 원하는 동작이기 때문이다.

### 좁아지면 `left` 가 서랍으로 간다 — 같은 노드로

`breakpoint`(기본 960px)보다 좁으면 헤더에 햄버거가 생기고 `TxSlidePanel` 이 왼쪽에서
나온다. 햄버거는 `TxButton icon`(ghost)이라 머리 줄의 다른 아이콘 버튼과 크기 · 색이 같다 —
크기는 `--tx-button-icon-size` 를 따른다. **그때는 크기 조절 손잡이가 사라진다** — 서랍의 폭은 서랍 것이다. **모바일용 메뉴를 따로 받지 않는다** — 둘을 받으면 어긋나고, 어긋난 쪽은 좁은
화면에서만 보이므로 가장 늦게 발견된다. 테스트가 이것을 지킨다(패널과 서랍에 같은 링크가
**동시에 있지 않은지**까지 본다 — 둘 다 있으면 스크린리더가 두 번 읽는다).

**서랍 안의 링크를 누르면 서랍이 닫힌다.** SPA 에서는 링크가 문서를 바꾸지 않으므로,
닫지 않으면 주소는 바뀌었는데 서랍이 새 화면을 가린 채 남는다. 열림 상태는 셸 안에 있어
앱이 닫을 길이 없으니 셸이 맡는다 — 라우터를 몰라도 되게 **`<a href>` 클릭**만 본다
(`Link` · `NavLink` 도 결국 `<a>` 다). 라우터가 `preventDefault` 를 부르므로
`defaultPrevented` 로는 가리지 않는다.

닫지 않는 경우는 **"이 화면을 떠나지 않는" 클릭**이다 — 새 탭(`target="_blank"`) ·
내려받기(`download`) · 보조키(⌘ · Ctrl · Shift · Alt)를 누른 클릭. 링크가 아닌 것(묶음을
펼치는 버튼)도 그대로 둔다.

```tsx
<TxAppShell left={<TxSideNav>{menu.map(item)}</TxSideNav>}>   {/* 따로 할 것이 없다 */}
```

`apps/site` 에서 드러났다 — 좁은 화면에서 서랍의 메뉴로 장을 옮기면 서랍이 그대로 열려 있었다.

폭을 **JS 가 잰다.** 미디어 쿼리는 커스텀 프로퍼티를 못 읽어 `breakpoint` 를 prop 으로
받을 길이 없다. 재는 대상은 **화면 폭**이다 — 셸은 화면 전체를 짜는 것이라 그것이 맞는
자리고, 놓인 자리의 폭을 보는 `TxGrid` 와 다르다.

### 건너뛰기 링크는 `:focus` 다 — `:focus-visible` 이 아니다

화면 밖에 두므로 **마우스로는 닿을 수 없다.** 브라우저가 "키보드로 온 포커스" 로 보지
않는 경우까지 살리려면 `:focus` 여야 한다. `display: none` 으로 감추지도 않는다 —
그러면 Tab 이 닿지 않아 있으나 마나다.

본문의 `id` 는 `useId` 로 만든다. **한 페이지에 셸이 둘이어도 서로의 본문을 가리키지
않는다.**

### 건너뛰기는 주소를 바꾸지 않는다 — HashRouter 에서 빈 화면이 됐다 (settlemint 에서 잡았다)

건너뛰기는 `<a href="#본문id">` 이고 처음에는 이동을 브라우저에 맡겼다. **HashRouter 앱에서는 주소의 조각(hash)이 곧 경로라**
누르는 순간 `#/history` 가 `#_r_0_` 로 바뀌었고, 라우터는 그런 경로가 없어 빈 화면을 그렸다(배포 사이트에서 재현).

| 고친 것                                               | 왜                                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 누르면(클릭 · Enter) 기본 이동을 막고 본문으로 포커스 | 주소(hash · query)가 그대로다. 라우터를 몰라도 된다 — 어떤 라우터든 주소를 안 건드리면 안전하다        |
| 본문 `<main>` 에 `tabIndex={-1}`                      | 포커스를 받을 수 있어야 다음 Tab 이 본문 안의 첫 컨트롤로 간다. `-1` 이라 Tab 순서에는 들어가지 않는다 |
| 본문의 포커스 테두리는 그리지 않는다                  | 본문은 누르는 것이 아니라 읽기를 시작하는 자리다. 본문 전체에 테두리가 남으면 거슬린다                 |
| 스크롤은 `scroll-margin-block-start` 로 헤더를 비킨다 | 머무는 헤더 밑으로 본문 머리가 들어가지 않는다. 포커스는 `preventScroll` 로 두고 따로 굴린다           |
| `href` 는 남긴다 · 보조키 클릭은 막지 않는다          | JS 가 없을 때의 길이고, 새 탭으로 여는 클릭은 브라우저의 일이다                                        |

### 여백 · 높이 · 색은 기본값을 두되 전부 변수로 연다 (고쳤다)

**처음 문장은 "셸은 색·여백을 손대지 않는다" 였는데 사실이 아니었다.** 헤더 줄(`__bar`)에
`padding-inline: 1rem` · `min-block-size: 3.5rem` · `gap: 0.75rem`, 가로 띠(`__top`)에
`padding-inline: 1rem` 이 고정값으로 박혀 있었다. `__bar` 에는 `classNames` 슬롯도 없어서
**공개된 방법으로는 끌 수 없었다** — black-message 에 붙이자 `h-8` 로 준 헤더가 56px 로 서고
좌우에 1rem 이 생겼다. 끄려면 내부 클래스(`.tx-app-shell__bar`)를 덮어써야 했다.

다른 컴포넌트(`TxCard` · `TxModal` · `TxCollapsible` …)는 전부 **기본값 + 변수**다. 셸만 어긋나 있었으므로
같은 방식으로 맞췄다. **기본값은 그대로라 이미 쓰는 화면은 바뀌지 않는다.**

| 변수                            | 기본      | 자리                                        |
| ------------------------------- | --------- | ------------------------------------------- |
| `--tx-app-shell-bar-min-height` | `3.5rem`  | 헤더 줄의 최소 높이 — 내용이 크면 늘어난다  |
| `--tx-app-shell-bar-padding`    | `0 1rem`  | 헤더 줄 여백                                |
| `--tx-app-shell-bar-gap`        | `0.75rem` | 햄버거 ↔ `header` 슬롯 사이                 |
| `--tx-app-shell-top-padding`    | `0 1rem`  | `top` 띠 여백                               |
| `--tx-app-shell-main-padding`   | `1.5rem`  | 본문 여백 (원래 있던 것)                    |
| `--tx-app-shell-header-bg`      | surface   | 머리 배경 (원래 있던 것)                    |
| `--tx-app-shell-border-color`   | border    | 머리 · 패널 · footer 경계선 (원래 있던 것)  |
| `--tx-app-shell-border-width`   | `1px`     | 같은 경계선의 두께 (settlemint 에서 더했다) |

`classNames` 에는 `bar` 를 더했다 — `header` 는 머리 전체(`bar` + `top`)의 겉이고, `bar` 는 그 안의 줄이다.
**슬롯을 감싸는 자리의 여백 · 높이가 변수를 거치는지는 CSS 계약 테스트가 지킨다.**

셸이 슬롯 안을 직접 꾸미지 않고 슬롯이 스스로 꾸미게 하려면 셸의 여백을 전부 끄면 된다.

```css
.tx-app-shell {
  --tx-app-shell-bar-min-height: 0;
  --tx-app-shell-bar-padding: 0;
  --tx-app-shell-top-padding: 0;
  --tx-app-shell-main-padding: 0;
}
```

**경계선을 없애려면 두께를 `0` 으로 둔다.** 색만 `transparent` 로 두면 보이지 않는 1px 이 남아 헤더가
그만큼 높아진다 — settlemint 는 그래서 `--tx-app-shell-bar-min-height` 를 56 대신 55 로 줘서 맞췄다.
접기 스위치의 테두리는 경계선이 아니라 그 단추의 것이라 두께를 따라가지 않는다.

```css
.tx-app-shell {
  --tx-app-shell-border-width: 0;
}
```

본문에는 `min-inline-size: 0` 을 준다 — flex 자식의 기본 최소 크기는 내용이라, 그대로 두면
긴 표가 본문을 밀어내 옆 패널까지 넘친다.

### 화면을 꽉 채우는 앱은 소비자가 두 가지를 정한다

**셸의 기본은 문서가 스크롤되는 페이지다** — 겉은 `min-block-size: 100dvh` 이고 본문(`__main`)은
`display: block` 이라 내용만큼 늘어난다. black-message 에 붙이자 **표가 있는 화면의 높이가 0** 이 됐다.
예전 앱 레이아웃은 `h-screen` 겉 안에 `<div className="flex min-w-0 flex-1 overflow-hidden"><Outlet /></div>`
였고, 화면들은 그 flex 부모를 `flex-1` 로 채우게 짜여 있었다. 셸 본문은 flex 가 아니라
`flex-1` 이 먹지 않고, 그 안의 `height: 100%` 그리드는 기준 높이가 없어 0 이 된다.

**셸을 바꾸지 않고 소비자가 정하게 했다.** 글을 읽는 사이트(이 사이트)에는 지금 기본이 맞고,
관리 화면에는 아래 두 줄이면 된다. 본문 줄과 본문에 `min-block-size: 0` 이 이미 있어서
겉의 높이만 고정하면 남는 높이가 그대로 내려간다.

```tsx
<TxAppShell className="h-dvh" classNames={{ main: "flex overflow-hidden" }}>
```

site 의 `Guide › Layout › Fill the screen with the content` 가 소비자용 설명이다.

### 브라우저 창의 시계가 멈춰 있었다 (도구 한계)

내리면 숨는 헤더가 안 움직여 결함으로 보였다. **직접 만든 `<div>` 의 전이도
`playState: running / currentTime: 0`** 인 것을 보고 도구 쪽으로 가렸다. 전이를 끄고
재니 숨을 때 헤더가 정확히 제 높이(105px)만큼 올라갔다 오고, 서랍도 끝자리(x=0)에
정확히 섰다. 프로그램 스크롤에 이벤트가 안 오는 것(`TxScrollArea` 에서 겪은 것)도
같이 나와, 스크롤 이벤트는 손으로 보내 확인했다 — 8px 손떨림은 무시하고 500 → 300 에서
바로 다시 나온다.

### 하단 탭바 — `tabBar` (settlemint 에서 요구됐다 · 사용자 결정)

`bottom` 은 본문 아래의 콘솔 · 로그 패널이라 모바일 하단 탭바 자리가 아니다. 그래서 자리를 따로 열었다 —
**좁을 때(`breakpoint` 보다 좁은 화면)만** 화면 아래에 붙는다. 항목은 [051_TxTabBar](051_TxTabBar.md) 가 그린다.

```tsx
<TxAppShell breakpoint={1024} left={<TxSideNav>{sideItems}</TxSideNav>} tabBar={<TxTabBar>{tabItems}</TxTabBar>}>
  <Outlet />
</TxAppShell>
```

| 셸이 하는 것         | 어떻게                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| 좁을 때만 그린다     | 서랍과 같은 `breakpoint` 를 쓴다 — 넓으면 `left` · `top` 의 메뉴가 그 일을 한다                |
| 랜드마크             | `<nav aria-label="하단 탭">` (`labels.tabBar` 로 바꾼다). `classNames.tabBar`                  |
| 화면 아래 고정       | `position: fixed` · `z-index` 는 헤더와 같다. 서랍(모달)은 최상위 층이라 그 위를 덮는다        |
| **본문 자리 비우기** | 서 있는 동안 루트에 `data-tab-bar` · 그만큼 아래 여백(`border-box`). 푸터도 탭바 위에서 끝난다 |
| 아이폰 홈 표시줄     | `env(safe-area-inset-bottom)` 을 아래 여백 · 전체 높이에 더한다                                |
| 위쪽 페이드          | `--tx-app-shell-tab-bar-fade`(기본 `0`) — 가상요소라 마크업이 늘지 않고 눌림을 가로채지 않는다 |

**서랍(햄버거)은 탭바가 있어도 남는다** — 탭바에 다 안 드는 메뉴가 갈 곳이다. 두 메뉴는 같은 라우트 배열에서 뽑는다.
이 셸이 "모바일용 메뉴를 따로 받지 않는다"(위 "좁아지면 `left` 가 서랍으로 간다")고 정한 것과 부딪히는 자리라, 어긋나지 않는 길을 그렇게 정했다.

토큰은 `--tx-app-shell-tab-bar-height` · `-padding-top` · `-padding-bottom` · `-bg` · `-border-width` · `-border-color` · `-fade` · `-fade-color`.
기본값과 Figma 값을 맞추는 예는 [051](051_TxTabBar.md) 의 "토큰".
