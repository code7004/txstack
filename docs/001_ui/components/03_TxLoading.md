## 1. 목적

**"로딩 중"을 화면에 세우는 자리.** `TxSpinner` 가 아이콘 하나라면, 이쪽은 그 아이콘을 **언제 보일지**와
**옆에 무슨 말을 붙일지**, 그리고 **화면 전체를 덮을지**를 맡는다.

- 소비자가 직접 하면: `{loading && …}` 를 화면마다 쓰고, 목록 로딩에서는 `data.length === 0` 을 다시 계산하고,
  전체화면 딤은 `fixed inset-0` + z-index + 다크모드 색을 매번 정하고, 스크린리더 안내(`role="status"`)를 매번 판단해야 한다.
- 그 판단을 한 번만 하고 **어느 프로젝트에서든 같은 이름·같은 props 로 꺼내 쓰는 것**이 존재 이유다.

**책임 범위: 표시 여부 판단 + 문구 + 전체화면 오버레이.** 회전 아이콘 자체는 `TxSpinner` 가 소유한다 —
`TxLoading` 은 그것을 안에서 쓴다 ([TxSpinner §5 Q2](01_TxSpinner.md)).

## 2. 공개 API

```ts
// packages/ui/src/TxLoading/TxLoading.tsx
import type { HTMLAttributes } from "react";

export interface TxLoadingProps extends Omit<HTMLAttributes<HTMLDivElement>, "children"> {
  /** 문구. 비우면 스피너만 나온다 */
  text?: string;
  /** 표시 여부. 배열을 주면 그 배열이 비어 있는 동안 보인다. 기본 true */
  visible?: boolean | readonly unknown[];
  /** 화면 전체를 덮는다. document.body 로 포털된다 */
  fullScreen?: boolean;
  /** 안쪽 슬롯. 바깥 겉은 className 이 맡는다 */
  classNames?: { icon?: string; text?: string; backdrop?: string };
}

export const TxLoading: (props: TxLoadingProps) => JSX.Element | null;
```

`HTMLAttributes` 의 나머지(`style` · `id` · `onClick` · `aria-*` …)는 그대로 통과한다.

| 항목             | 값                                                                  | 근거         |
| ---------------- | ------------------------------------------------------------------- | ------------ |
| export           | **named** (`export const TxLoading`)                                | 기존 유지    |
| 타입 이름        | `TxLoadingProps` — **`I` 접두 없음**. 원래부터 맞았다               | 20_design §7 |
| `visible` 기본값 | `true` — `<TxLoading />` 만 두면 보인다                             | §5 Q1        |
| 기본 클래스      | `tx-loading`. 소비자 `className` 은 **덧붙는다** (교체 아님)        | D1           |
| 전체화면         | `data-full-screen` + **`document.body` 로 포털**                    | §5 Q2        |
| 안쪽 슬롯        | `.tx-loading__icon` · `.tx-loading__text` · `.tx-loading__backdrop` | §3           |
| 스크린리더       | 문구가 있으면 래퍼가 `role="status"`, 없으면 스피너가 안내한다      | A1           |
| 모션 저감        | `TxSpinner` 가 처리한다 — **멈추지 않고 늦춘다**                    | A2           |
| DOM 표식         | `data-tag="TxLoading"`                                              | 기존 유지    |

### DOM

```html
<!-- 인라인 -->
<div class="tx-loading" data-tag="TxLoading" role="status">
  <span class="tx-loading__icon"><svg class="tx-spinner" data-tag="TxSpinner" aria-hidden="true">…</svg></span>
  <span class="tx-loading__text">불러오는 중</span>
</div>

<!-- 전체화면 (document.body 직속) -->
<div class="tx-loading" data-tag="TxLoading" data-full-screen role="status">
  <div class="tx-loading__backdrop"></div>
  <span class="tx-loading__icon">…</span>
  <span class="tx-loading__text">불러오는 중</span>
</div>
```

## 3. 커스터마이징 지점

규약은 [20_design §4](../20_design.md) 가 소유한다. 여기서는 `TxLoading` 의 실제 토큰과 슬롯만 적는다.

| 무엇을 바꾸나      | 무엇으로                                | 예                                                   |
| ------------------ | --------------------------------------- | ---------------------------------------------------- |
| 아이콘 크기 · 간격 | **CSS 변수**                            | `.tx-loading { --tx-loading-icon-size: 3em }`        |
| 딤의 진하기        | **CSS 변수**                            | `.tx-loading { --tx-loading-backdrop-opacity: 60% }` |
| 쌓임 순서          | **CSS 변수**                            | `.tx-loading { --tx-loading-z: 9999 }`               |
| 이 인스턴스의 겉   | `className`                             | `<TxLoading className="my-loader" />`                |
| 안쪽 슬롯          | `classNames={{ icon, text, backdrop }}` | `classNames={{ text: "font-bold" }}`                 |

### 토큰

| 토큰                            | 기본값                                                                                       | 쓰임                      |
| ------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------- |
| `--tx-loading-icon-size`        | `1.5em` (전체화면 `2.5em`)                                                                   | 스피너 크기               |
| `--tx-loading-gap`              | `0.5em` (전체화면 `1em`)                                                                     | 아이콘과 문구 사이        |
| `--tx-loading-backdrop-opacity` | `20%`                                                                                        | 딤의 진하기               |
| `--tx-loading-backdrop-bg`      | `color-mix(in oklab, var(--tx-color-state) var(--tx-loading-backdrop-opacity), transparent)` | 딤의 색                   |
| `--tx-loading-z`                | `50`                                                                                         | 전체화면 `z-index`        |
| `--tx-loading-fg`               | `var(--tx-color-text)`                                                                       | **전체화면** 문구 색 (D6) |

**크기와 간격이 `em` 이다.** 아이콘·문구·간격이 함께 놓인 자리의 글자 크기를 따라간다 —
`rem` 으로 두면 큰 글자 옆에서 간격만 좁아 보인다 (§11 실측).

**딤의 색을 리터럴로 적지 않는다.** `--tx-color-state` 는 [tokens.css](../../../packages/ui/src/tokens.css) 에서
다크모드에 뒤집히는 값이라, 이 파생 한 줄로 **라이트는 검게 · 다크는 밝게** 덮인다 —
컴포넌트 CSS 에 `.dark` 분기가 한 줄도 없다 ([20_design §6](../20_design.md)).

> **전역 토큰 `--tx-color-overlay` 를 만들지 않았다.** 딤을 쓰는 컴포넌트가 아직 이것 하나다.
> [20_design §5](../20_design.md) 의 "안 쓰는 토큰을 미리 설계하지 않는다" 에 따라 컴포넌트 토큰으로 둔다.
> **E 그룹(`TxModal`·`TxSlidePanel`)이 같은 딤을 쓰게 되면 그때 전역으로 승격한다.**

### 문구의 색과 크기는 선언하지 않는다

`.tx-loading__text` 에 `color` 도 `font-size` 도 없다. **놓인 자리의 글자를 따라간다** —
`TxSpinner` 가 확정한 방식과 같다. 바꿀 게 있으면 `classNames={{ text }}` 나 `.tx-loading__text` 를 직접 조준한다.

**단, 전체화면은 `document.body` 직속이라 상속의 출발점이 body 다.** 호출한 자리의 글자색이 아니다 (§5 Q2 의 대가).

### 접근성

| ID  | 내용                                                                                                                                                                            | S2 처리                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| A1  | **로딩 상태를 안내하지 않는다.** `role` 도 `aria-live` 도 없다. `Dots` 는 의미 없는 `div` 7개고 문구도 평범한 `div` 라, 스크린리더 사용자는 **화면이 멈춘 것과 구분할 수 없다** | 문구가 있으면 래퍼에 `role="status"` + 스피너는 `decorative`. 없으면 스피너가 안내 |
| A2  | **`animate-bounce` 가 `prefers-reduced-motion` 미대응.** 저장소 공통 규칙(끄지 않고 늦춘다)이 이미 있는데 여기만 빠져 있었다                                                    | `Dots` → `TxSpinner` 교체로 해소. `TxSpinner.css` 가 이미 처리한다                 |

**A1 은 한 자리에서만 안내한다.** 래퍼(`role="status"`)와 스피너(`role="status"`)를 둘 다 켜면
live region 이 중첩돼 같은 내용이 두 번 읽힌다. 그래서 갈랐다 —

- **문구가 있으면** 래퍼가 live region 이고, 스피너는 `decorative` 다. 안내되는 것은 소비자가 준 문구다
- **문구가 없으면** 래퍼에 `role` 을 걸지 않고 `TxSpinner` 의 기본 안내(`"Loading"`)에 맡긴다.
  읽을 내용이 없는 live region 은 침묵하기 때문이다

> **live region 의 한계는 남는다.** 마운트와 동시에 내용이 이미 있으면 안내를 놓치는 조합이 있다.
> 그건 이 컴포넌트가 풀 수 있는 문제가 아니라서 여기서는 다루지 않는다.

| C7  | **테스트 없음**                                                                                                                    | `TxLoading.test.tsx` 신설 → §9                           |
| C8  | 하드코딩 `z-50` — 소비자가 쌓임 순서를 조정할 수 없다                                                                              | `--tx-loading-z` 토큰                                    |

### 남긴 것

- **`visible` 이 진짜 빈 결과와 로딩 중을 구분하지 못한다.** `visible={rows}` 는 `rows` 가 비어 있으면 보이므로,
  응답이 실제로 0건이면 **영구 로딩**이 된다. 배열 규약의 대가이고 `TxCard` 의 `isLoading` 도 같다 (§5 Q1).
  **결함이 아니라 함정으로 문서화한다** — 스토리·`aria` 로는 못 고치고, 고치려면 규약 자체를 버려야 한다.
- **전체화면이 클릭을 막는다.** 화면을 덮는 요소라 그 아래는 눌리지 않는다. 로딩 중 조작 차단이 대개 의도이므로
  그대로 두고 명세에 적는다. `pointer-events` prop 은 만들지 않는다 (§7).
- **`text` 만 있고 `children` 은 없다.** `TxButton` 의 `label \| children` 공존 문제를 여기로 끌고 오지 않는다.

## 5. 설계 결정 (2026-08-26 합의)

| ID  | 질문                                    | 결정                                                     |
| --- | --------------------------------------- | -------------------------------------------------------- |
| Q1  | `visible` prop 을 유지할 것인가         | **유지. 타입만 `any[]` → `readonly unknown[]`**          |
| Q2  | `fullScreen` 오버레이를 어디에 렌더하나 | **`createPortal` 로 `document.body`**                    |
| Q3  | 인라인 모드의 배치와 문구 스타일        | **가로 한 줄 + 문구는 상속** (색·크기를 선언하지 않는다) |

### Q1 — 배열 규약을 살린다

`visible` 에 배열을 주면 **그 배열이 비어 있는 동안** 보인다. 이 규약을 유지한다.

- `TxCard` 의 `isLoading` 이 이미 같은 관행이다 (`TxCard.tsx:55` — 같은 한 줄이 들어 있다).
  둘이 갈라지면 "여러 프로젝트에서 같은 방법" 이라는 이 라이브러리의 명분이 안에서부터 깨진다
- `data.length === 0` 을 소비자가 계산하지 않는다. 목록 화면에서 실제로 반복되는 코드다

**대가**: 진짜로 0건인 응답과 로딩 중을 구분하지 못한다 (§4 "남긴 것"). 그래서 이 규약은 **선택**이다 —
구분이 필요한 화면은 `visible={loading}` 으로 boolean 을 준다.

버린 대안:

- **boolean 만 받는다** — 예측 가능해지지만 `TxCard` 와 규약이 갈리고, 소비자가 `rows.length === 0` 을 매번 쓴다
- **prop 자체를 없앤다** (`{loading && <TxLoading />}`) — 표면이 가장 작지만, 기존 사용처가 전부 바뀌고
  배열 규약이 함께 사라진다. React 관례에 맡기는 게 맞는 자리도 있는데 여기서는 그걸 위해 버릴 게 너무 많다

### Q2 — 전체화면은 포털로 body 에 붙인다

`position: fixed` 는 **조상에 `transform`·`filter`·`perspective`·`contain` 이 있으면 그 조상을 기준으로** 배치된다.
그러면 "화면 전체" 가 "그 카드 전체" 가 되고, 딤이 헤더나 사이드바를 덮지 못한다.

- **이 컴포넌트의 대표 용도가 "페이지 전환 중 표시"** 다. 페이지 전환은 `transform` 으로 애니메이션하는 일이 흔해서,
  가장 자주 쓰이는 자리에서 가장 잘 깨진다
- 증상이 원인을 안 가리킨다 — 딤이 반쯤 나오는 것을 보고 `z-index` 를 의심하게 된다
- `react-dom` 은 이미 peerDependency 다. **새 의존이 아니다**

**SSR 에서는 첫 렌더에 아무것도 내지 않는다.** `document` 가 없으면 `null` 을 반환하고, 하이드레이션 뒤에 붙는다.
로딩 표시는 클라이언트에서 의미가 생기는 것이라 이 절충을 받아들인다.

**대가 둘**:

1. **상속의 출발점이 바뀐다.** 전체화면 문구는 호출한 자리가 아니라 `body` 의 글자를 따라간다 (§3)
2. **E 그룹(오버레이) 규약을 여기서 먼저 정하게 된다.** `TxModal`·`TxSlidePanel`·`TxDropMenu` 가
   같은 문제를 만나므로 **이 선례를 따르면 된다.** 순서가 뒤바뀐 것은 사실이라 여기 적어 둔다

버린 대안: **제자리 `fixed` 유지 + 함정 문서화** — E 그룹 규약을 미리 정하지 않는 이점은 있지만,
**조용히 깨지는 경로가 남는다.** 문서로 막는 결함은 결국 다시 온다.

### Q3 — 인라인은 가로 한 줄, 문구는 상속

```
◌ 불러오는 중
```

- `TxSpinner` 의 사용 예제가 이미 이 모양이다 (`<p className="flex items-center gap-2"><TxSpinner />불러오는 중</p>`).
  라이브러리가 그걸 대신 해주는 것이 이 컴포넌트의 값이다
- **색·크기를 선언하지 않으면 놓인 자리에 저절로 맞는다.** 작은 캡션 안에서는 작게, 본문 옆에서는 본문 크기로.
  `text-xs text-gray-600` 을 박아 두면 그 반대가 된다 — 소비자가 매번 되돌려야 한다

**전체화면은 세로다** (스피너 위, 문구 아래, 화면 중앙). 가로 한 줄은 인라인 모드의 배치다.

**겉모습이 바뀐다** — `Dots` 7개가 회전 아이콘 하나로, 세로가 가로로, 작은 회색 글씨가 상속으로.
changeset 에 전부 적었다.

## 6. 사용 예제

**흔한 케이스** — 목록을 불러오는 동안.

```tsx
import { TxLoading } from "@txstack/ui";
import "@txstack/ui/styles.css"; // 앱에서 한 번

// rows 가 채워지면 저절로 사라진다
<TxLoading visible={rows} text="목록을 불러오는 중" />;
```

**전체화면** — 페이지 전환 중.

```tsx
<TxLoading visible={isNavigating} text="이동 중" fullScreen />
```

**커스터마이징** — 값은 CSS 변수 한 곳에서 바꾼다.

```css
.tx-loading {
  --tx-loading-icon-size: 3em; /* 스피너를 크게 */
  --tx-loading-backdrop-opacity: 60%; /* 딤을 진하게 */
  --tx-loading-z: 9999; /* 우리 앱의 헤더보다 위로 */
}
```

문구만 다르게 하려면 슬롯을 준다. 바깥 겉은 `className` 이다.

```tsx
<TxLoading text="불러오는 중" classNames={{ text: "font-bold" }} />
```

## 7. 하지 않는 것

- **회전 아이콘 자체** — `TxSpinner` 가 소유한다. 속도는 `--tx-spinner-duration` 으로 바꾼다
- **진행률(determinate) 표시** — `%` 를 아는 로딩은 다른 컴포넌트다 ([TxSpinner §7](01_TxSpinner.md) 과 같은 판단)
- **지연 표시(delay) · 최소 표시 시간 · 타임아웃** — 깜빡임을 줄이는 정책은 화면마다 다르다. 소비자가 정한다
- **스켈레톤** — 자리 모양을 아는 로딩은 `TxCard` 의 `isLoading` 이 한다
- **포커스 트랩 · 스크롤 잠금 · `Esc` 닫기** — 전체화면이 대화상자가 아니다. 그건 `TxModal` 의 일이고,
  E 그룹에서 규약으로 정한다
- **클릭 통과(`pointer-events`) 옵션** — 로딩 중 조작 차단이 의도다. 필요하면 `className` 으로 끈다
- **`text` 의 색·크기 소유** — 놓인 자리를 따라간다 (§5 Q3)
- **전역 딤 토큰** — 쓰는 컴포넌트가 셋이 될 때 승격한다 (§3)

## 10. S4 — 스토리북 (2026-08-26)

`Feedback/TxLoading` · 스토리 **6개**. 이름을 [901 §1](../../901_storybook/20_design.md) 에 맞춰 영어 PascalCase 로 바꿨다 (C6).

| 스토리              | 무엇을 보나                                                                         |
| ------------------- | ----------------------------------------------------------------------------------- |
| `Playground`        | 컨트롤이 살아 있는 자리. 스크린리더에 무엇이 안내되는지도 글로 드러낸다             |
| `Basic`             | `<TxLoading text="…" />` 하나. 놓인 자리의 글자를 따라가는 것을 셋으로 비교         |
| `Visible`           | 배열 규약. 채우면 사라진다 + **0건 응답이면 안 사라지는 함정**을 나란히 놓았다      |
| `FullScreen`        | 버튼으로 띄우고 3초 뒤 사라진다. 기본 딤(모드에 따라 뒤집힘)과 어두운 스크림을 비교 |
| `CustomizingTokens` | 토큰을 인라인으로 비교. 설명에는 CSS 한 곳에 적는 실제 사용법                       |
| `CustomizingSlots`  | `className` 과 `classNames` 가 각각 어디에 붙는지                                   |

- `Playground` 만 컨트롤이 살아 있고 나머지는 `controls: { disable: true }` ([901 §4](../../901_storybook/20_design.md))
- **`Playground` 에서는 `fullScreen` 컨트롤을 끈다.** autodocs 는 스토리를 한 페이지에 인라인으로 싣기 때문에
  전체화면 딤이 컨트롤 패널까지 덮어 되돌릴 손잡이가 사라진다. 그래서 전용 스토리에서 **버튼 + 3초 자동 해제**로 본다
- 토큰을 가진 컴포넌트는 토큰 스토리를 하나 갖는다 → `CustomizingTokens` · `FullScreen`(딤)
- **`Visible` 에 함정을 같이 실었다.** 배열 규약의 대가(§4 "남긴 것")는 실제로 걸려 넘어지는 것이라 카탈로그에 적는다

### 카탈로그 쪽에서 하나 고쳤다 — 포털된 콘텐츠에 테마가 안 닿았다

`apps/storybook/.storybook/preview.tsx` 의 테마 데코레이터가 색을 **스토리 안쪽 `div`** 에 걸고 있었다.
포털된 것은 그 `div` 밖(`body` 직속)에 붙으므로 **상속할 색이 없어 다크모드에서 검게 남는다** —
D6 을 처음 발견한 자리가 여기다. `body` 에도 같은 클래스를 걸어 고쳤다.

**라이브러리 결함처럼 보이지만 카탈로그의 구멍이다.** 이 둘이 겹쳐 있었기 때문에
D6 을 고친 뒤에도 화면이 안 바뀌어 한 번 더 봐야 했다. E 그룹(오버레이)이 전부 포털을 쓰게 되므로
지금 고쳐 두는 것이 맞다 → [901/20_design §4](../../901_storybook/20_design.md) 에 규칙으로 올렸다.

### 브라우저 실측 — `elementFromPoint` 로 페인트 순서를 확인했다

D2 는 "딤이 문구 위에 그려진다" 는 결함이라 렌더 트리로는 안 보인다. 그래서 **문구 중앙 좌표에서
실제로 어느 요소가 잡히는지**를 물었다. 되돌려 넣어 양쪽을 다 확인했다.

| 상태                                | 문구 중앙에서 잡히는 요소 |
| ----------------------------------- | ------------------------- |
| 고친 상태                           | `tx-loading__text` ✅     |
| `position: static` 으로 되돌린 상태 | `tx-loading__backdrop` ❌ |

**D2 가 실재했다는 증거이자 수정이 실효했다는 증거다.** 이 방법은 페인트 순서 결함이 있는
다른 컴포넌트에도 쓸 수 있다 — E 그룹(오버레이)이 전부 해당한다.

| 항목                              | 실측값                                                   |
| --------------------------------- | -------------------------------------------------------- |
| 포털                              | `parentElement === BODY` ✅                              |
| 딤 (라이트 / 다크, 20%)           | `oklab(0.21 …)` / `oklab(0.97 …)` — **뒤집힌다** ✅      |
| 전체화면 문구색 (라이트 / 다크)   | `#111827` / `#f3f4f6` — 딤과 같은 방향으로 뒤집힌다 ✅   |
| 어두운 스크림 (양쪽 모드)         | `oklab(0 0 0 / 0.6)` + 흰 글자 — 모드와 무관하게 고정 ✅ |
| 인라인 상속 (12 / 16 / 24px 자리) | 스피너 18 / 24 / 36px · gap 6 / 8 / 12px ✅              |
| 콘솔 오류                         | 0건 ✅                                                   |

**gap 단위가 여기서 바뀌었다.** `0.5rem` 이던 시절에는 아이콘만 커지고 간격은 8px 로 고정돼,
24px 글자 옆에서 문구가 아이콘에 붙어 보였다. `0.5em` 으로 바꿔 셋이 같이 따라간다.

## 12. 🧑 사용자 확인 — **통과 (2026-08-26)**

**반려 없이 통과했다.** 게이트에 올린 판단거리 넷(기본 딤을 모드에 따라 뒤집을지, 가로 한 줄과 1.5em,

**이 컴포넌트의 공개 API 가 확정됐다** — props · 토큰 6개 · 슬롯 3개 · DOM 계약(§2).

> 규약이 확정돼 있었고([20_design](../20_design.md)), 파일럿에서 배운 실측을 게이트 **전에** 했다.
