## 개발 목적

파일을 골라 올리는 자리. 고르기 · 진행률 · 파일 단위 재시도를 맡되 **어디로 보내는지는 모른다** — 보내는 함수를 주입받는다.

## 기능

### 쓰는 법

```tsx
<TxFileUpload
  accept="image/*"
  maxSize={5 * 1024 * 1024}
  uploader={async (file, { onProgress, signal }) => {
    await api.upload(file, { onUploadProgress: (e) => onProgress(e.progress * 100), signal });
  }}
/>
```

**어디로 어떻게 보내는지 모른다.** 주소도 헤더도 응답 봉투도 앱의 것이라 `uploader` 로
주입받는다 — 그것을 패키지가 정하면 그 규약을 쓰는 앱에서만 쓸 수 있다.

**다시 시도는 파일 단위다.** 열 개 중 하나가 실패했다고 다 올린 아홉을 또 보내지 않는다.

**끌어다 놓기와 눌러서 고르기가 둘 다 된다.** 숨긴 `<input type="file">` 을 함께 두는
것이 그 때문이다 — 끌어다 놓기만 두면 키보드로는 파일을 고를 길이 없다.

## 정한 것 · 고친 것

### `TxFileUpload` — 어디로 보내는지 모른다

주소도 헤더도 응답 봉투도 앱의 것이라 **`uploader(file, { onProgress, signal })` 로
주입받는다.** 그것을 패키지가 정하면 그 규약을 쓰는 앱에서만 쓸 수 있다.

- **다시 시도는 파일 단위다.** 열 개 중 하나가 실패했다고 다 올린 아홉을 또 보내지 않는다
- **끌어다 놓기와 눌러서 고르기가 둘 다 된다.** 끌어다 놓기만 두면 키보드로는 파일을
  고를 길이 없어서, 고르는 자리를 진짜 `<button>` 으로 두고 숨긴 `<input type="file">` 을
  함께 둔다 — 그것도 `display: none` 이 아니라 화면에서만 감춘다
- **크기 제한은 고르는 순간 본다.** 올려 보고 나서 알려 주면 그동안 기다린 것이 헛수고다
- **줄을 빼면 올리던 것도 끊는다.** 뺀 줄의 응답이 늦게 오면 없는 줄을 고치게 된다
- 진행률은 `TxProgress` 가, 다시 시도 버튼은 `TxButton` 이 그린다

### 파일마다의 값은 이름이 아니라 번호로 가린다

같은 파일을 두 번 고르는 일이 흔하다. 이름으로 가리면 **두 줄이 한 값을 가리켜
하나를 지울 때 둘 다 사라진다.**
