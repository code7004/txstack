## 개발 목적

넘치는 내용을 굴려 보는 자리. **양 끝이 흐려져 더 있다는 것을 알린다** — 스크롤바가 숨는 환경에서는 넘친다는 사실 자체가 안 보인다.

## 기능

### 쓰는 법

```tsx
<TxScrollArea size="12rem" label="약관">
  <p>…긴 글…</p>
</TxScrollArea>
```

흐림은 **더 볼 것이 있는 쪽에만** 생긴다. 맨 위에 있으면 위는 또렷하고 아래만 흐리다 —
양쪽을 늘 흐리게 두면 끝에 닿았는지 알 수 없다.

**스크롤 위치는 JS 가 읽는다.** CSS 만으로 하려면 `mask-attachment: local` 이 있어야
하는데 **어느 브라우저에도 구현돼 있지 않고**, 스크롤 기반 애니메이션은 없는 곳에서
흐림이 통째로 사라진다 — 그건 이 컴포넌트가 하는 일의 전부다.

겉모습은 CSS 변수로 바꾼다 — `.tx-scroll-area { --tx-scroll-area-fade: 3rem }`.

## 정한 것 · 고친 것

### CSS 만으로는 안 됐다 (재서 정했다)

흐림을 스크롤 위치에 따라 켜고 끄려면 `mask-attachment: local` 이 있어야 하는데
**어느 브라우저에도 구현돼 있지 않다**(브라우저에서 확인: `CSS.supports` 도 계산값도
모두 없음). 스크롤 기반 애니메이션(`animation-timeline: scroll()`)은 있지만, **없는
곳에서는 흐림이 통째로 사라진다** — 그건 이 컴포넌트가 하는 일의 전부라 "기능이 조금
빠지는 것" 이 아니라 아무것도 안 하는 것이 된다. 그래서 **스크롤 위치만 JS 가 읽는다.**

흐림은 그림자가 아니라 **`mask`** 로 그린다. 그림자로 하면 덮개 색이 바탕과 같아야 해서
**뒤에 무슨 색이 있는지 알아야 한다**(고전적인 `background-attachment: local` 수법이
그렇다). 흐림은 그것을 묻지 않는다.

**흐림은 더 볼 것이 있는 쪽에만 생긴다.** 양쪽을 늘 흐리게 두면 끝에 닿았는지 알 수 없다.
넘치지 않으면 아예 흐리지 않는다.

### 가짜 스크롤바를 그리지 않는다

`scrollbar-width` 와 `scrollbar-color` 로 다듬기만 한다. 직접 그리면 **휠 관성 · 터치 ·
접근성 설정**을 전부 다시 만들어야 하고 어느 하나는 어긋난다. 테스트가
`::-webkit-scrollbar` 를 금한다.

### 키보드로도 굴린다

기본으로 탭 정거장을 하나 만든다. **안에 버튼이 하나도 없으면 마우스 없이는 안쪽 내용에
닿을 길이 없다.** 안에 이미 버튼·링크가 있으면 `focusable={false}` 로 끈다.
