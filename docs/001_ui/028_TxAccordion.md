## 개발 목적

여러 덩이를 이어 붙이고 **하나씩만 열리게** 한다. 접는 일 자체는 `TxCollapsible` 것이고, 이쪽은 묶어 두기만 한다.

## 기능

### 쓰는 법

```tsx
<TxAccordion
  items={[
    { title: "배송은 얼마나 걸리나요?", content: "2~3일 안에 받습니다." },
    { title: "교환은 어떻게 하나요?", content: "수령 후 7일 이내에 신청합니다." }
  ]}
/>
```

덩이 하나하나는 **`TxCollapsible`** 이다 — 네이티브 `<details>` 라 접힌 글도 ⌘F 로 찾힌다.
여기서 더하는 것은 **이어 붙인 겉모습과, 열린 것을 하나로 묶어 두는 일**뿐이다.

상자를 떨어뜨려 놓고 싶으면 `TxCollapsible` 을 그냥 여러 개 쓴다 — 이쪽은 **이어 붙은 목록**이다.

`TxTabs` 와 형제다. 같은 정보를 **한 번에 하나만 보여 준다**는 점이 같고,
탭은 자리를 나란히 두고 이쪽은 위아래로 편다.

## 정한 것 · 고친 것

덩이 하나하나는 `TxCollapsible` 이다. 여기서 더하는 것은 **이어 붙인 겉모습과, 열린 것을
하나로 묶어 두는 일**뿐이라 색·여백·화살표를 다시 정하지 않는다 — 테스트가 그것을 지킨다
(되돌리는 것은 괜찮다. 머리말로 감쌌을 때 브라우저가 얹는 크기·굵기를 지우는 것은
겉모습을 정하는 것이 아니다).

### `<details name>` 에 맡기지 않았다 (판단)

브라우저는 `<details name="…">` 로 **하나만 열리기를 공짜로 해 준다.** 그런데도 JS 로
들고 있다 — 그쪽에 맡기면 **여는 길이 둘이 된다**(브라우저와 우리). controlled 로 쓸 때,
그리고 `onChange` 로 알릴 때 어느 쪽이 이겼는지를 따라다녀야 한다.

상태를 **배열 하나**로 두면 하나만 열리기는 상태의 모양이 보장한다 — 어긋날 자리가 없다.
`<details>` 를 쓰는 진짜 이유(⌘F · 키보드 · 스크린리더)는 `name` 없이도 그대로 온다.

### 값은 늘 배열로 돌려준다

하나만 열리는 모드에서도 `onChange` 는 `[]` 아니면 `[1]` 이다. **받는 쪽에서 타입을
좁힐 일이 없다.** 줄 때는 숫자 하나로도 받는다 — 입력을 너그럽게 받고 출력을 하나로
두는 것이 쓰는 쪽에 편하다.

### 머리말은 옵션이다 (판단)

`headingLevel` 을 주면 제목이 `<h3>` 같은 머리말이 되어 **스크린리더 사용자가 머리말
목록으로 건너뛸 수 있다.** `<summary>` 는 원래 phrasing content 하나 **또는 머리말 하나**를
품도록 규정돼 있어서 이 마크업이 맞다 (그래서 `TxCollapsible` 에 `titleAs` 를 더했다).

**기본으로 켜지 않았다.** 깊이는 그 페이지의 짜임을 아는 쪽이 정해야 한다 — `<h1>` 아래에
`<h4>` 를 놓으면 안 하느니만 못하다. 우리가 고를 수 없는 값을 기본값으로 정하지 않는다.
