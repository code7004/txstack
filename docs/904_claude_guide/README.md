# 904 — Claude 가이드 (에이전트용 사용 설명)

> **한 줄 정의**: 타 프로젝트에서 **Claude 가 이 라이브러리를 정확히 쓰도록** 하는 가이드.
> 패키지에 **동봉해서 npm 에 배포한다.**

## 왜 필요한가

사람용 문서와 에이전트용 문서는 다르다.

| 사람이 필요한 것           | 에이전트가 필요한 것                                        |
| -------------------------- | ----------------------------------------------------------- |
| 왜 이렇게 설계했는지, 배경 | **시그니처 · 규칙 · 금지사항** (서술은 오히려 방해)         |
| 훑어보고 감을 잡기         | 정확한 import 경로, 정확한 props 이름                       |
| 예제를 보고 응용           | **복사해서 그대로 쓸 수 있는 최소 예제**                    |
| "대충 이런 거구나"         | **하지 말아야 할 것** (있지도 않은 prop 을 만들어내지 않게) |

에이전트가 가장 많이 하는 실수는 **그럴듯한 API 를 발명하는 것**이다.
`<TxButton variant="primary">` 처럼, 있을 것 같지만 없는 prop 을 쓴다.
가이드의 첫 번째 목적은 그걸 막는 것이다.

## 도달 경로 (확정)

**패키지에 동봉해서 배포한다.** 소비자의 Claude 는 이 저장소를 볼 수 없고, `node_modules/@txstack/*` 만 본다.

```
소비자 프로젝트/
└─ node_modules/@txstack/ui/
   ├─ dist/
   ├─ README.md
   └─ <가이드 파일>      ← 이것을 읽는다
```

- 오프라인에서 동작하고, **설치된 버전과 가이드 버전이 자동으로 일치**한다
- 문서 사이트나 네트워크에 의존하지 않는다
- 패키지 `files` 에 포함시켜야 실제로 올라간다 → [05_RELEASE.md](../00_foundation/05_RELEASE.md) 점검 항목

## 여기에 함정이 하나 있다

**Claude Code 는 `node_modules/*/CLAUDE.md` 를 자동으로 읽지 않는다.**
동봉만 해두면 아무도 안 읽는다. 소비자 프로젝트가 **자기 `CLAUDE.md` 에서 가리켜야** 한다.

그래서 이 트랙의 산출물은 두 개다.

1. **동봉 가이드 파일** — 패키지 안에 들어가는 내용
2. **소비자용 붙여넣기 스니펫** — 소비자가 자기 `CLAUDE.md` 에 한 줄 넣으면 연결되는 문구

2번이 없으면 1번은 죽은 파일이다.

## 현재 상태

**없다.** 아무것도 만들어져 있지 않다.

## 컴포넌트 플로우에서의 위치

이 트랙은 **`S6` 단계의 양식을 소유**한다 → [06_COMPONENT_FLOW.md](../00_foundation/06_COMPONENT_FLOW.md)

- 내용의 원본은 `docs/001_ui/components/<Name>.md` (S1) 다. 가이드는 그것의 **압축판**이다
- 사실이 갈리면 S1 문서를 고치고 가이드를 맞춘다. 반대 방향으로 하지 않는다
- 파일럿 1차(`TxSpinner`)에서 **최소 골격을 만든다**
