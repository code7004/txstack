# 001 · `@txstack/ui`

**Tx\* React 컴포넌트. 목표는 두 가지 — 쉬운 사용법, 쉬운 커스터마이징.**

`react` / `react-dom` 은 peerDependency 다.

## 무엇을 해결하는가

세 프로젝트가 같은 모달, 같은 드롭다운, 같은 테이블을 각자 복사해 들고 있었다.
한 곳에서 버그를 고쳐도 나머지 둘은 그대로였다.

여기서 중요한 건 **그냥 옮기는 게 아니라는 것**이다. 원본 컴포넌트들은
앱 전역 타입·도메인 지식·`import.meta.env` 에 묶여 있다. **그걸 걷어내야 라이브러리가 된다.**

판정 기준: **네 번째 프로젝트가 설치해서 그대로 쓸 수 있는가.**

## 진입점 구조

무거운 선택적 의존은 **서브패스로 분리한다.** 루트 배럴을 import 한 소비자는
`ag-grid` 나 `react-day-picker` 를 설치하지 않아도 동작해야 한다.

| 진입점                   | 내용               | 추가 peer 의존                      | 상태      |
| ------------------------ | ------------------ | ----------------------------------- | --------- |
| `@txstack/ui`            | 대부분의 컴포넌트  | 없음                                | 19개 있음 |
| `@txstack/ui/aggrid`     | `TxAgGrid` 계열    | `ag-grid-community` `ag-grid-react` | 2개 있음  |
| `@txstack/ui/daypicker`  | `TxDayPicker` 계열 | `react-day-picker`                  | 4개 있음  |
| `@txstack/ui/styles.css` | 전체 스타일시트    | —                                   | **있음**  |

`tokens.css` 는 별도 진입점이 아니다 — `styles.css` 가 `@import` 로 먼저 싣는다.
컴포넌트를 옮길 때마다 `styles.css` 에 `@import` 가 한 줄씩 늘어난다.

```tsx
import { TxButton, TxModal } from "@txstack/ui";
import { TxAgGrid } from "@txstack/ui/aggrid";
import "@txstack/ui/styles.css";
```

#### `TxForm` — 조립 계층. 배선이 통째로 없었다

옮길 실질 코드가 거의 없는 자리인데 **결함이 14건** 나왔다. 재작성했다.

**캡션이 `<label>` 이 아니었다.** `<div>` 로 그려서 어떤 컨트롤과도 이어지지 않았다 —
스크린리더는 이름 없는 입력으로 읽었고, 캡션을 눌러도 포커스가 가지 않았다.
**에러도 마찬가지였다.** `aria-invalid` 도 `aria-describedby` 도 없어서 화면에만 떴다.

이제 필드가 `id` 를 만들어 셋을 잇는다. **컨트롤의 종류에 따라 잇는 방법이 다르다.**

| 컨트롤                                      | 방법              | 왜                                                 |
| ------------------------------------------- | ----------------- | -------------------------------------------------- |
| `Input` `SearchInput` `Textarea` `Combobox` | `<label for>`     | `<input>`·`<textarea>` 는 이름을 붙일 수 있다      |
| `Dropdown` `DayPicker`                      | `aria-labelledby` | 헤드가 `<div>`·`<button>` 이라 `for` 가 안 먹는다  |
| `CheckBox`                                  | 잇지 않는다       | `label` 로 자기 이름을 이미 갖고 있다. 겹쳐 읽힌다 |

**가리키는 곳이 없는 `htmlFor` 를 만들지 않는다.** `TxForm.Field` 는 `htmlFor` 를 준 때만
캡션을 `<label>` 로 그리고, 안 주면 `<span>` 이다.

이 배선을 위해 이미 나간 컴포넌트 세 곳에 통로를 열었다 — `TxDropdown` 과 `TxDayPicker` 는
props 타입이 닫혀 있어 `aria-describedby` 조차 넘길 수 없었고, `TxInputLike` 는 `id` 가 없었다.
**넷 다 더하기만 했다.**

##### `labelWidth` 는 아무 일도 하지 않고 있었다

Context 로 내려간 값을 읽는 것은 `TxForm.Label` 뿐이었는데, 필드는 `Label` 이 아니라
`caption` 으로 그린다. **그래서 어떤 필드도 정렬되지 않았다** — 그걸 보여주던 스토리가
일어나지 않는 일을 보여주고 있었다.

값의 모양도 문제였다. `"w-24"` 라는 **Tailwind 클래스 문자열**이라 Tailwind 를 쓰지 않는
소비자에게는 아무 값도 아니다. 지금은 CSS 길이(`"6rem"`)를 받아 `--tx-form-label-width` 를
세우고, **배치는 CSS 가 정한다.** Context 도 리렌더도 없고, 소비자가 그 변수를 직접 덮어도 똑같이 동작한다.

##### 메시지는 자리가 하나다

원본은 `warning` 과 `error` 를 **같은 좌표**(`absolute -bottom-5 left-0`)에 그려서 둘이 있으면
글자가 포개졌다. 스토리 문서에는 "error 가 우선한다" 고 적혀 있었지만 그렇게 만드는 코드가 없었다.

이제 슬롯 하나에 `error` 가 우선한다. 문구 앞에 붙던 영어 하드코딩(`warning ` · `error `)도 없앴다 —
소비자가 바꿀 수 없었고 스크린리더도 그대로 읽었다.

**빈 자리를 미리 잡아 둔다.** 에러가 떴다 사라져도 아래 줄이 밀리지 않고, live region 이
먼저 자리잡고 있어야 안에서 바뀐 내용이 읽힌다 (`TxCapsLockCheck` 에서 겪은 것과 같다).
높이는 글자 크기에서 계산하므로 `--tx-form-message-reserve: 0` 한 줄로 되돌릴 수 있다.

##### 그 밖에 고친 것

- **`data-tag` 가 통과 props 에 덮였다.** 스프레드보다 앞에 있어서, `TxForm.Input` 이 넘긴
  값이 `TxForm.Field` 라는 이름을 지웠다. 게다가 `SearchInput` 이 `data-tag="TxForm.Input"` 을
  주고 있었다 — 복붙 실수다. 지금은 필드가 늘 `TxForm.Field` 이고 컨트롤이 자기 이름을 갖는다
- **`className` 의 목적지가 컴포넌트마다 달랐다.** `Input` 은 필드 상자로, `Dropdown` 은
  구조분해에서 빠져 드롭다운 자체로 샜다. 지금은 전부 **필드 상자**다 — 그리드에 놓는 자리다
- **입력창마다 `w-full` 이 박혀 있었다.** 소비자가 폭을 되돌릴 수 없다. 그리드 항목은 칸을
  저절로 채우므로 클래스가 필요 없다
- **타입이 거짓말했다.** `TxFormInput` 이 필드 테마 타입의 값을 `TxInput` 의 `theme` 으로 넘겼다
- **순환 참조.** `TxForm.hook.ts` 가 배럴을 import 하고 배럴이 그 훅을 내보냈다
- 죽은 테마 키 둘(`field.readOnly` · `field.surface`)과 `theme` prop 전체를 걷어냈다
- `memo` 셋 · `useMemo` 둘 · `useCallback` 하나가 전부 헛일이었다. `children` 을 받거나
  인라인 객체를 deps 로 삼아서 매 렌더 새 참조였다. "렌더마다 반복될 수 있어 안정화한다" 는
  주석이 붙어 있었지만 사실이 아니었다

##### 밀도는 배치가 정한다 — prop 을 늘리지 않았다

원본이 캡션을 테두리에 얹고 메시지를 띄운 이유는 **공간을 적게 쓰려던 것**이었다.
그 대가가 겹침이었다. 그렇다고 자리를 다 잡으면 한 행이 두 배가 된다.

같은 필드를 배치만 바꿔 재 본 값이다.

| 조합                                          | 필드   | 한 행      |
| --------------------------------------------- | ------ | ---------- |
| 기본 — 세로 쌓기 + 메시지 자리 예약           | 87.5px | **99.5px** |
| `labelWidth` — 캡션이 왼쪽으로                | 62px   | **74px**   |
| `labelWidth` + `--tx-form-message-reserve: 0` | 44px   | **56px**   |
| (원본 — 노치 + 겹침)                          | 40px   | ~52px      |

**세 번째가 원본만큼 조밀한데 겹치지 않는다.** 그래서 새 prop 을 만들지 않았다 —
`labelWidth` 와 토큰 하나가 이미 그 일을 한다.

**기본값은 안전한 쪽에 뒀다.** 라이브러리의 기본이 "에러가 뜨면 줄이 밀린다" 이면
소비자는 그걸 겪고 나서야 알게 된다. 반대로 조밀하게 만드는 것은 한 줄이면 되고,
그 줄을 쓰는 사람은 무엇을 맞바꾸는지 알고 쓴다. `Density` 스토리가 셋을 나란히 보여 준다.

##### `TxForm.Flex` 는 폭을 나눈다

`TxFlex` 와 겹쳐 보이지만 다르다 — **자식이 남는 폭을 똑같이 나눠 갖는다.**
원본 스토리가 버튼마다 `className="flex-1"` 을 붙이고 있던 자리다. `TxFlex` 는 내용만큼만 차지한다.

전역 토큰이 하나 늘었다 — `--tx-color-warning`.

**밝은 노랑을 쓰지 않는다.** 원본은 `text-yellow-300` 이었는데 흰 바탕에서 대비가 1.32:1 이라
작은 글씨로는 사실상 안 보였다 (AA 기준 4.5:1). 흰 바탕에서 그 기준을 넘는 노랑은
`yellow-700`(`#a16207`, 4.92:1) 뿐이다. 다크는 바탕이 어두우니 반대로 밝은 노랑
(`#facc15`, 11.66:1)이 읽힌다.

#### `TxDayPicker` — 서브패스 분리가 실제로 도는 것을 확인했다

빌드 산출물에서 잰 값이다.

| 진입점                    | 외부 의존                                           |
| ------------------------- | --------------------------------------------------- |
| `dist/index.js` (32KB)    | `react` · `react-dom` — **`react-day-picker` 없음** |
| `dist/daypicker.js` (9KB) | `react-day-picker`                                  |

루트 배럴을 import 한 소비자는 `react-day-picker` 를 설치하지 않아도 된다. `index.test.ts` 가
"서브패스 전용 컴포넌트가 루트 배럴에 없다" 로 이 경계를 지킨다.

**`react-day-picker` 의 `dist/style.css` 를 쓰지 않는다.** 그쪽 클래스 이름을 우리 것으로
갈아끼우고 레이아웃까지 직접 그렸다 — `styles.css` 에 `tx-daypicker` 69곳, `rdp-` 0곳이다.
그래서 소비자는 여전히 `@txstack/ui/styles.css` 하나만 import 하면 되고, 번들러가
`node_modules` 안의 CSS 를 처리할 수 있어야 할 이유도 없다.

`dayjs` optional peer 를 걷어냈다. 쓰던 것이 포맷·하루 경계·일수 차이 셋뿐이라 직접 쓴다.
일수 차이를 밀리초로 나누지 않는 것이 중요하다 — 서머타임이 있는 지역에서 하루가 23시간이 되면
결과가 어긋난다.

원본이 고쳐진 것들:

- **팝업을 두 컴포넌트가 각자 다시 만들었다.** 게다가 **위치를 바꾸기 전에 잰 값으로 판정**해서
  첫 열림은 늘 한 프레임 뒤처졌고, **스크롤하면 닫아 버렸다.** `TxPopup` 으로 갈아끼웠다
- **라이브러리가 `alert()` 를 띄웠다.** 이제 `maxDays` 를 넘는 날은 아예 눌리지 않는다 —
  고르고 나서 알리는 것보다 못 고르게 하는 편이 낫다
- `TxInputLike` 를 쓰면서 열림 상태를 안 넘겨 스크린리더가 늘 "닫힘" 으로 들었다
- `header` render prop 이 값과 콜백 넷을 되넘기는 복잡한 시그니처였다 → `ReactNode` + `ref`

##### 포털된 팝업은 앵커의 토큰을 못 읽는다

`TxDayPicker` 의 달력이 **칸 폭 0 으로 그려지는 것**을 Storybook 실측에서 발견했다.

토큰을 앵커(`.tx-daypicker`)에 선언했는데 달력은 `document.body` 로 포털된다. CSS 변수는
DOM 을 따라 상속되므로 **앵커의 선언이 팝업에 닿지 않는다.** 값이 통째로 사라져 칸 폭이 0 이 되고
색이 안 칠해진다.

**`TxDropdown` 과 `TxCombobox` 도 같은 상태였다** — 목록 항목의 여백·글자크기·짚은 줄 배경이
전부 안 먹고 있었다. 셋 다 팝업 쪽 클래스(`.tx-daypicker__panel` · `.tx-dropdown__list` ·
`.tx-combobox__list`)로 토큰 선언을 옮겼다.

**규칙:** 팝업 안에서 쓰는 토큰은 팝업 쪽에 선언한다. 전역 토큰(`--tx-color-*`)은 `:root` 에
있어 어디서든 닿는다. 세 컴포넌트의 CSS 계약 테스트가 이걸 지킨다 — 앵커에만 선언된 토큰을
팝업 쪽 규칙이 쓰면 실패한다.

#### `TxDropdown` — 재작성. 그리고 `TxPopup` 이 생겼다

원본 848줄에서 결함이 가장 많이 나왔다.

**키보드 트랩이었다.** `Tab` 을 가로채 다음 항목으로 이동시켜서 **열린 드롭다운에서 빠져나갈 수
없었다.** 각 줄에 `tabIndex={0}` 이 붙어 줄이 100개면 탭 순서에 100개가 들어갔고,
`aria-activedescendant` 가 없어 스크린리더는 어느 줄이 활성인지 몰랐다.

**200ms 디바운스가 모든 클릭에 걸려 있었다.** 주석은 "정렬 헤더 연속 클릭 방지" 인데
열기·항목선택·전체선택 전부에 적용돼서, **다중 선택에서 빠르게 두 개를 고르면 두 번째가 무시됐다.**

**목록이 잘렸다.** `position: absolute` + `z-20` 이라 `overflow: hidden` 조상 안에서 잘리고,
화면 아래쪽에서 열면 밖으로 나갔다.

##### `TxPopup` — 앵커에 붙어 뜨는 층 (내부 전용)

계획대로 팝업 계층을 부품으로 뽑았다. **`TxCombobox`(13번)와 나중의 `TxDropMenu` ·
`TxContextMenu` 가 같은 것을 쓴다.** 맡는 것은 넷이다.

1. **포털** — `document.body` 로 낸다. 조상의 `overflow`·`transform` 에 갇히지 않는다
2. **위치** — 아래가 좁으면 위로 뒤집고, 화면 밖으로 나가지 않게 가둔다. 스크롤·리사이즈를 따라간다
3. **바깥 클릭** — `pointerdown` 을 **캡처 단계**에서 듣는다. 버블이면 중간에서
   `stopPropagation` 한 코드에 막힌다 (원본이 헤더에 `stopPropagation` 을 걸어 소비자의
   부모 핸들러를 죽이던 이유이기도 하다)
4. **Escape**

**포커스는 옮기지 않는다.** 목록형 위젯은 포커스를 앵커에 두고 `aria-activedescendant` 로
활성 항목을 가리키는 것이 표준이다.

쌓임 순서는 `--tx-popup-z` 토큰이다. 매직넘버로 박으면 소비자가 모달 위에 띄울 방법이 없다.

##### 그 밖에 고친 것

- `onChangeNumb` → `onChangeNumber` (`TxInput` 규약)
- `TxDropdownMulti` 헤더의 한글 하드코딩(`전체 n items`)을 `locale` 을 타게 바꿨다
- 다중 선택의 콜백이 `data` 첫 항목 타입으로 갈렸다 → **고른 값들에서** 본다
- `{...props}` 를 `<div>` 에 뿌려 `multiple`·`maxHeight` 가 DOM 속성으로 샜다
- 죽은 prop(`warning`·`error`) 제거. 드롭다운과 무관한 `numberToPeriod`(날짜 유틸)도 뺐다
- 확인 버튼 모드는 유지했다 — 고르는 동안 서버를 치지 않으려는 자리다. 확인 전까지 값이
  나가지 않고, 확인하지 않고 닫으면 되돌아간다

#### `TxCapsLockCheck` — 손대지 않은 칸에 경고가 떴다

원본은 `window` 에 키 리스너를 붙였다. **화면 어디서 타이핑하든 반응해서**, 로그인 폼을
띄워 둔 채 다른 곳에서 Caps Lock 을 켜면 손대지도 않은 비밀번호 칸에 경고가 켜졌다.

**입력창을 `children` 으로 감싸는 구조로 바꿨다.** 감싼 안에서 누른 키만 듣고,
경고가 뜨면 `aria-describedby` 로 그 입력창과 이어 준다 — 스크린리더가 그 칸에서 바로 안내한다.

`role="status"` 영역을 **경고가 뜰 때 비로소 만들던 것**도 고쳤다. live region 은 미리
자리잡고 있어야 안에서 바뀐 내용을 읽어 준다 — 나중에 삽입하면 화면엔 떠도 안 읽힐 수 있다.

`preserveSpace` 는 목적을 달성하지 못하고 있었다. 빈 상태를 `&nbsp;` 로 채웠는데
**그 문단에만 글자 크기 클래스가 안 붙어서**, 경고가 뜨는 순간 막으려던 그 점프가 났다.
높이를 글자 크기와 줄높이에서 계산하도록 바꿨다. `&nbsp;` 도 없앴다 — 스크린리더가 읽는 텍스트 노드다.

`locale` prop 을 없앴다. `text` 를 키로 주고 `locale` 로 번역하는 이중 경로라 어느 쪽이
맞는지 헷갈렸다. 번역된 문구를 `text` 에 그대로 준다.

**남는 한계 하나.** 브라우저는 키를 누를 때만 Caps Lock 상태를 알려 준다. 마우스로 칸을 눌러
들어온 직후에는 알 수 없고 첫 글자를 칠 때 알게 된다. 이건 고칠 수 없다.

#### `TxCheckBox` — 체크박스가 아니었다

원본은 `<div onClick>` 이었다. 키보드로 도달할 수 없고, 스크린리더가 체크박스로 읽지 않고,
**`<form>` 안에서 값이 제출되지 않았다.** `TxForm` 에 들어갈 컴포넌트인데 폼 필드로 동작하지 않았다.

시각적으로만 숨긴 **진짜 `<input type="checkbox">`** 를 `<label>` 로 감싸는 표준 구조로 다시 만들었다.
그러면 키보드·스크린리더·폼 제출이 전부 공짜로 따라오고, `name` · `value` · `required` 같은
표준 속성도 그냥 통과한다. **`display: none` 으로 지우면 안 된다** — 그러면 Tab 도 폼 제출도 죽는다.

상태를 CSS 가 `:checked` 로 읽으므로 **컴포넌트가 체크 상태를 들지 않는다.** 원본은 `value` 를
내부 state 로 복사하고 effect 로 동기화해서, controlled 로 쓰는데 콜백을 안 주면 어긋났다.

`variant="toggle"` 에는 `role="switch"` 를 준다 — 스크린리더가 "선택됨" 이 아니라 "켜짐/꺼짐" 으로 안내한다.

죽은 prop 세 개(`borderColor` · `fillColor` · `cursorColor`)를 걷어냈다. 타입에 선언만 있고
구현에서 꺼내 쓰지도 않았다. 대신 `disabled` 가 없던 것을 채웠다.

#### `TxTextarea` — 껍데기를 공유한다

**`.tx-input` 클래스를 함께 걸고 높이만 되돌린다.** 원본은 껍데기를 따로 그리다
`TxClassBase`(배경·글자색)를 빠뜨려서 **텍스트영역만 배경이 없었다** — 다크모드에서 부모가 비쳤고
입력한 글자는 `gray-500` 으로 흐렸다. 클래스를 공유하면 그렇게 갈라질 자리가 없다.

**이게 `TxInput` 에서 정한 규칙의 첫 적용이다** — "껍데기를 함께 쓰는 컴포넌트는
`.tx-input` 을 같이 건다". `TxInputLike` 에 이어 두 번째다.

콜백도 정리했다. 원본의 `onChangedText` 는 **값 변경 · Enter · blur 세 곳에서** 불렸다.
textarea 에서 Enter 는 줄바꿈이라 `change` 로 이미 오는데 같은 값으로 한 번 더 왔고,
blur 는 값이 안 바뀌어도 왔다. `onChangeText`(`TxInput` 과 같은 이름) + `onBlurText` 로 갈랐다.

**`autoGrow` 는 신규다.** 내용에 맞춰 높이가 늘고 줄어든다. 켜면 손잡이(`resize`)가 사라진다 —
둘이 같이 있으면 타이핑할 때마다 사용자가 맞춰 둔 높이가 덮인다.

#### `TxCombobox` — 완료 (temp 에 없던 신규)

**자유입력 + 자동완성.** 포커스하면 후보가 뜨고, 타이핑으로 걸러지고, ↑↓/Enter/Esc 로 고르되
**목록에 없는 값도 그대로 입력된다.**

`TxDropdown` 은 이걸 못 한다 — 검색·필터·자유입력이 하나도 없는 순수 select 다. 실제 공백이다.

`TxDropdown` 에서 뽑아 둔 `TxPopup` 위에 올렸다. 그래서 포털·뒤집기·바깥클릭·Escape 와
키보드 패턴(`aria-activedescendant`, 하이라이트 스크롤 추적, Tab 비가로채기)이 그대로 따라왔다.

**값은 보이는 글자 그 자체다.** `TxDropdown` 처럼 `{ name, value }` 를 받지 않는다 —
목록에 없는 글자를 쳤을 때 대응할 코드값이 없기 때문이다. 코드값이 필요하면 그건 `TxDropdown` 의 일이다.

`Home`·`End` 를 **가로채지 않는 것**이 `TxDropdown` 과 다른 점이다. 글자 안에서 커서를 옮기는
키라 목록 이동에 뺏기면 편집이 불편해진다.

후보가 하나도 없으면 목록을 닫는다. 자유입력이라 새 값을 치는 중일 뿐이고, 빈 상자를 띄울 이유가 없다.

기본은 제한 없이 전부 보여 주고 안에서 스크롤한다. `limit` 을 주면 잘라내고
**몇 개가 더 있는지 알리는 줄**이 붙는다 — 없으면 사용자는 이게 전부인 줄 안다.

앱 쪽 시제품에서 채운 것들:

- **접근성 전체** — `role="combobox"` · `aria-expanded` · `aria-controls` · `aria-activedescendant`,
  목록의 `role="listbox"`/`option`. 없으면 스크린리더에 입력창 하나로만 들린다
- **포털** — `position: absolute` 로 띄우면 `overflow: hidden` 조상에 잘린다.
  테이블 필터 안에 넣으면 바로 겪는다
- **하이라이트 스크롤 추적** — 목록에 최대 높이가 있으면 ↓ 로 보이는 영역을 벗어날 때 따라가야 한다
- **후보 개수 제한을 알리기** — 잘라서 보여 준다면 더 있다는 표시가 필요하다
- 색은 전부 토큰으로

`TxModal` 도 포털을 안 쓴다 — temp 에서 `TxDropMenu`·`TxContextMenu`·`TxSlidePanel`·`TxToolTip`
은 `createPortal` 을 쓰는데 `TxDropdown`(고쳤다)과 `TxModal` 만 빠져 있었다. `TxModal` 은
3차에서 `TxPopup` 을 쓸지 함께 본다.

- [x] `TxForm.Combobox` — **만들었다.** 자유입력 칸도 캡션·에러 배선이 똑같이 필요하다.

#### `TxInput` — 첫 CSS 이행

기반 4개와 달리 **Tailwind 클래스 문자열에서 CSS 로 새로 옮긴 첫 컴포넌트**다. 여기서 정해진 것들:

- **테두리·배경·포커스 링은 래퍼(`.tx-input`)가 소유하고 `<input>` 은 투명하다.**
  아이콘을 나란히 놓아도 테두리가 하나로 보여야 하기 때문이다 — `TxSearchInput` 이 그 구조를 쓴다.
- **껍데기를 함께 쓰는 컴포넌트는 `.tx-input` 클래스를 같이 건다.** `TxInputLike` 가 그렇다 (`TxDayPicker` 가 쓴다).
  폼 안에 나란히 놓았을 때 높이와 테두리가 어긋나면 안 된다.
- **`style` 은 `className` 과 같은 자리(껍데기)에 건다.** CSS 변수는 아래로만 상속되므로
  안쪽 요소에 걸면 껍데기가 읽는 토큰이 안 바뀐다 — 소비자가 `style={{ "--tx-…": … }}` 로
  값을 줘도 아무 일도 일어나지 않는다.
- **바깥 선택자로 안쪽을 덮는다.** `.tx-search-input .tx-input` 이 안쪽 껍데기를 지운다.
  원본은 `theme` prop 으로 클래스를 비웠는데 그 prop 은 폐기됐다. CSS 로 풀면 공개 API 가 늘지 않는다.

전역 토큰 두 개가 늘었다 — `--tx-color-surface`(입력 가능한 표면) · `--tx-color-border`(그 테두리).
`--tx-color-muted` 와 다르다: 그쪽은 보조 버튼처럼 바탕에 눌러앉는 자리다.

**Storybook 이 버그를 하나 잡았다.** `AlignsWithTxInput` 스토리에서 `TxSearchInput` 이 40px 이어야 할
자리에서 42px 로 나왔다 — 껍데기에 높이가 없어 내용 위에 자기 테두리가 얹혔다.
jsdom 에는 레이아웃이 없어 테스트로는 안 보인다. **사람이 보는 자리가 실제로 값을 했다.**

#### `TxIcons` — 내부 전용, 2개만

7개 중 **`TxIconClose` · `TxIconSearch` 둘만** 가져왔다.

- `IconSortAsc` · `IconSortDesc` · `IconLayout` 은 **쓰는 곳이 하나도 없었다.**
  정렬 아이콘 2개는 제외 확정된 `TxCoolTable` 것이었다
- `IconDragHandle*` 2개는 `TxLayout`(3차 후보) 것이라 그때 함께 온다

**배럴에서 내보내지 않는다.** 두 개짜리 세트는 소비자에게 쓸모가 없고(이미 lucide·heroicons 를 쓴다),
공개하면 이름과 모양이 공개 API 가 되어 바꿀 때마다 major 다.
**닫는 건 major 지만 나중에 여는 건 minor** 라 지금은 닫는다.

소비자가 아이콘을 갈아끼워야 하는 자리(입력창의 지우기·검색 버튼)는 그 컴포넌트가 prop 으로
받는 쪽이 맞다 — `TxInput` 을 옮길 때 판단한다.

두 규약이 조합의 근거다: **`1em`** (놓인 자리의 `font-size`) · **`currentColor`** (놓인 자리의 `color`).
`TxSpinner` 와 같다.

안 가져온 5개에 결함이 몰려 있었다 — `IconDragHandleHonrizonBold` 오타, `IconLayout` 의
kebab-case DOM 속성(React 콘솔 경고), `SVGRepo_*` 껍데기 `<g>` 3중첩(하드코딩 `id` 라 같은
페이지에 둘만 놓여도 중복), `1em` 누락. 가져온 둘에는 하나도 없다.

`TxForm.DayPicker` / `DayPickerRange` 는 **루트 배럴에 없다.** `@txstack/ui/daypicker` 가
가져간다 — 코어가 `react-day-picker` 를 import 하면 optional peer 가 성립하지 않는다.
이 분리는 temp 에서 이미 지켜져 있다.

**`TxAgGrid`(23번)는 서브패스라 얽히지 않아 먼저 했다.** 나머지는 위 순서대로 간다.

#### `TxModal` — 네이티브 `<dialog>` 로 옮겼다

원본 78줄에서 **접근성 결함 셋**이 한꺼번에 나왔다. 포커스 트랩이 없어 열린 모달에서 Tab 이
배경으로 새어 나갔고, 포커스를 모달로 옮기지도 닫을 때 되돌리지도 않았으며,
닫기 아이콘이 `<div>`(SVG)에 `onClick` 이라 키보드로 누를 수 없었다.

**`<dialog>` + `showModal()` 로 옮겨서 앞의 둘을 브라우저에 넘겼다.** 덤으로 top layer 에
올라가므로 포털도 z-index 토큰도 필요 없다 — `overflow: hidden` 조상에 잘리지 않고,
`TxPopup` 이 `--tx-popup-z` 를 들고 있는 것과 다른 점이다. 손으로 짠 트랩은 중첩 모달과
동적 내용에서 새기 쉬운데 그 부담을 지지 않는다.

**`TxPopup` 을 쓰지 않는다.** 그쪽은 앵커에 붙어 뜨는 층이라 하는 일이 다르다.
겹치는 건 `createPortal` 두 줄뿐인데 `<dialog>` 는 그것도 필요 없다. (3차에서 정하기로 했던 항목이다.)

**jsdom 에는 `showModal` 이 없다**(30.0.1 에서 확인). 그래서 있는지 보고 없으면 `open` 속성으로
연다 — 트랩은 없지만 내용은 그려지므로 **소비자가 jsdom 에서 테스트해도 깨지지 않는다.**

##### `cancel` 이벤트에만 기대면 안 된다 — 사용자가 잡았다

Escape 가 **아무 일도 하지 않았다.** `<dialog>` 의 `cancel` 이벤트만 듣고 있었는데, 그건
DOM 이벤트가 아니라 **브라우저가 판단해서 보내는 close request** 라서 끼워 넣은 화면
(Storybook 의 iframe)이나 자동화 도구에서는 오지 않는다. 처음 옮길 때 "실물 Escape 는
확인하지 못했다" 고 적어 둔 바로 그 자리다.

이제 `keydown` 을 **직접 받는다.** 포커스가 창 안에 갇혀 있으므로 키는 반드시 `<dialog>` 로
올라온다. 기본 동작을 막는 것도 그대로 중요하다 — 안 막으면 브라우저가 스스로 닫아서
창은 사라졌는데 `open` 은 `true` 로 남는다.

`cancel` 경로도 남겨 뒀다(두 경로가 다 오는 환경이 있다). 대신 **닫아 달라는 요청을 한 번만
흘려보낸다** — 소비자의 `onClose` 가 두 번 불리면 저장이나 라우팅이 두 번 일어난다.

`closeOnEscape` 가 생겼다. 끄는 자리는 답을 받아야만 하는 창인데, **`TxDialog` 는 켠 채로 둔다** —
네이티브 `confirm` 도 Escape 를 `false` 로 보기 때문이다.

##### 닫는 길 — 두 컴포넌트가 다르다

| 닫는 길                | `TxModal` | `TxDialog`                    |
| ---------------------- | --------- | ----------------------------- |
| 닫기 버튼(X)           | 있다      | **없다** — 취소 버튼과 겹친다 |
| 바깥(어두운 바탕) 클릭 | 닫힌다    | **막는다**                    |
| Escape                 | 닫힌다    | 닫힌다 → `false`              |

바깥 클릭만 막는 이유는 **잘못 누른 것이 "취소를 골랐다" 가 되면 안 되기** 때문이다.
Escape 는 그와 달리 분명한 의사표시다. **스토리 문서가 이 표와 어긋나 있었다** — 사실에 맞췄다.

##### 화면과 상태가 갈리지 않게

Escape 를 브라우저가 스스로 처리하면 창은 닫히는데 `open` 은 `true` 로 남는다.
`cancel` 의 기본 동작을 막고 `onClose` 만 부른다 — **닫는 것은 소비자가 `open` 을 내려서 한다.**

원본은 Escape 를 `window` 에서 들어서 **겹쳐 뜬 모달이 한 번에 다 닫혔다.** 이제 브라우저가
맨 위 모달에만 close request 를 보낸다.

##### 그 밖에 고친 것

- **`id="txpopup-title"` 하드코딩** — 모달이 둘이면 `aria-labelledby` 가 겹쳤다. `useId` 로 바꿨다
- **`data-tag="TxPopup"`** — TxModal 인데 이름이 TxPopup 이었다 (복붙)
- **제목이 없으면 닫기 버튼째 사라졌다.** 앱의 `PartnerList` 가 실제로 제목 없이 쓰는데,
  `preventOutside` 까지 켜면 닫는 길이 ESC 하나였다. 지금은 제목과 무관하게 닫기 버튼이 있다
- **배경 스크롤이 안 잠겼다.** `<dialog>` 도 이건 안 해 준다. 겹쳐 뜰 수 있으므로 **세어 둔다** —
  안쪽이 닫혀도 바깥이 남아 있으면 풀리지 않는다
- 안쪽에 걸린 `onClick={(e) => e.stopPropagation()}` 제거. 바깥 클릭은 `event.target` 이
  `<dialog>` 자신인지로 가린다 — `TxDropdown` 에서 고쳤던 것과 같은 결함이었다
- `preventOutside` → `closeOnBackdrop`. **부정형 prop 을 만들지 않는다**
- `visible`/`onExit` → `open`/`onClose` (`TxPopup`·`TxDropdown` 과 같은 이름)

##### framer-motion 을 걷어낸 첫 사례

여닫히는 페이드는 `@starting-style` 과 `transition-behavior: allow-discrete` 로 한다.
`::backdrop` 도 같은 방식으로 흐려진다. **애니메이션 라이브러리 하나를 peer 에서 뺀 값이다.**
`--tx-modal-duration: 0ms` 면 움직임 없이 즉시 뜬다.

전역 토큰이 하나 늘었다 — `--tx-color-backdrop`. **다크모드에서 뒤집지 않는다**:
라이트든 다크든 "뒤를 가린다" 는 뜻이 같다.

#### `TxTooltip` — 마우스로만 열렸다

원본 125줄. **여는 길이 hover 하나뿐**이라 키보드로도 터치로도 열 수 없었고,
`role="tooltip"` 도 `aria-describedby` 도 없어 스크린리더에는 존재하지 않았으며,
Escape 로 치울 수도 없었다 (WCAG 1.4.13 이 요구하는 셋 중 어느 것도 없었다).

지금은 **여는 길이 셋**이다 — 마우스 올리기 · 포커스 · 터치로 길게 누르기.
**포커스로 열 때는 기다리지 않는다.** 키보드로 온 사람은 이미 그것을 보려고 온 것이다.

##### 설명을 누가 받는가

`aria-describedby` 는 **포커스를 받는 그 요소**에 걸려야 읽힌다. 조상에 걸면 스크린리더가
읽지 않는다. 그런데 감싸는 대상이 버튼일 수도 있고 그냥 글자일 수도 있다.

그래서 마운트할 때 감싼 안에 포커스를 받는 것이 있는지 본다.

| 감싼 것        | 감싸개의 탭 순서 | 설명이 걸리는 곳 |
| -------------- | ---------------- | ---------------- |
| 버튼·링크·입력 | 끼어들지 않는다  | **그 요소**      |
| 그냥 글자      | 감싸개가 받는다  | 감싸개           |

버튼을 감쌌는데 감싸개까지 탭 순서에 넣으면 한 컨트롤에 정거장이 둘이 된다.
반대로 글자만 감쌌을 때 아무도 안 받으면 키보드만 쓰는 사람에게 툴팁이 존재하지 않는다.
**브라우저에서 둘 다 확인했다** — 버튼은 Tab 한 번에 오고 `aria-describedby` 가 버튼에 걸린다.

##### `TxPopup` 이 자체 위치 계산을 대신한다

원본은 포털·위치·스크롤 추적을 직접 들고 있었다. 그러면서 첫 열림은 **툴팁을 그리기 전에**
위치를 계산해 `tooltipRect` 가 없었고, **기본값 250×80** 으로 재고 다음 프레임에 다시 잡았다.
`TxDayPicker`·`TxDropdown` 에서 고쳤던 것과 같은 결함이다. `TxPopup` 은 `useLayoutEffect` 로
그리기 전에 자리를 끝낸다.

`edgeBuffer = 64` 매직넘버도 사라졌다 — 화면 오른쪽 64px 안에 있으면 툴팁 폭과 무관하게
오른쪽 정렬로 뒤집던 값이다. 쌓임 순서도 `--tx-popup-z` 를 따른다.
원본은 **`z-50` 과 `z-[9999]` 를 한 클래스에 둘 다** 박아 두었다.

##### 그 밖에 고친 것

- **닫는 지연이 없어 트리거에서 툴팁으로 가는 8px 사이에 사라졌다.** `closeDelay`(기본 100ms)로
  갈랐고, 툴팁 위에서는 안 닫힌다 — 앱이 툴팁 안에 JSON 트리를 띄우므로 읽고 긁을 수 있어야 한다
- **언마운트할 때 타이머를 안 껐다**
- `overflow: auto` 를 인라인으로 박아 툴팁 안에 스크롤이 생겼다. 높이는 `TxPopup` 이 맡는다
- `width`·`height` prop 을 없앴다. 툴팁에 고정 높이를 주는 자리는 드물다 → `maxWidth` 하나
- **이름을 `TxTooltip` 으로 맞췄다.** 폴더·파일은 `TxToolTip`, 컴포넌트는 `TxTooltip` 이었다

##### 넘치는 내용과 스크롤 — 둘 다 `TxPopup` 이 한다

사용자가 스토리에서 확인하고 싶다고 해서 재 봤더니 **둘 다 이미 되고 있었다.** 다만 스토리에
없어서 안 보였고, 툴팁이 높이를 조절할 길도 없었다.

- **툴팁 안 스크롤** — `.tx-popup` 이 `overflow-y: auto` 이고 높이 상한이 있다.
  실측: `20rem`(320px) 안에 713px 내용이 들어가 스크롤된다. 툴팁 위에서는 안 닫히므로
  끝까지 읽고 긁을 수 있다
- **페이지·조상이 굴러가면 따라간다** — 실측: 150px 굴리니 트리거를 따라 356 → 206 으로 옮겨
  간격 4px 를 지켰다

`maxHeight` 를 `maxWidth` 와 짝으로 열었다. `Scrollable` · `FollowsScroll` 스토리를 더했다.

**터치는 길게 누르면 뜬다.** 톡 건드리는 것으로는 안 뜬다 — 누르려던 것인지 보려던 것인지
헷갈리기 때문이다. 뜬 뒤에 손을 떼도 남아서 읽을 새가 있고, 다른 곳을 누르면 닫힌다.

#### `TxCard` — 카드가 다섯 가지를 겸하고 있었다

카드는 어느 라이브러리에나 있다(MUI · Ant · Chakra · Mantine · shadcn). 다만 **그들이 파는 것은
얇은 상자**다 — 테두리·모서리·그림자·여백을 한 자리에서 정하고 슬롯을 주는 것. 값어치는
로직이 아니라 **여백과 모서리가 앱 전체에서 같아지는 것**에 있다.

원본 129줄은 다섯 가지를 겸했다.

| 하던 일                    | 판정                                  |
| -------------------------- | ------------------------------------- |
| 상자 · 슬롯                | **남긴다.** 이게 카드다               |
| 접기/펼치기                | **남긴다** (사용자 판단)              |
| "더보기" 링크              | **자른다.** 소비자가 내용 안에 넣는다 |
| 로딩 스켈레톤              | **자른다.** `TxLoading` 이 이미 한다  |
| `displayName` 로 자식 훑기 | **자른다.** 아래                      |

앱은 파일 하나에서 `caption` 과 `TxCard.Footer` 만 쓴다. `link` · `useFold` · `isFold` ·
`isLoading` · `TxCard.Header` · `TxCard.Caption` 은 **한 곳도 쓰지 않는다.**

##### 자식을 문자열로 훑고 있었다

```tsx
if (getDisplayName(child.type) === "TxCardCaption") captions.push(child);
```

이러면 자식을 한 겹만 감싸도(조건부 렌더 · Fragment · `memo`) 못 찾아 **조용히 엉뚱한 자리에
들어간다.** 지금은 순서대로 두고 CSS 가 자리를 잡는다 — 푸터는 본문 안에 있지만 음수 여백으로
카드 폭을 꽉 채운다. 훑을 일이 없다.

##### 링크를 자르니 라우터 의존이 하나 줄었다

원본은 카드 안에서 `react-router` 의 `Link` 로 "더보기" 를 그렸다. 글자도 한글 하드코딩이었다.
**카드가 라우터를 알 이유가 없다** — 소비자가 내용 안에 자기 링크를 넣으면 된다.

그래서 3차에서 정한 "링크 컴포넌트 주입" 이 **`TxDropMenu` · `TxContextMenu` 두 곳만 남았다.**
거기서는 메뉴 항목이 곧 링크라 주입이 필요하다.

##### 그 밖에 고친 것

- **controlled 인데 값을 내부 state 로 복사**하고 effect 로 맞췄다 — `TxTabs` 와 같은 결함이다
- **`isLoading` 이 `boolean | 배열` 을 겸했다.** `Array.isArray(isLoading) && isLoading.length === 0`
  으로 판정했는데, 타입 하나가 두 가지 뜻을 갖고 있었다
- 접기 버튼 글자가 `"접기 🔼"` 로 하드코딩. 지금은 `aria-expanded` 가 상태를 알리고
  이름은 `collapseLabel` · `expandLabel` 로 바꾼다
- **접어도 내용을 지우지 않는다.** `hidden` 으로 감출 뿐이라 안에 치던 폼 값이 살아남는다
  (브라우저에서 확인했다). 지우면 펼쳤을 때 처음부터 다시 쳐야 한다

**접히면 제목 줄의 아래 여백을 채운다.** 펼쳐져 있을 때 아래가 `0` 인 것은 본문이 자기 여백을
갖고 있어 두 겹이 되는 것을 막으려는 것인데, 접히면 그 본문이 없다. 그대로 두면 위 16px /
아래 0px 이라 글자가 위로 붙어 보인다 — Storybook 에서 사용자가 잡았다.

`.tx-card__body` 는 `display: flex` 라서 **`hidden` 속성만으로는 안 감춰진다** —
그 선언이 이긴다. CSS 에 `[hidden] { display: none }` 을 함께 둔다. 계약 테스트가 지킨다.

#### `TxTabs` — `role="tablist"` 만 있고 규약이 없었다

원본 51줄. 겉으로는 접근성이 있는 것처럼 보였지만 **탭 규약을 하나도 지키지 않았다.**

- **화살표 키로 옮길 수 없었다.** `role="tablist"` 를 달면 따라와야 하는 규약이다
- **roving tabindex 가 없었다.** 탭마다 탭 순서에 들어가서 **열 개면 Tab 을 열 번** 눌러야 지나갔다
- **`aria-selected` 가 없었다.** 어느 것이 골라졌는지 스크린리더가 몰랐다
- **패널과 이어지지 않았다.** `role="tabpanel"` 도 `aria-controls`↔`aria-labelledby` 도 없었다

지금은 넷 다 채웠다. 화살표는 **옮기는 즉시 전환**하고(WAI-ARIA 가 본문이 가벼울 때 권하는 방식),
비활성 탭은 건너뛰며, 양 끝에서 감긴다. `Home`·`End` 도 받는다.

##### 항목이 요소를 갖는다

원본은 본문을 `renderBody` 로만 받았다. `tabData` 라는 prop 이 타입에 있고 JSDoc 에
"body 데이터 배열" 설명까지 붙어 있었지만 **구현이 꺼내 쓰지 않는 죽은 prop** 이었다
(`TxAgGrid` 의 `colWidths` 와 같은 종류다).

```tsx
<TxTabs
  tabs={[
    { label: "정보", content: <UserInfo /> },
    {
      label: (
        <span>
          신규 <Badge>3</Badge>
        </span>
      ),
      content: <NewList />
    },
    { label: "보관", content: <Archive />, disabled: true }
  ]}
/>
```

`renderHead` · `renderBody` 는 잘랐다. `label` 이 `ReactNode` 라 배지·아이콘이 그대로
들어가고 `content` 가 본문을 받으니 할 일이 없다. 특히 **`renderHead` 는 주는 순간
`role="tab"` 과 키보드 규약이 통째로 사라져** 접근성을 소비자에게 떠넘기고 있었다.

**`content` 를 하나도 안 주면 패널을 그리지 않는다.** 앱의 사이드바가 탭을 전환 스위치로만
쓰는데, 그 쓰임을 그대로 살렸다.

##### 그 밖에 고친 것

- **controlled 인데 값을 내부 state 로 복사**하고 effect 로 맞췄다. 소비자가 `onChange` 를
  받고 값을 안 바꿔도 화면이 멋대로 넘어갔다 — `TxCheckBox`·`TxDayPicker` 와 같은 결함이다
- **`ref.changeTab()` 이 `onChange` 를 안 불렀다.** 클릭 경로와 다르게 동작해서 ref 로 바꾸면
  소비자는 바뀐 것을 몰랐다. 명령형 핸들 자체를 걷어냈다 — `value`/`onChange` 로 충분하다
- `useState(value || 0)` — `0` 이 falsy 라 우연히만 맞았다
- JSDoc 이 `tabs` 를 "문자열 배열" 이라고 적어 두었는데 실제 타입은 `ReactNode[]` 였다

##### 탭 줄에 세로 스크롤이 생기고 있었다

Storybook 에서 잡혔다. **`overflow-x` 를 주면 CSS 규칙상 세로도 `auto` 가 된다.**
거기에 탭의 `margin-bottom: -1px`(밑줄을 줄의 테두리에 겹치려던 것)이 1px 을 넘겨서
탭 줄에 **세로 스크롤바**가 생겼다.

회색 밑줄을 테두리가 아니라 **안쪽 그림자**(`box-shadow: inset`)로 그려 넘침 자체를 없앴다 —
안쪽 그림자는 자식보다 아래에 칠해지므로 골라진 탭의 밑줄이 자리를 다투지 않고 그대로 덮는다.

가로 스크롤바도 감췄다. 밑줄이 1px 인데 그 자리에 스크롤바가 앉으면 굵은 회색 막대가 밑줄을
가린다. 감춰도 다루는 길은 남는다 — ←→ 로 옮기면 브라우저가 포커스를 따라 줄을 밀어 준다
(마지막 탭까지 가면 `scrollLeft` 가 실제로 움직이는 것을 확인했다).

**골라진 탭을 클래스가 아니라 `[aria-selected="true"]` 로 칠한다.** 화면에 보이는 것과
스크린리더가 듣는 것이 같은 근거에서 나와야 둘이 어긋나지 않는다. CSS 계약 테스트가 이걸 지킨다.

#### `TxDialog` — 신규. `alert` · `confirm` 을 대신한다

원본에 없다. **앱이 네이티브 `alert` 을 15곳, `confirm` 을 5곳에서 쓰고 있어서** 만들었다.
`TxModal` 이 막 끝난 참이라 그 위에 얹는 값이 쌌다.

```tsx
await TxDialog.alert("처리할 수 없습니다.");
if (await TxDialog.confirm("로그아웃 하시겠습니까?")) signOut();
```

**바뀌는 것은 하나, `await` 다.** 브라우저에서 자바스크립트를 멈춰 세울 방법이 없다.
`if (!confirm(…)) return` 은 `if (!(await …)) return` 이 된다.

##### 훅이 아니라 함수인 이유

React 다운 방식은 Provider + 훅이지만, 앱의 `alert` 하나가 **`core/extensions.ts` 안**에 있다.
axios 인터셉터에서 "세션이 만료됐습니다" 를 띄우는 자리도 마찬가지다 — **컴포넌트가 아닌 곳에서는
훅을 쓸 수 없다.** 그래서 어디서든 import 해서 부르는 형태로 만들고, 처음 부르는 순간
자기 React 루트를 만들어 띄운다.

**이게 가능한 것은 겉모습이 전부 `:root` 의 토큰이기 때문이다.** 별도 루트에 띄워도 테마가
그대로 따라온다 — ThemeProvider 를 요구하는 라이브러리였다면 못 했을 방식이다.

이름이 `TxDialog` 하나인 것도 이유가 있다. 배럴 테스트가 **모든 공개 이름이 `Tx` 로 시작할 것**을
강제하므로 `txAlert` 같은 이름은 쓸 수 없다.

##### 정한 것들

- **줄 세운다.** 셋을 한 번에 불러도 겹쳐 뜨지 않고 차례로 뜬다 — 사람은 한 번에 하나만 답한다
- **바깥을 눌러도 닫히지 않는다.** 네이티브가 그렇듯 답하기 전에는 안 닫힌다 —
  `confirm` 에서 바깥을 잘못 누르면 조용히 "취소를 골랐다" 가 되어 버린다. 그건 답이 아니다.
  바깥 클릭으로 닫히는 창이 필요하면 그건 `TxModal` 의 일이다
- **취소 · Escape 가 `false`** 다. 네이티브 `confirm` 과 같다
- **오른쪽 위 X 가 없다.** 취소 버튼과 뜻이 같은 길이 둘이면 답이 둘로 보인다.
  `TxModal` 에 `hideCloseButton` 을 더해 껐다 — **확인·취소가 답을 받는 창**에만 쓰는 옵션이다
- **줄바꿈(`\n`)을 그대로 보인다.** 앱의 문구에 실제로 들어 있어서, 한 줄로 뭉치면 옮겨 온 문구가 망가진다
- `tone: "danger"` 로 확인 버튼을 붉게 한다. 되돌릴 수 없는 동작을 알리는 자리다
- 문구는 `TxDialog.configure({ labels })` 로 앱 전체를 한 번에 바꾼다
- **import 만으로 DOM 을 건드리지 않는다.** 안 쓰는 소비자에게 빈 요소를 남기지 않고,
  서버에서 import 해도 안전하다

#### `TxAgGrid` — 완료. 쪽 번호를 갈라냈다

원본 673줄에서 **죽은 prop 둘**과 **경계 위반 넷**이 나왔다.

`colWidths` 는 **선언만 있고 읽는 코드가 없었다.** 그런데 앱이 실제로
`colWidths: [4, 20, 42, 10, 14, 6, 13]` 을 넘기고 있었다 — 소비자는 폭이 먹는다고 믿는 중이었다.
쓸 일이 없다고 확인받아 지웠다. `data?: TData` 도 같은 상태였는데 이쪽은 더 나빴다 —
구조분해에 없어서 `{...props}` 를 타고 `<AgGridReact data={…}>` 로 흘러갔다.

##### 쪽 번호는 그리드의 것이 아니다

원본은 페이지네이션을 `TxAgGrid` 안에 묶고 **ag-grid 내부 클래스(`ag-paging-panel`)** 로
껍데기를 그렸다. 그쪽이 이름을 바꾸면 조용히 깨진다.

`TxPagination` 으로 갈라 **루트 배럴**에 뒀다 — 카드 목록이나 손수 짠 표에도 쓰이는데
`ag-grid` 서브패스에 숨기면 그걸 쓰려고 ag-grid 를 설치해야 한다.

**`10000` 매직넘버도 함께 걷어냈다.** 페이지 수 상한이 `Math.floor(10000 / pageSize)` 로
박혀 있었는데, 그 1만은 검색엔진이 돌려주는 결과 창의 한계다. 백엔드 사정을 UI 컴포넌트가
알고 있었던 것이다. 이제 `maxPage` 로 소비자가 준다.

버튼도 되살렸다. 원본은 페이지 버튼마다 Tailwind 클래스 덩어리를 발라 `TxButton` 의 색·상태를
통째로 덮었다 — `--tx-color-primary` 를 바꿔도 페이지 번호만 안 따라왔다. 지금은 `variant` 만 준다.

##### 순번 열이 행 데이터를 건드리고 있었다

원본은 행마다 객체를 복사해 `#` 키를 심었다. 소비자가 준 객체에 없던 필드가 생기고,
매번 새 객체라 `getRowId` 없이 쓰면 그리드가 행을 처음부터 다시 만든다.
`valueGetter` 로 행 위치에서 계산하도록 바꿨다.

**그런데 그것만으로는 부족했다 — Storybook 에서 잡혔다.** `offset` 을 클로저로 잡았더니
3쪽으로 넘겨도 순번이 1부터 다시 시작했다. 그리드가 들고 있던 옛 함수가 그대로 불린 것이다.
값을 그리드 `context` 에서 읽도록 바꾸고, `offset` 이 바뀌면 그 열만 다시 그린다.
**같은 열 정의가 새 `offset` 을 따라오는지**를 테스트가 지킨다.

##### 테마 enum 은 ag-grid 를 되파는 것이었다

`AGGrid_Theme_TYPE` enum 이 하는 일은 ag-grid 가 이미 내보내는 테마를 우리 이름으로 다시
파는 것뿐이었다. 그래서 소비자는 `withPart` 조합을 만들 수 없었고, 앱은 자기 `constants.enum.ts` 에
**같은 enum 을 또** 만들어 두고 있었다. 없애고 `TxAgGridProvider` 가 **Theme 객체를 그대로** 받는다.

**표 안쪽의 겉모습은 ag-grid 의 테마가 소유한다.** 우리 CSS 는 바깥 틀과 우리가 얹은 것
(순번 열·편집 표시)만 맡는다 — 같은 것을 두 곳이 정하면 어긋난다. 그래서 **다크모드도
ag-grid 테마가 정한다**: `--tx-*` 를 뒤집어도 표 안쪽은 따라오지 않으므로, 앱의 테마 상태를
Provider 에 물려야 한다. CSS 계약 테스트가 `.ag-*` 선택자를 쓰면 실패한다.

##### 그 밖에 고친 것

- `className` 기본값이 Tailwind 문자열(`"flex flex-1 min-h-0 flex-col"`)이라 소비자가
  `className` 을 주면 **레이아웃이 교체되어 그리드가 높이를 잃었다.** 높이를 CSS 가 소유한다
- default export → named (배럴의 `export *` 가 default 를 못 실어 서브패스가 따로 받아내고 있었다)
- 주석 처리된 `console.log` 블록과 deps 배열 안의 주석을 걷어냈다
- `TxAgGridIconEdit` 은 아이콘이 아니라 헤더 렌더러였다 → `TxAgGridHeader`, 내부 전용

#### `TxDropMenu` · `TxContextMenu` — 공개는 둘, 속은 하나다

**앞서 "서로 다른 것" 이라고 적었고 그 판단은 맞았다.** 다만 다른 것이 무엇인지 세어 보니
**둘뿐이었다** — 여는 방법(왼쪽 클릭·hover / 오른쪽 클릭)과 뜨는 자리(앵커 아래 / 마우스 좌표).
항목 그리기 · 화살표 이동 · 포커스 · 닫기는 글자 하나까지 같다.

그래서 **`TxMenuShell` 이라는 내부 부품 하나에 그 전부를 두고, 공개는 둘 그대로 둔다.**
`TxDropdownShell` 이 `TxDropdown` 과 `TxDropdownMulti` 에 하는 일과 같은 구조다.

- **하나로 합치지 않은 이유** — 소비자가 쓰는 자리는 정말로 둘이다. `<TxMenu trigger="context">`
  같은 것은 이름이 하는 일을 말해 주지 않는다. **부르는 이름으로 무엇이 뜰지 알아야 한다.**
- **둘로 두되 속을 나누지 않은 이유** — 접근성(메뉴 규약)은 한 번만 만드는 것이 옳다.
  둘로 두면 한쪽만 고쳐지고 다른 쪽은 남는다. 원본이 정확히 그랬다.
- `TxDropMenu.Item` 과 `TxContextMenu.Item` 은 **이름만 둘이고 같은 부품**이다.

##### `children` 은 손대는 대상, `menu` 는 떠오르는 것

메뉴 계열의 API 를 정하면서 **`TxTooltip` 의 `tip` 과 같은 규칙으로 맞췄다.**
`children` 에는 누르거나 오른쪽 버튼을 댈 것이 오고, 뜨는 내용은 prop 으로 준다.

```tsx
<TxTooltip tip="설명">     <button>버튼</button>       </TxTooltip>
<TxDropMenu menu={<…/>}>   👤 {username}                </TxDropMenu>
<TxContextMenu menu={<…/>}><TxAgGrid … />               </TxContextMenu>
```

셋이 같은 모양이라 하나를 익히면 나머지가 따라온다. `menu` · `children` 을 컴포넌트마다
다르게 두면 소비자는 매번 문서를 다시 본다.

##### 라우터 주입 — 계획대로 마지막 두 곳이었다

원본 둘은 `react-router-dom` 의 `NavLink` 를 직접 import 했다. **줄은 기본이 `<button>` 이고
링크는 `as` 로 갈아끼운다** — `as={NavLink}` · `as={Link}` · `as="a"`. peer 가 늘지 않고
Next.js·TanStack Router 소비자도 그대로 쓴다. (`TxCard` 는 링크를 아예 잘라서 주입이
필요 없어졌으므로, 3차에서 계획한 링크 주입은 이 둘로 끝났다.)

##### 원본에 없던 것 — 메뉴 규약 전부

원본 둘에는 `role="menu"` 도, 화살표 이동도, 포커스 관리도 없었다. 그냥 `<div>` 가 뜨고
마우스로만 눌렀다. **키보드만 쓰는 사람에게는 없는 기능이었다.**

- 열면 첫 줄로 포커스가 들어가고, 닫으면 **트리거로 돌아온다.** 안 돌리면 포커스가 `<body>` 로
  떨어져 처음부터 Tab 을 다시 눌러야 한다
- ↑↓ 로 옮기고 양 끝에서 감긴다. Home · End 로 양 끝
- 줄은 `tabIndex={-1}` 이다. **줄마다 탭 정거장을 만들면 열 줄짜리 메뉴에 Tab 이 열 번이다**
- 메뉴 안에서 Tab 은 빠져나가는 것이 아니라 **닫는 것**이다 (메뉴 규약)
- `TxDropMenu` 는 ↓ 로도 열린다

**포커스를 옮기는 일은 `TxMenuShell` 이 갖고 `TxPopup` 은 그대로 두었다.** `TxPopup` 이 옮기면
드롭다운·콤보박스에서 타이핑이 끊긴다 — 목록형 위젯은 포커스를 앵커에 두는 것이 표준이다.

##### 팝업 안에서 팝업이 열리면 서로를 "바깥" 으로 봤다

메뉴 안에 테마 드롭다운을 하나 놓자마자 드러난 결함이다. 안쪽 목록은 `document.body` 로
포털되므로 **바깥 메뉴가 보기에 자기 밖이다.** 값을 고르는 순간 메뉴가 닫혀서
그 조합을 아예 쓸 수 없었고, Escape 한 번에 둘이 함께 닫혔다.

`TxPopup` 이 **열려 있는 팝업을 순서대로 쌓아 두고**, 두 가지를 가린다.

- 바깥 클릭 — **나보다 나중에 열린 팝업 안이면 바깥이 아니다**
- Escape — **맨 위의 것만 닫는다.** 겹쳐 있으면 위에서부터 하나씩 걷힌다

원본에도 있던 결함이지만 원본 메뉴에는 애초에 그런 조합이 없어 드러나지 않았다.
`TxDropdown` · `TxCombobox` · `TxDayPicker` · `TxTooltip` 도 같은 바탕이므로 함께 고쳐졌다.

##### 화살표는 항목이 아닌 컨트롤에도 닿는다

메뉴 안에 드롭다운을 놓았을 때 화살표가 그것을 건너뛰면 **키보드로는 닿을 길이 없다** —
메뉴 안에서 Tab 은 닫는 키이기 때문이다. 그래서 이동 대상에 `[role="combobox"]` 를 넣었다.

##### 그 밖에 고친 것

- **`z-index` 를 각자 박아 두었다.** 쌓임 순서는 `TxPopup` 의 `--tx-popup-z` 하나가 정한다
- 두 메뉴가 각자 클래스를 갖지 않는다 — 겉모습도 `.tx-menu__*` 하나다
- hover 로 여는 메뉴도 **눌러서 열린다.** 터치에는 hover 가 없다
- 오른쪽 버튼 메뉴는 브라우저 기본 메뉴를 막는다. 안 막으면 그 위에 겹쳐 뜬다

#### `TxSlidePanel` — `TxModal` 과 다른 것은 뜨는 자리 하나뿐이다

원본은 `role="dialog" aria-modal="true"` 를 손으로 달고 `framer-motion` 으로 밀었다.
**`TxModal` 에서 이미 답이 나온 문제들이라 `<dialog>` 로 옮기자 한꺼번에 사라졌다** —
포커스 트랩 · 닫을 때 포커스 되돌리기 · 배경 비활성화 · top layer 를 브라우저가 맡는다.
`lockPageScroll` 은 두 컴포넌트가 함께 쓰므로 `tx-ui.utils` 로 옮겼다.

##### `aria-modal="true"` 인데 갇히지 않았다

가장 큰 결함이다. **갇혔다고 알려 놓고 Tab 으로 뒤 화면에 나갔다.** 스크린리더는
"이 밖은 없는 셈 치라" 고 듣고 실제로는 밖으로 나가니, 아무 안내도 없는 것보다 나쁘다.
`showOverlay={false}` 일 때도 `true` 라서 그때는 아예 거짓말이었다.

##### `top` · `bottom` 이 화면을 통째로 덮고 있었다

`panelClassName` 의 기본값이 `"w-80 h-screen"` 이었다. 위아래 방향은 `positions` 가
`w-screen` 을 얹는데 기본값의 `h-screen` 은 그대로 남아, **위에서 내려오는 서랍이
전체 화면이 됐다.** 크기 손잡이를 하나로 합쳐 없앤 결함이다.

##### 크기 손잡이는 `--tx-slide-panel-size` 하나다 (합의)

**좌우면 폭, 위아래면 높이**를 뜻한다. 방향마다 다른 prop 을 외울 것이 없고,
Tailwind 를 안 쓰는 소비자도 크기를 갖는다. 원본은 기본값이 Tailwind 클래스여서
**Tailwind 없는 프로젝트에서는 크기가 아예 없었다** — 범용 라이브러리가 할 일이 아니다.

##### 비모달 모드는 잘랐다 (합의)

원본의 `showOverlay={false}` 는 "뒤 화면을 계속 조작하는 서랍" 이었다. 앱 사용 0회였고,
그 모드에서도 `aria-modal="true"` 를 달고 있어 **애초에 뜻대로 동작하지 않았다.**
`<dialog>` 의 `show()` 로 되살릴 수는 있지만 그러면 포커스 트랩이 없고 top layer 밖이라
z-index 층이 하나 더 는다 — **한 컴포넌트가 두 동작을 갖는다.** 요구가 생기면 그때 판단한다.

##### `<dialog>` 의 UA 스타일과 겹쳐 자리가 어긋났다 (이식하며 낸 결함)

`right` · `bottom` 서랍이 **화면 가운데쯤에서 밀려 나왔다.** UA 스타일은 `dialog` 에
`left: 0; right: 0` 을, 모달에는 `top: 0; bottom: 0` 까지 준다 — 가운데 놓으려고 그런 것이다.
붙일 변만 얹으면 반대쪽 UA 값이 살아남아 **폭·높이와 함께 과잉 제약**이 되고, 브라우저는
둘 중 하나를 버린다(LTR 에서는 `right`, 세로로는 `bottom`). 그래서 패널이 반대쪽 끝에
자리 잡고, `translate` 가 그것을 화면 안쪽으로 옮겨 놓았다.

`left` · `top` 은 UA 가 이미 주던 값과 같아서 멀쩡했다 — **절반만 맞아서 안 보이던 종류다.**
이제 네 방향이 붙는 변과 **반대쪽 변(`auto`)을 함께** 정한다. 물리 속성으로 양쪽을 다
정하므로 RTL 에서도 UA 의 논리 속성이 새어 들어오지 않는다.

##### 그 밖에 고친 것

- **Escape 가 `window` 리스너였다.** 패널이 둘 겹치면 한 번에 둘 다 닫혔다. 이제
  포커스가 패널 안에 갇히므로 `keydown` 은 맨 위의 것에만 올라온다
- **오버레이가 화면을 덮는 `<button aria-label="Close panel">`** 이었다. 탭 순서에 잡히고,
  `closeOnBackdrop={false}` 면 아무 일도 안 하는 버튼이 화면을 덮었다. 문구도 영어 하드코딩이라
  소비자가 못 바꿨다. `::backdrop` 이 대신한다
- **닫기 X 가 `<svg onClick>`** 이었다 — 키보드로 못 닫고 버튼으로 읽히지 않았다 (`TxModal` 과 같은 결함)
- `role="dialog"` 가 오버레이를 자식으로 품은 바깥 `<aside>` 에 붙어 있었고 `title` 과 이어지지 않았다
- `lockScroll` 이 각자 `body.style.overflow` 를 저장·복원해서 **둘이 겹치면 어긋났다.**
  세어 두는 방식으로 바꿨다 (`prop` 도 없앴다 — 화면을 덮는 층이 배경을 흘리게 둘 이유가 없다)
- 패널의 `onClick={(e) => e.stopPropagation()}` — 받을 부모가 없는 죽은 코드였다. 게다가
  실제로 걸려 있었다면 소비자의 부모 클릭 핸들러까지 죽인다
- `showCloseButton` → `hideCloseButton` (`TxModal` 과 이름을 맞췄다)
- `ITxSlidePanel` · `TTxSlidePanelSide` → `TxSlidePanelProps` · `TxSlidePanelSide`
- **`prefers-reduced-motion` 을 지킨다.** 원본은 늘 밀었다

#### `TxDropMenu` — `children` 은 버튼 안의 내용이다

스토리를 브라우저에서 보다 콘솔이 잡아 준 것이다. 트리거를 감싸는 것이 이미 `<button>` 이라
`children` 에 버튼을 넣으면 **`<button>` 안의 `<button>`** 이 된다. 타입으로는 못 막으므로
prop 설명에 적었다. (스토리 하나가 그러고 있어서 함께 고쳤다.)

#### `TxJsonTree` — 옮긴 것이 아니라 목적에서 다시 짰다

**만든 이유부터 다시 확인하고 시작했다.** 흔한 뷰어들은 기능이 너무 많거나 너무 적어서
맞는 것이 없었고, 정작 필요한 것은 셋이었다 — **보기 · 고치기 · 값 변화 지켜보기.**
셋째는 원본에 아예 없었고, 그것이 이 컴포넌트를 따로 두는 이유이기도 하다.

##### 고치는 일을 라이브러리가 맡는다 (합의)

`onChange(next, change)` 가 **바뀐 것이 반영된 새 객체 전체**를 준다. 원본은
`onEdit(path, next, prev)` 로 경로만 알려 줘서, 소비자가 `["profile","address","city"]`
같은 경로를 타고 들어가 불변으로 갱신하는 코드를 **매번 다시 썼다.** 지나온 길만 복사하므로
손대지 않은 가지는 참조가 유지된다.

##### 값 변화 지켜보기 — `watch` (신규)

`data` 가 밖에서 바뀌면 이전 값과 견주어 **달라진 줄만 잠깐 반짝인다.** 폴링하는 응답처럼
계속 흘러 들어오는 값에서 무엇이 움직였는지가 눈에 든다. 사라진 줄은 짚지 않는다 —
반짝일 자리가 이미 없다.

반짝임은 **줄마다 새로 만들어지는 요소**다. 같은 줄이 잇달아 바뀌어도 애니메이션이 처음부터
다시 돌아야 하는데, 클래스나 속성만 갈아 끼우면 CSS 애니메이션은 다시 시작하지 않는다.

##### 원본의 결함

- **편집이 타입을 잃었다.** `<input>` 이 준 문자열이 그대로 나가서 `42` 가 `"42"` 가 됐다.
  이제 편집 칸이 `[타입][값]` 한 벌이고 **타입 칸은 지금 타입에서 시작한다** — 값만 고치면
  원래 타입이 지켜지고, 필요할 때만 바꾼다. `null` 을 다른 값으로 채울 길도 이것으로 생겼다
  (원본은 `null` 자리에 문자열밖에 못 넣었다)
- **키 추가가 네이티브 `prompt()` 였다.** 샌드박스 iframe 에서 막히고 번역도 안 된다 —
  `alert`·`confirm` 을 `TxDialog` 로 바꾼 것과 같은 문제다. 이제 줄 안에서 받는다
- **펼침·편집 상태를 노드마다 `useState` 로 들고 있었다.** 배열 항목의 React key 가
  인덱스라, 한 줄을 지우면 **상태가 그 자리에 남아 다른 줄의 것이 됐다.** 펼침은 루트가
  경로(`pathKey`)로 들고 있게 바꿨다
- **`onEdit` 하나가 편집과 삭제 버튼을 함께 켰다.** 삭제만 열 수 없었다. 이제 `onChange`
  하나가 편집 전체를 켜고, 안 주면 읽기 전용이다
- 배열의 `+ add` 는 `onAdd` 없이도 보였다 — 눌러도 아무 일이 없었다
- `data` 가 밖에서 바뀌어도 편집 칸은 옛 값을 들고 있었다 (초기화 함수에 한 번 갇혔다)
- 펼침 버튼이 `+`/`-` 글자뿐이라 이름도 `aria-expanded` 도 없었고, 키와 값은 `<span onClick>`
  이라 키보드로 닿지 않았다
- `ml-4` · `flex` · `space-x-1` 이 테마도 아니고 **컴포넌트에 박혀** 있었다
- 타입이 `JsonLike` · `JsonLikeObject` · `JsonObject` · `JsonArray` · `EditableValue` 로
  다섯 벌인데 대부분 안 쓰이고 서로 맞지 않았다

##### `role="tree"` 를 쓰지 않는다 (판단)

그 역할은 화살표 이동과 roving tabindex 까지 갖춘 위젯을 뜻한다. **이름만 달고 규약이
없으면 스크린리더 사용자에게 거짓**이 된다 — `TxSlidePanel` 원본의 `aria-modal` 과 같은
종류의 잘못이다. 중첩 목록과 진짜 펼침 버튼으로 짜면 Tab 만으로 전부 닿고 아무것도 속이지 않는다.

##### 타입 색에 새 전역 토큰을 만들지 않는다 (판단)

값의 타입마다 색이 다른 것은 이 컴포넌트의 핵심이지만, 그렇다고 `--tx-color-success`
같은 전역색을 새로 만들면 **소비자가 브랜드색을 덮을 때 챙길 것이 늘어난다.**
기존 전역 토큰에서 끌어오고(숫자=primary, 참거짓=warning, null=흐린 본문색),
문자열은 따옴표가 이미 구분해 주므로 본문 색 그대로 둔다. 컴포넌트 토큰으로 각각 덮을 수 있다.

##### 반짝임이 안 보이고 있었다 (이식하며 낸 결함)

`z-index: -1` 로 글자 뒤에 깔았는데 **아무것도 보이지 않았다.** 줄이 `position: relative`
만 갖고 있어 쌓임 맥락이 생기지 않았고, 그래서 `-1` 이 줄 뒤가 아니라 **페이지 배경 뒤까지**
내려갔다. 줄에 `isolation: isolate` 를 주어 그 `-1` 을 줄 안에 가둔다. 둘은 반드시 짝이라
테스트가 그 짝을 지킨다.

  "높이·정렬·테두리를 잡아 준다" 고 적혀 있었지만 **테마에 그런 것이 없다.**
- **`TxClipboardButton`**(4) — `<div onClick>{📋}</div>` 다. 버튼이 아니라서 키보드로 못 누르고

`TxCoolTable`(1024)과 `TxTheme`(29)은 앞서 제외 확정했다. 그래서 **26개 중 23개를 이식했다.**

#### 외부 의존 둘을 걷어낸다 — 결정됨

옛 패키지의 peer 에는 `framer-motion` 과 `react-router-dom` 이 있었다. **지금은 없고, 늘리지 않는다.**

- **`framer-motion`**(`TxModal` · `TxSlidePanel` · `TxLayout`) → **CSS transition 으로 옮긴다.**
  여닫히는 페이드·슬라이드에 애니메이션 라이브러리가 필요하지 않다. `dayjs` 를 걷어낸 것과 같은 판단이다.
- **`react-router-dom`**(`TxCard` · `TxDropMenu` · `TxContextMenu`) → **링크 컴포넌트를 주입받는다.**
  기본은 `<a>` 다. 이대로 옮기면 루트 배럴이 라우터를 끌어와 Next.js·TanStack Router 소비자가
  이 패키지를 못 쓴다. 주입이면 peer 가 늘지 않고 어느 라우터든 붙는다.

#### 메뉴 2종은 서로 다른 것이다

앞서 "역할 겹침" 으로 분류했는데 **틀렸다.** 트리거도 위치 계산도 다르다.

- **`TxDropMenu`** — GNB 에서 유저네임 같은 걸 누르면 **아래로 펼쳐지는** 메뉴
- **`TxContextMenu`** — 특정 태그에서 **마우스 오른쪽**을 누르면 나오는 메뉴 창

겹치는 건 공개 API 가 아니라 **내부 구현**이다 — 둘 다 `createPortal` · 뷰포트 클램핑 ·
바깥 클릭 닫기를 각자 들고 있다. **그 셋은 이제 `TxPopup` 이 갖고 있다.** 남는 차이가
무엇인지는 둘 다 올린 뒤에 본다. 지금 합치면 아직 모르는 차이를 추상화로 덮게 된다.

**결론(둘 다 올린 뒤): 공개는 둘, 속은 하나다.** 아래 `TxDropMenu` · `TxContextMenu` 항목을 본다.

### 4차 — 사이트 화면용 (이식이 아니라 신규)

**여기서부터는 옮기는 것이 아니다.** 3차까지로 원본 26개 중 24개가 왔고, 그 결과 지금
목록은 **업무 화면 쪽으로 쏠려 있다** — 폼 10개 · 그리드 · 드롭다운 · 모달 · 메뉴.
사이트 화면(마케팅·서비스 페이지)이 필요로 하는 것 중 있는 건 `TxCard` · `TxTabs` ·
`TxTooltip` 정도다.

고르는 기준은 셋이다 — **흔한가 · 직접 짜면 틀리기 쉬운가 · 도메인이 안 붙는가.**

#### `TxAlert` — 네 갈래의 기준이 된다

신규다. 옮길 원본이 없으므로 **결함 목록 대신 정한 것을 적는다.**

##### 갈래는 색 하나만 갈린다

`--tx-alert-accent` 를 갈래가 정하고 **바탕 · 테두리 · 아이콘 색이 전부 거기서 섞여 나온다**
(`color-mix`). 그래서 갈래를 늘리거나 소비자가 색을 바꿀 때 손댈 곳이 한 군데고,
다크모드도 토큰이 뒤집히면 저절로 따라온다. 테스트가 이 규칙을 지킨다 —
갈래 규칙 안에 선언이 둘 이상이면 깨진다.

##### 색만으로 뜻을 전하지 않는다

갈래는 **색 · 아이콘 · 글자 셋으로** 알린다. 색만 쓰면 색을 못 보는 사람과 스크린리더에
아무것도 남지 않는다 (WCAG 1.4.1). 화면에는 안 보이는 `안내:` · `완료:` · `주의:` ·
`오류:` 가 상자 앞에 실린다. **`display: none` 이 아니라 `clip-path` 로 감춘다** —
전자는 스크린리더에서도 사라져서 감추는 뜻이 없어진다. 이것도 테스트가 지킨다.

##### 라이브 리전은 기본이 꺼져 있다 (판단)

`role="alert"` 을 늘 달면 **페이지에 처음부터 있던 안내까지 읽어 주어 읽는 흐름을 끊는다.**
그래서 `announce` 를 두고 기본을 끔으로 했다 — 저장 결과처럼 동작에 대한 답으로 새로
나타나는 알림에만 켠다. 켜면 `danger` 는 `role="alert"`(즉시), 나머지는 `role="status"`
(하던 말 뒤)로 갈린다. 이 갈림은 `TxToast` 가 그대로 물려받는다.

##### 아이콘을 `TxIcons` 에 넣지 않았다 (판단)

갈래마다 붙는 아이콘 네 개는 `TxAlert` 안에 둔다. **`TxIcons` 에 이름을 더하는 것은
공개 API 를 늘리는 일**이라 따로 정할 문제다. `TxToast` 는 같은 어휘를 쓰므로 여기서
가져다 쓴다. (`TxDropdown` 의 화살표, `TxJsonTree` 의 펼침표가 같은 선례다.)

##### `title` 이 `HTMLAttributes` 와 부딪힌다

`title` 은 DOM 속성이라 `string` 만 받는데 우리는 `ReactNode` 를 받는다. `Omit` 으로
가려냈다 — `TxModal` 이 이미 같은 자리를 지나갔다.

#### `TxToast` — `TxAlert` 의 겉에 `TxDialog` 의 구조

신규다. **겉은 `TxAlert` 이 그리고, React 바깥에서 부르는 구조는 `TxDialog` 에서 가져왔다** —
모듈을 import 한 것만으로 DOM 을 건드리지 않고 처음 부를 때 `createRoot` 를 만드는 것,
상태를 컴포넌트 밖에 두고 `useSyncExternalStore` 로 보는 것이 그대로다.

**`TxDialog` 와 다르게 둔 것은 셋이다.** 확인창은 답을 받으므로 한 번에 하나씩 차례로 뜨지만,
알림은 답을 받지 않으므로 **여럿이 함께 쌓인다.** 그리고 **스스로 사라지고, 그 시계를
멈출 수 있어야 한다.**

##### 모달 위에 떠야 한다 — 그래서 `popover`

`TxModal` · `TxSlidePanel` 은 네이티브 `<dialog>` 라 **top layer** 에 올라간다. 거기는
`z-index` 로 닿을 수 없어서, 보통의 토스트는 **모달이 열려 있는 동안 뒤에 가려 보이지 않는다.**
저장 실패를 모달 안에서 알리는데 그게 안 보이면 알림이 아니다.

`popover` 도 같은 top layer 를 쓴다. 그래서 통을 `popover="manual"` 로 열어 둔다 —
`auto` 가 아닌 이유는 **바깥을 눌렀다고 알림이 사라지면 안 되기** 때문이다.

**통은 클릭을 받지 않는다.** top layer 에 있는 통이 화면을 덮으면 그 아래가 통째로 안 눌린다.
받는 것은 알림 하나하나다.

##### 속성만 달고 API 가 없으면 영영 안 보인다

`popover` 를 **아는 브라우저에서만 속성을 단다.** 속성만 달려 있고 API 가 없으면 UA 스타일이
통을 `display: none` 으로 숨겨 두는데 열 방법이 없다. **jsdom 이 정확히 그 상태였고**,
테스트가 전부 "요소는 있는데 role 로 못 찾겠다" 로 깨지면서 드러났다.

CSS 도 짝을 맞춘다 — 통을 그냥 `display: flex` 로 두면 작성자 스타일이 UA 의
`[popover] { display: none }` 을 이겨서 **빈 통이 늘 top layer 에 남는다.** 그래서
`속성이 있을 때만` 숨긴다.

##### 시계를 멈출 수 있어야 한다

읽는 데 걸리는 시간은 사람마다 다르다. 시간이 정해진 것을 늘리거나 끌 길이 없으면 못 읽고
놓친다 (WCAG 2.2.1). 마우스를 얹거나 **키보드로 안에 들어오면** 멈춘다 — 마우스만 보면
키보드 사용자는 멈출 방법이 없다. 다시 갈 때는 **남은 시간만** 센다. 처음부터 다시 세면
잠깐 스쳐도 시계가 되감겨 영영 안 사라진다.

`duration: 0` 은 스스로 사라지지 않는다. 놓치면 안 되는 오류가 그 자리다.

##### 여기서도 UA 의 `inset` 이 살아남고 있었다 (이식하며 낸 결함)

**오른쪽 위에 띄우라고 했는데 왼쪽 위에 떴다.** `[popover]` 의 UA 스타일이 `inset: 0` 을
주는데 `right` 만 얹어서, 폭과 함께 **과잉 제약**이 됐다. `TxSlidePanel` 에서 `<dialog>` 로
똑같이 겪은 것을 **알고도 다시 밟았다** — top layer 에 올라가는 것들은 UA 가 가운데 놓으려고
네 변을 다 잡아 둔다는 것이 공통점이다. 이제 양쪽 다 반대편 변을 `auto` 로 놓고,
테스트가 그 짝을 지킨다.

#### `TxCollapsible` — 접힌 글도 ⌘F 로 찾힌다

신규다. **네이티브 `<details>` 위에 올렸다.** `TxModal` 을 `<dialog>` 로 옮긴 것과 같은
판단이다 — 여닫기 · 키보드 · 스크린리더가 상태를 읽는 것까지는 손으로도 짤 수 있지만,
**접힌 내용을 찾아 주는 페이지 내 검색(⌘F)은 브라우저만 할 수 있다.** 접힌 글이 검색에
안 걸리면 FAQ 나 약관에서는 없는 글이나 마찬가지다.

##### `<details>` 는 원래 움직이지 않는다

열리는 순간 내용이 `display` 로 나타났다 사라지므로 사이 값이 없다. `::details-content` 가
그 내용을 가리킬 수 있게 해 주고 `interpolate-size: allow-keywords` 가 `auto` 높이를
오갈 수 있게 해 준다. **아는 브라우저에서만 움직이고 모르는 쪽에서는 즉시 열린다** —
기능이 빠지는 것이지 깨지는 것이 아니다. 테스트가 `@supports` 밖에서 내용 높이를 건드리지
않는지 본다 — 밖에 두면 모르는 브라우저에서 **내용이 잘린다.**

##### controlled 인데 소비자가 값을 안 바꾸면 화면이 갈렸다

`<details>` 는 눌리면 **브라우저가 스스로 연다.** 소비자가 `onOpenChange` 를 받고도 값을
안 바꾸면 React 는 prop 이 그대로라 다시 그리지 않고, 그러면 DOM 을 되돌릴 기회가 없다 —
**화면만 열린 채 상태와 갈린다.**

상태를 하나 더 두는 것으로는 안 된다. 두 번째로 누를 때는 그 값이 이미 같아서 React 가
그냥 건너뛰고, **한 번은 되돌아오는데 두 번째부터 샌다.** 그래서 controlled 일 때는
값이 아니라 **다시 그릴 구실**(카운터)을 올린다.

##### `defaultOpen` 을 `<details>` 에 넘기지 않는다

React 가 아는 prop 이 아니라 `defaultopen` 속성으로 새어 나간다. 타입은 통과하지만
DOM 에 남는다 — uncontrolled 값을 내부 상태로 들고 있는다.

##### 그 밖에 정한 것

- **`disabled` 는 여는 것만 막는다.** 이미 열려 있었다면 내용을 뺏지 않는다 —
  네이티브 `<details>` 에는 `disabled` 가 없으므로 `summary` 의 click 을 막고
  `aria-disabled` 로 알린다
- 브라우저가 붙이는 삼각형은 **두 길로** 지운다 — 표준은 `list-style: none` 이지만
  옛 WebKit 은 `::-webkit-details-marker` 로 그린다
- **`name` 을 그대로 넘긴다.** `<details name>` 은 브라우저가 하나만 열리게 해 주므로
  `TxAccordion` 이 그 길을 쓸 수 있다

#### `TxCard` 의 접기를 걷어내지 않는다 (결정됨)

`TxCollapsible` 을 만들고 나니 **같은 일에 답이 둘**이 됐다. `TxCard` 는 접기를 위해
props 6개와 버튼 하나, `aria-expanded`/`aria-controls`, CSS 를 손으로 갖고 있고,
그쪽으로 접은 내용은 **⌘F 로 찾히지 않는다.**

그런데도 **둘 다 남긴다.** 쓰는 자리가 실제로 다르기 때문이다.

| | `TxCard` | `TxCollapsible` |
| --- | --- | --- |
| 본업 | **상자** — 그림자 · `overflow: hidden` · `Footer` 슬롯 | **접기** |
| 접기 | 손으로 짬 | `<details>` |
| ⌘F | ✗ | ✓ |
| 제목 줄에 다른 버튼 | 평범한 요소라 쉽다 | `<summary>` 안이라 눌러도 접힌다 |

**메뉴 2종을 하나로 합쳤던 것과 왜 다른가.** 그때는 다른 것이 둘(여는 방법·뜨는 자리)뿐이고
공개 API 도 겉모습도 같았다. 여기는 **본업이 다르고**, 합치면 한쪽의 요구(제목 줄에 동작
여러 개)를 다른 쪽의 규약(`<summary>` 는 통째로 누르는 곳)이 막는다.

**대신 갈라 쓰는 기준을 두 스토리에 밝힌다** — 소비자가 목록에서 둘을 보고 무엇을 골라야
하는지 모르면, 남겨 둔 것이 도움이 아니라 짐이 된다.

#### `TxAccordion` — 이어 붙이기와 묶어 두기만 한다

덩이 하나하나는 `TxCollapsible` 이다. 여기서 더하는 것은 **이어 붙인 겉모습과, 열린 것을
하나로 묶어 두는 일**뿐이라 색·여백·화살표를 다시 정하지 않는다 — 테스트가 그것을 지킨다
(되돌리는 것은 괜찮다. 머리말로 감쌌을 때 브라우저가 얹는 크기·굵기를 지우는 것은
겉모습을 정하는 것이 아니다).

##### `<details name>` 에 맡기지 않았다 (판단)

브라우저는 `<details name="…">` 로 **하나만 열리기를 공짜로 해 준다.** 그런데도 JS 로
들고 있다 — 그쪽에 맡기면 **여는 길이 둘이 된다**(브라우저와 우리). controlled 로 쓸 때,
그리고 `onChange` 로 알릴 때 어느 쪽이 이겼는지를 따라다녀야 한다.

상태를 **배열 하나**로 두면 하나만 열리기는 상태의 모양이 보장한다 — 어긋날 자리가 없다.
`<details>` 를 쓰는 진짜 이유(⌘F · 키보드 · 스크린리더)는 `name` 없이도 그대로 온다.

##### 값은 늘 배열로 돌려준다

하나만 열리는 모드에서도 `onChange` 는 `[]` 아니면 `[1]` 이다. **받는 쪽에서 타입을
좁힐 일이 없다.** 줄 때는 숫자 하나로도 받는다 — 입력을 너그럽게 받고 출력을 하나로
두는 것이 쓰는 쪽에 편하다.

##### 머리말은 옵션이다 (판단)

`headingLevel` 을 주면 제목이 `<h3>` 같은 머리말이 되어 **스크린리더 사용자가 머리말
목록으로 건너뛸 수 있다.** `<summary>` 는 원래 phrasing content 하나 **또는 머리말 하나**를
품도록 규정돼 있어서 이 마크업이 맞다 (그래서 `TxCollapsible` 에 `titleAs` 를 더했다).

**기본으로 켜지 않았다.** 깊이는 그 페이지의 짜임을 아는 쪽이 정해야 한다 — `<h1>` 아래에
`<h4>` 를 놓으면 안 하느니만 못하다. 우리가 고를 수 없는 값을 기본값으로 정하지 않는다.

##### 떨어뜨려 놓고 싶으면 `TxCollapsible` 을 쓴다

`TxAccordion` 은 **이어 붙은 목록**이다. 맞닿은 테두리를 한 겹으로 겹치고 모서리를 바깥에만
남긴다. 상자를 떨어뜨려 쌓는 것은 `TxCollapsible` 여러 개가 이미 하는 일이라, 그것을 위한
`gap` 옵션을 두지 않았다 — 두면 모서리 규칙이 갈라져 둘 다 어중간해진다.

#### `TxTag` — 갈래 어휘를 물려받되 `neutral` 이 하나 더

신규다. `TxAlert` 과 같은 방식으로 짰다 — **갈래는 `--tx-tag-accent` 하나만 갈아 끼우고**
바탕·테두리·점 색이 전부 거기서 섞여 나온다.

##### `neutral` 을 더한 이유

태그에는 **색이 뜻을 갖지 않는 라벨**이 흔하다 — 개수, 분류, 그냥 이름표. 그런 자리에
`info`(브랜드색)를 쓰면 안 해도 될 강조가 붙는다. 그래서 다섯 번째를 두고 **기본으로 삼았다.**
전역 토큰은 안 늘었다 — `neutral` 은 본문 색을 그대로 쓴다.

##### `solid` 를 두지 않았다 (판단)

배경을 갈래색으로 꽉 채우는 방식이다. **못 하는 이유가 팔레트에 있다** — `success` 와
`warning` 은 라이트/다크에서 밝기가 뒤집히고(`#15803d` ↔ `#4ade80`), 그 위에 얹을 글자색을
한 벌로 정할 수 없다. 다크에서 밝은 노랑 위에 흰 글자는 읽히지 않는다.

갈래마다 "그 위의 글자색" 토큰을 전역에 두면 되지만, 그러면 **소비자가 브랜드색을 덮을 때
그 짝까지 함께 내야 한다.** 요구가 실제로 오기 전에는 늘리지 않는다.

##### 갈래색을 그대로 글자에 쓰면 대비가 모자랐다 (재서 고쳤다)

처음에는 `--tx-tag-fg: var(--tx-tag-accent)` 였다. 다크에서 재 보니 **`info` 2.74:1,
`danger` 2.94:1** 로, 12px 굵은 글씨에 필요한 4.5:1 에 한참 못 미쳤다. 원인은 팔레트에 있다 —
`--tx-color-primary` 와 `--tx-color-danger` 는 **흰 글자를 얹는 버튼 배경용**으로 고른 값이라
다크에서도 어둡다.

**글자색을 본문 색 쪽으로 당겨 만든다.**

```css
--tx-tag-fg: color-mix(in oklab, var(--tx-tag-accent) 65%, var(--tx-color-text));
```

본문 색은 라이트에서 어둡고 다크에서 밝으므로, 그쪽으로 섞으면 **어느 모드에서든 바탕에서
멀어진다.** 컴포넌트가 모드를 알 필요가 없다.

**비율은 브라우저에서 재서 정했다.** 70% 로 두면 다크에서 `info` 4.40 · `danger` 4.46 으로
아슬하게 모자라, 65% + 바탕 10% 로 낮췄다. 지금은 **라이트 6.00~17.74, 다크 4.85~16.20** 으로
열 조합이 전부 4.5:1 을 넘는다. 작은 점과 가는 테두리도 같은 색에서 뽑는다 — 갈래색
그대로면 다크 바탕에 묻힌다.

##### 누르는 것이 아니다

태그는 읽는 것만 한다. **누를 수 있고 지울 수 있는 것(Chip)은 5차 후보군의 4번**이라,
그 요구가 오면 이 컴포넌트가 흡수한다.

##### 이름을 `TxBadge` 에서 `TxTag` 로 바꿨다 (결정됨)

처음에는 `TxBadge` 로 만들었다. 5차 후보군을 정리하면서 **`TxBadge` 라는 이름이 두 물건
사이에서 갈린다**는 것이 드러났다.

- MUI · Chakra · Ant Design — `Badge` 는 **알림 점·카운트**(아이콘 위에 붙는 작은 표시)
- shadcn/ui · Bootstrap — `Badge` 는 **상태 라벨**(지금 만든 것)

**둘을 둘로 부르는 모형이 일관된다.** 상태 라벨은 `TxTag`(Ant Design 의 `Tag`, MUI 의 `Chip`),
`TxBadge` 는 알림 점·카운트로 비워 둔다. 업계 이름을 따르기로 한 기준(`TxAlert` · `TxToast`)이
여기서도 같은 답을 낸다 — **배포 전이라 값이 기계적인 이름 바꿈뿐이었다.**

#### `TxSkeleton` — 자리를 잡아 두는 것이 전부다

신규다. **`TxSpinner` · `TxLoading` 과 하는 말이 다르다** — 그쪽은 "기다려라" 이고
이쪽은 "여기 이런 모양의 것이 올 것이다" 이다. 그래서 목록·카드처럼 **모양이 미리
정해진 것**에 맞고, 무엇이 올지 모르거나 화면을 덮어야 하면 `TxLoading` 이다.
그 기준을 스토리에 표로 적었다.

##### 줄 수만큼의 자리를 정확히 차지한다 (재서 고쳤다)

처음에는 막대 사이에만 간격을 뒀다. 브라우저에서 재 보니 스켈레톤 → 내용으로 바뀔 때
카드 높이가 **169.5px → 177.5px 로 8px 튀었다.** `N × 막대 + (N-1) × 간격` 이라
**간격 하나만큼 짧기** 때문이다.

남는 높이를 위아래로 반씩 나눠 두면 `N × 줄높이` 가 정확히 맞는다.

```css
--tx-skeleton-lead: calc(var(--tx-skeleton-line-height) - var(--tx-skeleton-text-height));

gap: var(--tx-skeleton-lead);
padding-block: calc(var(--tx-skeleton-lead) / 2);
```

고친 뒤 다시 재니 **차이 0px** 이다. 자리를 잡아 두는 것이 이 컴포넌트가 하는 일의
전부라, 그것이 어긋나면 있으나 마나다. 손잡이도 "막대 두께" 가 아니라
**`--tx-skeleton-line-height`(글 한 줄이 차지하는 높이)** 로 두었다 — 소비자가 맞춰야 할
값은 그쪽이기 때문이다.

##### 회색을 값으로 박지 않는다

본문 색을 옅게 섞어 만든다. 라이트에서는 어두운 회색, 다크에서는 밝은 회색이 저절로 된다 —
**값으로 박으면 다크에서 바탕보다 어두워져 자리가 아예 안 보인다.** `TxTag` 에서
글자색을 본문 색 쪽으로 당긴 것과 같은 수법이다.

##### 분기까지 맡는다 (합의)

처음에는 회색 덩이만 그리고 분기는 밖에 두었다. 그러면 쓰는 쪽이 매번 이렇게 된다.

```tsx
<div aria-busy={loading}>{loading ? <TxSkeleton lines={3} /> : <Content />}</div>
```

`loading` 을 받아 **`false` 면 `children` 을 그대로 내도록** 바꿨다. 껍데기를 남기지
않으므로 결과는 삼항과 같고, **`aria-busy` 를 스스로 붙인다** — "바깥에 `aria-busy` 를
두라" 를 문서로만 적어 두면 그건 잊힌다.

**치르는 값은 `?.` 다.** JSX children 은 삼항과 달리 **먼저 평가되므로**, 불러오는 동안에도
안전한 값이어야 한다 (`user?.name`). 값을 좁혀 쓰던 코드라면 밖에서 삼항으로 가르는 편이
낫고, 그 길도 그대로 열려 있다. 이 값을 prop 설명과 스토리에 분명히 적었다.

`TxCard` 의 접기와 `TxCollapsible` 을 갈라 둔 것과 왜 다른가 — **저 둘은 따로 쓸 수 있지만
여기는 늘 함께 쓰인다.** 분기 없는 스켈레톤은 쓸 데가 없고, 스켈레톤 없는 분기는 그냥 삼항이다.

##### 모양도 자식에서 가져온다 (합의)

`lines={3}` 을 주는 것은 **모양을 두 번 적는 일**이다 — 진짜 마크업에 이미 세 줄이 있는데
스켈레톤에도 세 줄이라고 또 적는다. 그래서 **아무 모양도 안 주면 `children` 에서 가져오도록**
했다. `lines` · `variant` · `width` · `height` 중 하나라도 주면 그리던 대로 그린다.

**되는지 먼저 브라우저에서 재고 결정했다.**

- 값이 안 왔으면 그 요소는 **비어 있고**, 붙박이 글이 든 요소는 비어 있지 않다 —
  **`:empty` 가 그 둘을 갈라 준다.** `이름` · `메일` 같은 라벨은 그대로 보이고 값 자리만
  회색이 된다 (측정: 라벨 남고 높이 48 → 48)
- 높이는 그 요소의 **자기 글꼴**에서 나온다(`min-height: 1lh`). 빈 `<p>` 셋이 실제 글과
  똑같이 60px 을 차지했다
- **자식을 훑거나 재지 않는다.** 순수 CSS 라 JS 가 늘지 않고, `ResizeObserver` 도 없다 —
  성능 걱정이 무색해지는 지점이다
- **소비자 CSS 와 싸우지 않는다.** 빈 요소라 감출 글자가 없어서
  `color: transparent !important` 가 필요 없다 (테스트가 `!important` 를 금한다)

껍데기는 `display: contents` 라 자리를 차지하지 않는다 — 다 불러오면 사라지는데 그때
배치가 달라지면 "자리를 잡아 둔다" 가 거짓이 된다. 카드 높이를 재니 **132.5 → 132.5** 였다.

**걸리는 데가 셋 있고 셋 다 조용히 실패한다** — 회색 막대가 안 나올 뿐 배치는 멀쩡하다.
prop 설명과 스토리에 그대로 적었다.

1. `{user?.name ?? "—"}` 처럼 **대체값**을 넣으면 비어 있지 않아 안 칠해진다
2. `<p> {name} </p>` 처럼 **공백**이 끼면 비어 있지 않아 안 칠해진다 (측정으로 확인)
3. 한 요소당 **한 줄**이다. 여러 줄로 감길 글에는 `lines` 를 쓴다

##### 그러면 모양을 직접 주는 길은 왜 남기나

**목록도 자식에서 가져온다.** 행 컴포넌트를 그대로 쓰고 값만 비워 넘기면 되고,
그러면 스켈레톤이 실제와 어긋날 수가 없다 — 같은 마크업이기 때문이다. 재 보니
행 셋짜리 목록이 **152 → 152** 로 맞았다.

직접 줘야 하는 자리는 **둘뿐**이다.

| 자리 | auto | 실제 |
| --- | --- | --- |
| 목록 (행 2개) | 80px | 80px |
| **세 줄로 감기는 문단** | **20px** | **60px** |

**글이 몇 줄로 감길지는 자식이 비어 있는 한 알 수 없다** — 빈 문단은 언제나 한 줄이다.
이건 고칠 수 있는 종류가 아니라서 `lines` 가 남는다. 다른 하나는 **미러링할 마크업이
아예 없는 자리**로, 차트나 지도가 들어올 상자가 그렇다.

그래서 스토리와 문서가 **auto 를 먼저 가르치고 명시적인 쪽을 예외로** 둔다.

##### 두 모드가 접근성을 다르게 다룬다

- **우리가 그릴 때** — 빈 막대뿐이라 읽힐 것이 없다. 막대를 `aria-hidden` 으로 두고
  바깥이 `aria-busy` 로 "지금 채우는 중" 을 한 번 알린다
- **자식에서 가져올 때** — 소비자의 진짜 마크업이라 **빈 버튼·입력에 초점이 들어갈 수 있다.**
  이름도 내용도 없는 것에 Tab 이 멈추면 막다른 길이라 `inert` 로 그 가지를 통째로 뺀다.
  그래서 이쪽에는 `aria-busy` 를 겹쳐 달지 않는다 — `inert` 가 이미 더 센 말이고,
  겹치면 뒤가 묻힌다

##### 대체 요소는 가상요소를 그리지 못한다

칠하는 것은 `::after` 다 — 그래야 줄 사이가 벌어지고 모서리가 둥글다. 그런데 `<img>` ·
`<input>` 은 가상요소를 갖지 못해서(측정으로 확인) 그쪽만 배경으로 칠한다.

##### 루트를 감추면 `aria-busy` 가 함께 묻힌다

처음에는 루트에 `aria-hidden` 을 걸었다. 그 위에 `aria-busy` 를 얹으면 **스크린리더가
그 가지 전체를 건너뛰므로 아무 뜻이 없다.** 감추는 것을 **막대 쪽으로 내렸다** —
빈 상자를 여러 개 읽어 주지 않으면서, 바깥은 "지금 이 자리를 채우는 중" 을 알린다.

##### 지나가는 빛은 배경으로 그린다

`::before` 로 한 겹 얹으면 소비자가 넣은 것과 겹칠 자리가 생긴다. 배경 그라디언트를
움직이면 요소가 하나도 늘지 않는다.

#### 이름은 업계에서 통하는 것을 쓴다 (결정됨)

`TxAlert` · `TxToast` 둘 다 **가장 널리 쓰이는 이름**을 골랐다.

- **`Alert`** — MUI · Chakra · Ant Design · Bootstrap · shadcn/ui · Mantine 이 전부
  같은 것(인라인 · 색 갈래 · 닫기 가능)을 이렇게 부른다
- **`Toast`** — Chakra · shadcn/ui · Radix · Sonner · react-hot-toast. `Snackbar` 는
  Material 용어라 그쪽을 안 거친 사람에게는 덜 통하고, `Notify` 는 라이브러리 이름보다
  **API 동사**로 더 많이 쓰인다

**짝이 이름으로 드러난다** — `TxAlert` 은 페이지에 박히고 `TxToast` 는 떴다 사라진다.

`TxDialog.alert()` 과 이름이 겹쳐 보이지만 하나는 컴포넌트, 하나는 메서드다.
겹침을 피하려고 업계에서 통하는 이름을 버리는 것이 더 비싸다 — 대신 두 스토리가
서로를 가리킨다.

#### 뒤로 미룬 것들

- **`TxTicker`** — 세로 롤링 공지 · 가로 흐름. 자동으로 움직이는 것은 멈출 수 있어야 한다 (WCAG 2.2.2)
- **`TxCarousel`** — CSS `scroll-snap` 이면 스와이프·키보드가 공짜라 싸다.
  **무한 루프를 넣으면 복제와 점프가 필요해 비용이 뛴다** — 뺀 채로 시작한다
- **`TxEmpty`** · **`TxAvatar`**(이미지 + 이니셜 폴백) · **`TxBreadcrumb`**(라우터는 `as` 주입)
- **`TxNavBar`(GNB)** — 아래

#### GNB 는 `TxLayout` 과 겹치지 않는다

확인하고 적는다. 원본 `TxLayout` 은 `top/left/middle/right/bottom` 슬롯에 크기 조절까지
되는 **관리자 셸**(VS Code 식 패널)이지 사이트 상단 내비게이션이 아니다. 둘은 다른 것이다.

**`TxNavBar` 가 맡을 것은 셋뿐이다 (합의)** — sticky 스크롤 반응 · 데스크톱↔모바일 전환 ·
메가메뉴. **로고 · 메뉴 구조 · 로그인 상태는 전부 슬롯으로 받는다.** 그것이 앱마다
다른 부분이고, 넣는 순간 범용이 아니게 된다. 드로어는 `TxSlidePanel`, hover 메뉴는
`TxDropMenu` 를 그대로 쓴다 — **새로 만들 것은 전환과 sticky 뿐이다.**

#### 자른 것

- **`TxScrollTop`** — 앱이 다섯 줄로 짠다
- **`TxRating`** — 도메인 냄새가 난다
- **`TxDivider`** — `<hr>` 에 토큰이면 끝난다. 컴포넌트로 감쌀 값이 없다
- **`TxImage`** — Next.js 같은 프레임워크가 각자 자기 것을 갖고 있다. 겹친다

#### 상태색 토큰을 하나 늘린다 (결정됨)

`TxAlert` · `TxToast` · `TxTag` 가 **info · success · warning · danger** 네 갈래를
갖는데, 지금 전역 토큰에 **초록만 없다.** `TxJsonTree` 때 "새 전역색을 만들면 소비자가
브랜드색을 덮을 때 챙길 것이 는다" 며 미뤘던 것을 여기서 연다.

**`--tx-color-success` 하나만 늘린다.** `info` 는 `--tx-color-primary` 가 겸한다 —
브랜드색과 안내색을 가르고 싶은 자리가 있지만, 그 요구가 실제로 오기 전에 토큰을 늘리면
소비자가 챙길 것만 는다. 세 컴포넌트가 **같은 네 갈래를 쓴다.**

#### 먼저 다섯 개 — 완료

**`TxDivider` → `TxProgress` → `TxEmptyState` → `TxGrid` → `TxCopyButton`.**

다섯 전부 **의존이 없고 작다.** 먼저 끝내 두면 뒤의 큰 것들(`TxAppShell` · `TxTable` ·
`TxFileUpload`)이 쓸 재료가 생긴다 — 빈 상태 · 진행률 · 구분선은 그 안에 들어간다.
다섯을 끝내고 다음을 다시 정한다.

#### 다섯 개를 만들며 정한 것

##### `TxDivider` — 글자가 없으면 `<hr>` 하나다

브라우저가 이미 "가르는 것" 으로 읽으므로 `role` 을 손으로 달지 않는다. 글자를 주면
`<hr>` 이 void 요소라 담지 못하므로 `<div>` 가 되는데, **그때 `role="separator"` 를 달지
않는다** — 그 역할은 자식을 장식으로 보게 만들어서, 달면 정작 읽혀야 할 글자가 안 읽힌다.
선은 `::before` · `::after` 가 그린다.

세로 선은 늘릴 기준이 없는 자리에서 **높이 0 이 되어 사라진다.** `align-self: stretch` 와
`min-block-size: 1lh` 를 함께 둔다.

##### `TxProgress` — 아는 것만 그린다

`determinate` 전용이다. 끝을 모르는 기다림은 `TxLoading` · `TxSpinner` 가 맡는다 —
**모르는데 막대를 그리면 아는 척**이 된다.

`<progress>` 를 쓰지 않았다. 브라우저마다 겉모습을 바꾸는 길이 달라 토큰 하나로 맞출 수 없다 —
값은 `role="progressbar"` 와 `aria-value*` 로 그대로 전한다. **범위를 넘는 값은 잘라서
화면과 읽히는 값을 같게** 한다. `showValue` 에 함수를 주면 `aria-valuetext` 도 그 글자로 나간다
(`3/5` 를 퍼센트로 읽으면 뜻이 달라진다).

##### `TxEmptyState` — 넷을 가르는 것이 요지다

`no-data` · `no-result` · `error` · `no-permission` 은 **사용자가 할 일이 서로 다르다.**
"없음" 이라고만 적으면 그 다음이 없으므로 갈래마다 문구와 그림을 따로 둔다.

**바탕도 테두리도 칠하지 않고, `error` 만 갈래색을 쓴다.** 나머지 셋은 잘못이 아니라
상태라, 붉히면 없는 문제를 있는 것처럼 보이게 한다 — 눈에 띄어야 하는 것은 `TxAlert` 쪽이다.

문구에서 **`??` 를 쓰면 `null` 에도 기본값이 돌아온다.** "안 준 것"(기본 문구)과
"일부러 비운 것"(줄 없음)을 가르려고 `=== undefined` 로 갈랐다. 테스트가 그 셋을 지킨다 —
안 준 것 · `null` · 빈 문자열.

##### `TxGrid` — 미디어 쿼리를 쓰지 않는다

`auto-fit` 과 `minmax` 가 칸 수를 정하므로 **화면이 아니라 놓인 자리의 폭**에 반응한다.
같은 코드를 사이드바에 넣으면 거기 폭에 맞춰 접힌다 (재 보니 18rem 에서 한 칸, 34rem 에서 두 칸).
`minmax(min(…, 100%), …)` 의 `min()` 이 없으면 최소 폭이 자리보다 클 때 넘쳐서
가로 스크롤이 생긴다. `TxGrid.Item` 의 `span` 도 `min()` 으로 칸 수를 넘지 못하게 가둔다.

##### `TxCopyButton` — 되살리며 원본의 결함 셋을 다 고쳤다

원본 `TxClipboardButton` 은 `<div onClick>` 이라 **키보드로 못 눌렀고, 버튼으로 읽히지
않았고, 복사됐는지 알 길도 없었다.** 겉을 `TxButton` 에 얹어 앞의 둘이 사라졌고,
셋째는 글자를 잠깐 바꾸고 **`role="status"` 로 소식을 따로 보낸다** — 버튼 글자가 바뀌는
것만으로는 마우스로 누른 사람에게 아무 소식이 없다.

**`navigator.clipboard` 는 보안 컨텍스트에서만 있다.** 사내 도구가 평문 http 로 뜨는 일이
흔해서, 없으면 숨긴 `<textarea>` 와 `execCommand` 로 물러선다. 브라우저에서 실패 경로가
실제로 돌았다 — 샌드박스 iframe 이라 둘 다 막혀서 "복사 실패" 가 떴다.

`data-tag` 는 넘기지 않는다. `TxButton` 이 그것을 **계약 속성으로 잠가 두어** 조용히
버려지기 때문이다 — 이것은 버튼이 맞으니 그 표시를 두고, 여기 것은 `.tx-copy-button` 과
`data-state` 가 알린다.

**폭이 튀는 것을 재서 고쳤다.** 처음 기본 실패 문구(`복사하지 못했습니다`)가 `min-width`
8rem 을 넘어 128 → 144.6px 로 흔들렸다. `복사 실패` 로 줄이니 기본 세 글자가 모두 128px
안에 들어 **폭이 아예 움직이지 않는다.**

#### 먼저 풀어야 했던 겹침 넷 — 전부 정했다

**1. `TxBadge` 는 알림 점·카운트에 준다. 상태 라벨은 `TxTag` 다.** (결정됨 · 반영 완료)

업계 이름이 갈리는 자리였다 — MUI · Chakra · Ant Design 은 `Badge` 를 알림 점·카운트로,
shadcn/ui · Bootstrap 은 상태 라벨로 쓴다. **둘을 둘로 부르는 모형이 일관되므로** 위 표를
따랐다. 이미 만든 것을 `TxTag` 로 바꿨고, 배포 전이라 값이 기계적인 이름 바꿈뿐이었다.
남은 일은 `TxTag` 가 **Chip(누를 수 있음·지울 수 있음)을 흡수**하는 것이다.

**2. `TxLayout` 을 자르고 `TxAppShell` 로 간다.** (결정됨)

3차의 마지막으로 남아 있던 `TxLayout` 을 **잘라낸다.** 근거는 셋이다.

- **앱 사용 0회**에 447줄이다. 이식 목록에서 가장 약한 자리였다
- 크기 조절되는 패널은 **IDE 재주**고, 지금 방향은 사이트 화면이다
- 한 화면에 셸이 둘일 일이 없다 — 남기면 소비자가 **무엇을 골라야 하는지 모른다**

앞서 따로 두기로 했던 **`TxNavBar`(GNB)도 `TxAppShell` 안으로 들어간다.** sticky 스크롤
반응과 데스크톱↔모바일 전환은 셸이 할 일이지 별개 부품이 아니다.
그래서 **이식은 26개 중 23개로 끝났다** (`TxHeader` · `TxClipboardButton` · `TxLayout` 을 잘랐다).
`TxClipboardButton` 은 13번 `TxCopyButton` 으로 되살아난다.

**3. 숫자 증감은 `TxNumberInput` 이다. `TxStepper` 는 비워 둔다.** (결정됨)

`Stepper` 는 **가입·주문 흐름의 단계 표시**로도 널리 쓰이는 이름이다(MUI 가 그쪽).
숫자 증감에 그 이름을 쓰면 나중에 단계 표시가 필요할 때 **이름이 이미 막힌다.**
`TxNumberInput` 으로 부르면 둘 다 산다.

**4. `TxDivider` 를 되살린다.** (결정됨)

4차 계획에서 "`<hr>` 에 토큰이면 끝나니 감쌀 값이 없다" 며 잘랐던 것이다.
**근거가 바뀌었다** — `orientation` 과 **라벨이 든 구분선**(가운데 글자)은 `<hr>` 이 못 한다.
그 둘이 있으면 값이 선다. `TxFlex` 에 `divided` 를 둘지도 함께 본다.

## 커스터마이징 방식 — 결정됨

**CSS 커스텀 프로퍼티 토큰(`--tx-*`) + `tx` 캐스케이드 레이어.** temp 에서 이미 결론이 났고
`TxSpinner` · `TxButton` · `TxLoading` · `TxFlex` 4개가 이 방식으로 이행됐다. **다시 논의하지 않는다.**

### 1. 토큰이 커스터마이징의 정문이다

소비자는 `tokens.css` 의 전역 토큰만 덮으면 된다.

```css
:root {
  --tx-color-primary: #7c3aed;
  --tx-radius: 9999px;
}
```

컴포넌트 토큰(`--tx-button-bg` 등)이 이 값을 **기본값으로 받는다.** 그래서 한 줄만 바꾸면
`hover` · `focus` · `.dark` 가 저절로 따라온다 — 상태별로 하나씩 덮을 필요가 없다.

**토큰 이름은 공개 API 다.** 지우거나 바꾸면 major 다. 그래서 **안 쓰는 토큰을 미리 만들지 않는다.**
실제로 쓰는 컴포넌트가 생길 때 한 줄씩 늘린다.

temp 기준 전역 토큰은 11개다 — `--tx-color-{primary,danger,muted,state,text,on-accent}` ·
`--tx-state-{hover,pressed}` · `--tx-focus-ring` · `--tx-focus-ring-offset` · `--tx-radius`.

### 2. 스타일시트는 하나만 낸다

```tsx
import "@txstack/ui/styles.css";
```

**컴포넌트가 자기 CSS 를 import 하지 않는다.** `styles.css` 에서만 모은다 —
그래야 SSR·번들러 환경에 따라 깨지는 경로가 생기지 않는다. 빌드가 `@import` 를 펼쳐
`dist/styles.css` 하나로 낸다. **순서가 곧 캐스케이드다** — 토큰 → 컴포넌트 순.

### 3. `@layer tx` 가 `className` 을 살린다

전부 `tx` 레이어에 넣는다. 이 한 줄이 핵심이다.

- **레이어 밖 CSS 는 레이어 안 CSS 를 특이도와 무관하게 무조건 이긴다.**
  그래서 순수 CSS · Sass · CSS Modules 를 쓰는 소비자는 **아무것도 안 해도** 덮어쓸 수 있다.
- **Tailwind 를 쓴다면 한 줄이 필요하다.** `tx` 는 preflight(`base`) 뒤, 유틸리티 앞이어야 한다.
  앞에 두면 preflight 가 버튼 배경·여백을 지우고, 뒤에 두면 `className` 이 안 먹는다.

  ```css
  @layer theme, base, tx, components, utilities;

  @import "tailwindcss";
  @import "@txstack/ui/styles.css";
  ```

### 4. `TxTheme` 은 폐기됐다

`TxClassBase` 같은 Tailwind 클래스 문자열 상수였다. 공개 API 로 두면 소비자가 그걸 받아서
할 수 있는 일이 **Tailwind 를 쓰는 것뿐**이라, "소비자가 무엇을 쓰든 상관없다" 는 전제와 어긋난다.

**이식 시 `TxTheme` 을 참조하는 컴포넌트는 그 참조를 CSS + 토큰으로 바꾼 뒤에 가져온다.**
`TxTheme` 자체는 새 저장소로 옮기지 않는다.

## 이식 시 반드시 걷어낼 것

각 컴포넌트를 열 때 이것부터 확인한다.

- **`TxTheme` / Tailwind 클래스 문자열** — 위 4번. CSS + `--tx-*` 토큰으로 옮긴다.
- **앱 전역(ambient) 타입** — 소비자 프로젝트에는 그 전역이 없다.
- **도메인 지식** — 블랙/문자/지갑/유저타입 등. props 로 받거나 잘라낸다.
- **`import.meta.env` 직접 참조** — Vite 아닌 소비자에서 깨진다. 옵션으로 받는다.
- **다른 Tx\* 컴포넌트로의 숨은 의존** — 배럴 import 라면 순환이 생길 수 있다.
- **default export** — 배럴의 `export *` 는 default 를 실어 나르지 않는다. named 로 바꾼다.

      아니라 비슷한 것을 만들 때 바탕으로 쓰는 부품이라는 것. 그러지 않으면 소비자가
      이걸로 무엇을 해야 하는지 모른다.
