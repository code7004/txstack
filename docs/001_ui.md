# 001 · `@txstack/ui`

**Tx\* React 컴포넌트. 목표는 두 가지 — 쉬운 사용법, 쉬운 커스터마이징.**

`react` / `react-dom` 은 peerDependency 다.

## 무엇을 해결하는가

세 프로젝트가 같은 모달, 같은 드롭다운, 같은 테이블을 각자 복사해 들고 있었다.
한 곳에서 버그를 고쳐도 나머지 둘은 그대로였다.

여기서 중요한 건 **그냥 옮기는 게 아니라는 것**이다. 원본 컴포넌트들은
앱 전역 타입·도메인 지식·`import.meta.env` 에 묶여 있다. **그걸 걷어내야 라이브러리가 된다.**

판정 기준: **네 번째 프로젝트가 설치해서 그대로 쓸 수 있는가.**

## 진입점 구조

무거운 선택적 의존은 **서브패스로 분리한다.** 루트 배럴을 import 한 소비자는
`ag-grid` 나 `react-day-picker` 를 설치하지 않아도 동작해야 한다.

| 진입점                    | 내용             | 추가 peer 의존                     |
| ------------------------- | ---------------- | ---------------------------------- |
| `@txstack/ui`             | 대부분의 컴포넌트 | 없음                               |
| `@txstack/ui/aggrid`      | `TxAgGrid`       | `ag-grid-community` `ag-grid-react` |
| `@txstack/ui/daypicker`   | `TxDayPicker` 계열 | `react-day-picker` `dayjs`         |
| `@txstack/ui/styles.css`  | 기본 스타일      | —                                  |
| `@txstack/ui/tokens.css`  | 디자인 토큰      | —                                  |

```tsx
import { TxButton, TxModal } from "@txstack/ui";
import { TxAgGrid } from "@txstack/ui/aggrid";
import "@txstack/ui/tokens.css";
import "@txstack/ui/styles.css";
```

## 커스터마이징 방식

**아직 합의되지 않았다. 이식 전에 여기부터 정해야 한다.** 컴포넌트 하나를 옮기고 나서
방식을 바꾸면 나머지 25개를 다시 손대야 한다.

후보:

1. **CSS 변수 토큰** — `tokens.css` 의 `--tx-*` 를 소비자가 덮어쓴다. 런타임 비용 0, 타입 안전성 없음.
2. **`className` 통과** — 각 컴포넌트가 `className` 을 받아 Tailwind 등으로 소비자가 덧붙인다.
3. **`TxTheme` 프로바이더** — 컨텍스트로 토큰 주입. 유연하지만 프로바이더 없이는 못 쓴다.

temp 구현은 `tokens.css` + `TxTheme` 이 둘 다 있다. **어느 쪽이 주인지 불명확하다.**

## 이식 시 반드시 걷어낼 것

각 컴포넌트를 열 때 이것부터 확인한다.

- **앱 전역(ambient) 타입** — 소비자 프로젝트에는 그 전역이 없다.
- **도메인 지식** — 블랙/문자/지갑/유저타입 등. props 로 받거나 잘라낸다.
- **`import.meta.env` 직접 참조** — Vite 아닌 소비자에서 깨진다. 옵션으로 받는다.
- **다른 Tx\* 컴포넌트로의 숨은 의존** — 배럴 import 라면 순환이 생길 수 있다.
- **default export** — 배럴의 `export *` 는 default 를 실어 나르지 않는다.
  이름 붙여 다시 내보내거나 named export 로 바꾼다.
