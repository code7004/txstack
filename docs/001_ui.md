# 001 · `@txstack/ui`

**Tx\* React 컴포넌트. 목표는 두 가지 — 쉬운 사용법, 쉬운 커스터마이징.**

`react` / `react-dom` 은 peerDependency 다.

## 무엇을 해결하는가

세 프로젝트가 같은 모달, 같은 드롭다운, 같은 테이블을 각자 복사해 들고 있었다.
한 곳에서 버그를 고쳐도 나머지 둘은 그대로였다.

여기서 중요한 건 **그냥 옮기는 게 아니라는 것**이다. 원본 컴포넌트들은
앱 전역 타입·도메인 지식·`import.meta.env` 에 묶여 있다. **그걸 걷어내야 라이브러리가 된다.**

판정 기준: **네 번째 프로젝트가 설치해서 그대로 쓸 수 있는가.**

## 진입점 구조

무거운 선택적 의존은 **서브패스로 분리한다.** 루트 배럴을 import 한 소비자는
`ag-grid` 나 `react-day-picker` 를 설치하지 않아도 동작해야 한다.

| 진입점                   | 내용               | 추가 peer 의존                      | 상태          |
| ------------------------ | ------------------ | ----------------------------------- | ------------- |
| `@txstack/ui`            | 대부분의 컴포넌트  | 없음                                | 빈 배럴       |
| `@txstack/ui/aggrid`     | `TxAgGrid`         | `ag-grid-community` `ag-grid-react` | 빈 배럴       |
| `@txstack/ui/daypicker`  | `TxDayPicker` 계열 | `react-day-picker` `dayjs`          | 빈 배럴       |
| `@txstack/ui/styles.css` | 전체 스타일시트    | —                                   | **아직 없음** |

`styles.css` 는 **첫 컴포넌트를 이식할 때 함께 생긴다.** 빈 스타일시트를 미리 내보내지 않는다.
`tokens.css` 는 별도 진입점이 아니다 — `styles.css` 가 `@import` 로 먼저 싣는다.

```tsx
import { TxButton, TxModal } from "@txstack/ui";
import { TxAgGrid } from "@txstack/ui/aggrid";
import "@txstack/ui/styles.css";
```

## 컴포넌트 — temp 에 있는 26개

**전부 이식하지 않는다.** 하나씩 열어보고 남길지 자를지 판단한다.
진행 상태는 [README](README.md) 가 소유한다.

| 그룹     | 컴포넌트                                                                              |
| -------- | ------------------------------------------------------------------------------------- |
| 기반     | `TxFlex`\* · `TxLayout` · `TxCard` · `TxHeader` · `TxIcons`                           |
| 입력     | `TxInput` · `TxTextarea` · `TxCheckBox` · `TxDropdown` · `TxForm` · `TxCapsLockCheck` |
| 액션     | `TxButton`\* · `TxClipboardButton` · `TxDropMenu` · `TxContextMenu`                   |
| 표시     | `TxSpinner`\* · `TxLoading`\* · `TxToolTip` · `TxJsonTree`                            |
| 오버레이 | `TxModal` · `TxSlidePanel` · `TxTabs`                                                 |
| 테이블   | `TxCoolTable` · `TxAgGrid`(서브패스)                                                  |
| 날짜     | `TxDayPicker`(서브패스)                                                               |

`*` 는 temp 에서 이미 CSS + 토큰 방식으로 이행이 끝난 4개다. **이식 순서를 여기서 시작한다** —
방식이 검증된 것부터 옮겨야 나머지 22개의 기준이 선다.

`TxTheme` 은 목록에 없다. 폐기됐다 — 아래 4번.

## 커스터마이징 방식 — 결정됨

**CSS 커스텀 프로퍼티 토큰(`--tx-*`) + `tx` 캐스케이드 레이어.** temp 에서 이미 결론이 났고
`TxSpinner` · `TxButton` · `TxLoading` · `TxFlex` 4개가 이 방식으로 이행됐다. **다시 논의하지 않는다.**

### 1. 토큰이 커스터마이징의 정문이다

소비자는 `tokens.css` 의 전역 토큰만 덮으면 된다.

```css
:root {
  --tx-color-primary: #7c3aed;
  --tx-radius: 9999px;
}
```

컴포넌트 토큰(`--tx-button-bg` 등)이 이 값을 **기본값으로 받는다.** 그래서 한 줄만 바꾸면
`hover` · `focus` · `.dark` 가 저절로 따라온다 — 상태별로 하나씩 덮을 필요가 없다.

**토큰 이름은 공개 API 다.** 지우거나 바꾸면 major 다. 그래서 **안 쓰는 토큰을 미리 만들지 않는다.**
실제로 쓰는 컴포넌트가 생길 때 한 줄씩 늘린다.

temp 기준 전역 토큰은 11개다 — `--tx-color-{primary,danger,muted,state,text,on-accent}` ·
`--tx-state-{hover,pressed}` · `--tx-focus-ring` · `--tx-focus-ring-offset` · `--tx-radius`.

### 2. 스타일시트는 하나만 낸다

```tsx
import "@txstack/ui/styles.css";
```

**컴포넌트가 자기 CSS 를 import 하지 않는다.** `styles.css` 에서만 모은다 —
그래야 SSR·번들러 환경에 따라 깨지는 경로가 생기지 않는다. 빌드가 `@import` 를 펼쳐
`dist/styles.css` 하나로 낸다. **순서가 곧 캐스케이드다** — 토큰 → 컴포넌트 순.

### 3. `@layer tx` 가 `className` 을 살린다

전부 `tx` 레이어에 넣는다. 이 한 줄이 핵심이다.

- **레이어 밖 CSS 는 레이어 안 CSS 를 특이도와 무관하게 무조건 이긴다.**
  그래서 순수 CSS · Sass · CSS Modules 를 쓰는 소비자는 **아무것도 안 해도** 덮어쓸 수 있다.
- **Tailwind 를 쓴다면 한 줄이 필요하다.** `tx` 는 preflight(`base`) 뒤, 유틸리티 앞이어야 한다.
  앞에 두면 preflight 가 버튼 배경·여백을 지우고, 뒤에 두면 `className` 이 안 먹는다.

  ```css
  @layer theme, base, tx, components, utilities;

  @import "tailwindcss";
  @import "@txstack/ui/styles.css";
  ```

### 4. `TxTheme` 은 폐기됐다

`TxClassBase` 같은 Tailwind 클래스 문자열 상수였다. 공개 API 로 두면 소비자가 그걸 받아서
할 수 있는 일이 **Tailwind 를 쓰는 것뿐**이라, "소비자가 무엇을 쓰든 상관없다" 는 전제와 어긋난다.

**이식 시 `TxTheme` 을 참조하는 컴포넌트는 그 참조를 CSS + 토큰으로 바꾼 뒤에 가져온다.**
`TxTheme` 자체는 새 저장소로 옮기지 않는다.

## 이식 시 반드시 걷어낼 것

각 컴포넌트를 열 때 이것부터 확인한다.

- **`TxTheme` / Tailwind 클래스 문자열** — 위 4번. CSS + `--tx-*` 토큰으로 옮긴다.
- **앱 전역(ambient) 타입** — 소비자 프로젝트에는 그 전역이 없다.
- **도메인 지식** — 블랙/문자/지갑/유저타입 등. props 로 받거나 잘라낸다.
- **`import.meta.env` 직접 참조** — Vite 아닌 소비자에서 깨진다. 옵션으로 받는다.
- **다른 Tx\* 컴포넌트로의 숨은 의존** — 배럴 import 라면 순환이 생길 수 있다.
- **default export** — 배럴의 `export *` 는 default 를 실어 나르지 않는다. named 로 바꾼다.
