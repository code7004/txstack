# 005 · `apps/site`

> txstack 을 **쓰는 사람에게** 보여 주는 사이트. 배포하지 않는 앱이지만, **네 패키지의 첫 진짜 소비자**다.

| | |
| --- | --- |
| 자리 | [`apps/site/`](../apps/site) — `@txstack/site`, `private` |
| 스택 | Vite + React + react-router-dom + Tailwind v4 |
| 띄우기 | `pnpm site:dev` (6410) · `pnpm site:build` |
| 짝 | 부품 레퍼런스는 [`apps/storybook`](../apps/storybook) 이 갖는다 |

## 왜 만드는가

**둘을 겸하는 자리다.**

1. **소개** — 처음 온 사람이 따라갈 길. 스토리북은 부품 하나하나의 레퍼런스라 "무엇부터
   하지" 에 답하지 못한다
2. **검증** — `route-meta` · `hooks` · `axios` 는 테스트와 카탈로그에서만 돌았다.
   **주소창 · 새로고침 · 딥링크 · 진짜 요청**을 겪은 적이 없다. 사이트를 만드는 행위가 곧
   그 검증이다

그래서 순서를 "패키지 마저 개발 → 사이트" 가 아니라 **"사이트가 끌고 간다"** 로 잡았다.
쓰는 사람 없이 만들면 안 쓰는 것을 만든다 — `TxTable` 에서 한 번 겪었다.

## 글은 한국어, 이름은 영어

**섹션·항목 이름은 영어**(`Home` · `Start` · `Guide` · `API` …), **설명은 한국어**다.
패키지 이름과 폴더가 영어라 이름까지 한국어면 찾을 때 서로 안 맞는다.

**말하는 관점도 스토리북과 다르다.** 스토리북은 부품이 무엇을 할 수 있는지를 말하고,
여기서는 **그 부품으로 무엇을 만드는지**를 말한다.

## 구조

**가로 줄은 다섯 칸이다.** 처음에 아홉 칸으로 뒀더니 눈이 한 번에 못 읽어서, 성격이 같은
것을 묶어 아래로 내렸다. **깊이는 셋까지만** 간다.

| 가로 줄 | 그 아래 | 어느 패키지를 쓰나 |
| --- | --- | --- |
| `Home` | — | `ui` |
| `Documents` | `Getting Started` · `Guide`(`Tokens` · `Dark mode` · `Layout`) · `Components` · `Tutorial` | `ui` |
| `API` | `ui` · `route-meta` · `hooks` · `axios` | 넷 다 |
| `Example` | — | **`axios` · `hooks`** |
| `About` | `Profile` · `Contact` | `ui` |

`Contact` 를 묶음 이름으로 두면 **`Contact > Contact`** 가 되므로 `About` 이다.
`Components` 는 스토리북으로 보내는 자리다 — 부품 레퍼런스를 두 곳에서 관리하지 않는다.

라우트는 [`src/routes.tsx`](../apps/site/src/routes.tsx) 트리 하나이고, **메뉴 · 하위 메뉴 ·
현재 위치가 전부 거기서 나온다**(`@txstack/route-meta`). 없는 주소(`path: "*"`)는
`hidden` 이라 메뉴에 안 나오고 주소로만 닿는다.

**묶음마다 인덱스 화면을 트리에 선언한다**(`index: true`) — 그래서 제목(`/docs`)을 눌러도
빈 껍데기가 아니라 그 묶음의 안내가 나온다. 인덱스 라우트는 경로가 없어 **메뉴에는 오르지
않는다.** 한때 부모 화면이 `useLocation` 으로 "지금 내 자리인가" 를 따져 안내를 그렸는데,
트리에 선언하고 나니 그 분기가 사라졌다 — `route-meta` 의 `IndexRouteNode` 첫 사용이다.

## 디자인 — 포트폴리오이기도 하다

이 사이트는 **소개 · 검증 · 포트폴리오** 셋을 겸한다. 그래서 겉모습이 기능만큼 중요한데,
여기엔 우리한테 유리한 점이 하나 있다 — **디자인 자체가 라이브러리의 증거가 된다.**

**부품 CSS 를 한 줄도 덮지 않는다.** 겉모습은 [`src/theme.css`](../apps/site/src/theme.css) 에서
`--tx-*` 토큰을 다시 정의해 만든다. 부품 클래스(`.tx-button` 등)에 손대고 싶어지는 순간이
오면 **토큰이 부족하다는 신호**로 읽고 그쪽을 고친다.

| 무엇 | 정한 것 | 왜 |
| --- | --- | --- |
| 톤 | **개발자 도구** — 저채도 바탕 · 얇은 선 · 조밀한 간격 · 모노스페이스 억양 | 라이브러리 사이트라는 정체와 맞고, 부품이 많은 화면에서 안 지친다 |
| 브랜드 색 | **청록**(`#0f766e` / 다크 `#2dd4bf`) | 기본 파랑과 거리가 있어 기억에 남는다. 다크에서 밝은 쪽으로 뒤집어야 명암비가 선다 |
| 글꼴 | **Pretendard**(본문) + 시스템 모노 | 한글·라틴이 한 가족으로 돈다. 제목용 글꼴을 따로 두지 않아 무게를 아낀다 |
| 반경 | `0.375rem` | 둥글수록 소비자 앱, 각질수록 도구다 |
| 본문 폭 | `68ch` | 넓은 화면에서 한 줄이 길면 눈이 줄을 놓친다 |

**코드가 읽히는 것이 문서의 절반이다.** `prism-react-renderer` 로 하이라이팅하고, 복사는
`TxCopyButton` 이 한다 — 코드 판은 라이트·다크 어느 쪽에서도 같은 어두운 색이다(터미널이 그렇다).

**맨 아래 줄은 셸의 `footer` 슬롯**을 쓴다. 셸이 자리와 경계선을 주고 배치는 사이트가 정한다.

## 내용을 쓰는 방식

**보여 주고 나서 설명한다.** 문서 사이트의 예제가 그림이면 읽는 사람이 믿지 않는다 —
그래서 각 장의 예제는 그 페이지 안에서 실제로 돈다.

| 장 | 살아 있는 것 |
| --- | --- |
| `Tokens` | 색·반경·상태 비율을 **직접 돌리는 판.** 그 판에만 변수를 얹어 사이트의 나머지는 그대로다 |
| `Dark mode` | **같은 마크업 두 판**을 나란히 — 오른쪽만 `class="dark"` 다 |
| `Layout` | 작은 `TxAppShell` 하나. ☰ 로 접으면 자리까지 함께 줄어든다 |
| `Tutorial` | 다섯 단계를 지나 **검색·등록·삭제 확인·알림이 붙은 화면**이 완성된다 |

**부품 레퍼런스는 여기서 다시 쓰지 않는다.** props 표와 부품별 이야기는 스토리북이 갖고,
사이트는 "그것으로 무엇을 만드나" 만 말한다.

## 만들며 드러난 것

**이 목록이 사이트를 먼저 만드는 이유다.** 카탈로그에서는 안 보이던 것들이다.

| 무엇 | 어디서 드러났나 | 지금 |
| --- | --- | --- |
| **페이지 바탕색을 앱이 칠해야 한다** | 시스템이 다크인 채로 라이트로 바꾸니 **본문만 검게 남았다** — 라이브러리는 페이지 바탕 토큰을 내보내지 않는다 | 사이트가 `html` 에 칠하고 `color-scheme` 도 맞춘다. `--tx-color-bg` 같은 토큰을 낼지는 **열린 질문** |
| **`TxButton` 에 `as` 가 없다** | 404 화면에서 "Home 으로" 를 버튼 모양 링크로 두려다 | 지금은 그냥 링크로 뒀다. `TxNavBar.Item` · `TxSideNav.Item` 은 `as` 를 갖는데 버튼만 없다 |
| **React 사본이 둘이 될 뻔했다** | 패키지를 소스로 이으면 그 소스의 `react` 는 pnpm 이 패키지 쪽 `node_modules` 에서 찾는다 | `vite.config.ts` 에 `resolve.dedupe` 를 준다 — 소스 별칭을 쓰는 모노레포의 필수 한 줄 |
| 셸의 `left` 는 여백을 정하지 않는다 | 왼쪽 줄이 벽에 붙었다 | 소비자가 `className="p-3"` 로 준다 — **의도된 동작**이라 그대로 두고 여기 적는다 |
| **`TxSideNav` 에서 자식을 가진 항목은 링크가 아니다** | `Documents › Guide` 를 왼쪽 줄에서 누를 수 없다(펼치기만 한다) | 그 화면으로 가는 길은 **가로 줄의 제목 링크**와 `Documents` 인덱스 카드가 맡는다. 세로 줄도 같은 모양(링크 + `▾`)으로 열지는 **열린 질문** |
| **`TxNavBar` 가 `panel` 있는 항목의 `as`·`to` 를 버렸다** | 가로 줄의 `Documents` 를 눌러도 패널만 열리고 이동하지 않았다 | **고쳤다.** `panel` + `as` 면 제목이 링크가 되고 옆의 `▾` 버튼이 패널을 연다 — [048_TxNavBar](001_ui/048_TxNavBar.md) |

## 정한 것

- **소스에 별칭을 건다.** `@txstack/*` 를 `dist` 가 아니라 소스로 잇는다(스토리북과 같은 방식) —
  패키지를 고치면 사이트에 바로 반영돼야 검증이 된다
- **`BrowserRouter` 다.** 카탈로그의 `MemoryRouter` 와 달리 주소창을 실제로 쓴다.
  하위 경로 배포를 위해 `basename={import.meta.env.BASE_URL}` 을 준다
- **데이터는 공개 API 를 쓴다.** 백엔드를 두지 않고도 진짜 요청·에러·지연을 겪는다
- **부품 문서를 사이트로 옮겨 오지 않는다.** `Components` 는 스토리북으로 보낸다 —
  같은 내용을 두 곳에서 관리하면 반드시 어긋난다
