# txstack 로드맵

> **여기가 진입점이다.** 무엇을 할 차례인지는 이 문서에서 찾고, 상세는 각 트랙 문서로 들어간다.
> 최종 갱신: 2026-08-19

## 원칙

1. **배포는 최하위 우선순위다.** 되돌릴 수 없으므로, 되돌릴 수 있는 동안 최대한 다듬는다.
2. **패키지 단위로 완성해 나간다.** 4개 패키지를 조금씩 동시에 올리지 않고, 한 트랙씩 끝낸다.
3. **job 은 30분~1시간 단위다.** 한 번에 하나를 끝내고 커밋할 수 있어야 한다.
4. 담당 표기 — 🧑 사용자 직접 · 🤖 Claude · 🤝 함께

### 하위 트랙의 뜻 (공통 패턴)

| 단계          | 질문                                  | 끝났다고 보는 기준                                        |
| ------------- | ------------------------------------- | --------------------------------------------------------- |
| **-1 기본**   | 이 패키지가 **올바른가**              | 알려진 결함 0건, 공개 API 가 일관되고, 회귀 테스트가 있다 |
| **-2 문서**   | 이 패키지를 **남이 쓸 수 있는가**     | props/옵션이 문서에서 보이고, 예제가 복붙 가능하다        |
| **-3 고도화** | 이 패키지가 **범용 라이브러리다운가** | 도메인 잔재·앱 가정이 없고, 확장점이 열려 있다            |

## 권장 진행 순서

```
1-1 (ui 기본)  →  1-2 (ui 카탈로그)  →  0-1 (테스트·CI)
     →  4-1 · 4-2 (network)  →  2-1 · 2-2 (hooks)  →  3-1 · 3-2 (route-meta)
     →  0-2 (규약 문서)  →  각 트랙 -3 (고도화)  →  9 (배포)
```

`@txstack/ui` 를 먼저 두는 이유 — 27종으로 가장 크고, 나머지 셋을 합친 것보다 표면적이 넓다.
여기서 나오는 규약(테마·props 이름·문서 형식)이 나머지 패키지의 기준이 된다.

## 문서 규칙

- 트랙 요구사항: `docs/requirements/<트랙번호>_*.md` — 무엇을/왜, 수용 기준
- 하위 트랙 계획: `docs/plans/<트랙번호+n>_*.md` — job 목록(30분~1시간 단위)
- 검증: `docs/verification/<같은 번호>_*.md` — 수행 결과
- job 은 **끝내면 계획 문서의 체크박스를 갱신한다.** 진행 상황은 이 로드맵이 아니라 각 계획 문서가 정본이다.
