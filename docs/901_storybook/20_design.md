## 1. 스토리 이름 — **영어 PascalCase**

```tsx
export const Playground: Story = { … };
export const Basic: Story = { … };
export const InForm: Story = { … }; // Storybook 이 "In Form" 으로 띄워 보여준다
```

| 규칙                     | 이유                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| **영어 PascalCase**      | 사이드바 정렬·검색이 예측 가능해진다                               |
| 밑줄 대신 PascalCase     | Storybook 이 대문자 앞에서 자동으로 띄운다. `In_form` 은 필요 없다 |
| 한 단어로 되면 한 단어로 | `Size` · `Color` · `Loading`                                       |

**설명 문구는 한국어다.** 바꾸는 것은 **이름뿐**이다.

> 스토리 이름은 **URL 에 들어간다** (`?path=/story/feedback-txspinner--playground`).
> 링크를 주고받는 자리라 한글이 퍼센트 인코딩으로 깨지고, 나중에 바꾸면 링크가 죽는다.

흔한 이름은 아래로 통일한다. **같은 뜻에 두 이름을 두지 않는다.**

| 이름             | 무엇                                           |
| ---------------- | ---------------------------------------------- |
| `Playground`     | 컨트롤이 살아 있는 스토리. **컴포넌트당 하나** |
| `Basic`          | 아무 prop 도 주지 않은 상태                    |
| `Size` · `Color` | 크기·색 비교                                   |
| `Variant`        | 변종 나열                                      |
| `Loading`        | 로딩 상태                                      |
| `Disabled`       | 비활성 상태                                    |
| `InForm`         | 폼 안에서의 동작                               |
| `Customizing…`   | 커스터마이징 경로별. 경로가 둘이면 둘로 나눈다 |

### 그룹(`title`)은 여기서 정하지 않는다

`Feedback/TxSpinner` 같은 그룹 체계는 `901-01` 이 소유한다. 지금은 **기존 관행을 따른다.**

## 2. 문구는 **쓰는 사람** 에게 쓴다

Storybook 은 **이 컴포넌트를 쓰려고 온 사람**이 보는 자리다.
만든 사람의 이야기가 섞이면 읽는 사람은 자기에게 필요 없는 문장을 걸러내며 읽어야 한다.

### 쓰지 않는 것

| 쓰지 않는 것               | 예 (실제로 있었던 문장)                                 | 어디에 적나                    |
| -------------------------- | ------------------------------------------------------- | ------------------------------ |
| **결함 ID·차수**           | "1차에서 `size` 가 무시되던 결함(D1)이 여기서 막힌다"   | `001_ui/components/*.md`       |
| **설계 근거**              | "라이브러리 CSS 는 크기를 선언하지 않는다"              | `001_ui/20_design.md`          |
| **내부 사실**              | "이게 이 컴포넌트의 유일한 토큰이다"                    | 명세 문서                      |
| **"소비자" 라는 3인칭**    | "소비자가 무슨 방식으로 쓰든 통한다"                    | — (읽는 사람이 그 소비자다)    |
| **홍보·주장**              | "그쪽도 그대로 통한다" · "이게 이 전환으로 얻은 것이다" | —                              |
| **안 해도 되는 일의 설명** | "`className` 으로 갈아끼울 필요가 없다"                 | —                              |
| **구현 트리비아**          | "TxButton 은 내부에서 `decorative` 로 쓴다"             | 필요하면 "이 경우다" 로 바꾼다 |

### 쓰는 것

- **무엇을 하면 무엇이 되는가.** 그게 전부다
- **실제로 걸려 넘어지는 것**은 적는다 — `size="w-6"` 처럼 클래스를 주면 무효인 것 같은 함정
- 이 컴포넌트가 **안 하는 일**은 한 줄로. 어느 컴포넌트를 대신 쓸지까지 (`TxLoading` 을 쓴다)

### 강조는 아껴 쓴다

**줄마다 굵은 글씨가 붙어 있으면 아무것도 강조되지 않는다.** 기계가 쓴 것처럼 읽히는 원인이기도 하다.
`**` 는 **함정 하나당 하나** 정도로 둔다.

## 3. 컴포넌트 설명(`docs.description.component`) 구조

**순서를 고정한다.** 읽는 사람이 필요한 것을 항상 같은 자리에서 찾게 한다.

````tsx
component: [
  "로딩 중임을 알리는 회전 아이콘. 글자 옆이나 버튼 안에 넣는다.", // ① 한 줄 정의
  "",
  "```tsx", // ② 설치·최소 사용
  'import { TxSpinner } from "@txstack/ui";',
  'import "@txstack/ui/styles.css"; // 앱에서 한 번',
  "",
  "<TxSpinner />;",
  "```",
  "",
  "크기와 색은 놓인 자리의 글자를 따라간다. 대부분은 아무것도 주지 않으면 된다.", // ③ 기본 동작
  "",
  "- `size` 에는 CSS 길이나 number(px) 를 준다. …", // ④ 손잡이·함정
  "",
  "문구·오버레이가 필요하면 `TxLoading` 을 쓴다.", // ⑤ 안 하는 일
  "",
  "컨트롤 패널은 `Playground` 에서만 동작한다. 나머지는 비교용이다." // ⑥ 이 카탈로그 사용법
].join("\n");
````

| 순서 | 무엇               | 길이      |
| ---- | ------------------ | --------- |
| ①    | 한 줄 정의         | 한 문장   |
| ②    | import + 최소 사용 | 코드블록  |
| ③    | 기본 동작          | 한두 문장 |
| ④    | 손잡이·함정        | 불릿 3~5  |
| ⑤    | 안 하는 일 · 대체  | 한 줄     |
| ⑥    | 컨트롤 안내        | 한 줄     |

- **`import "@txstack/ui/styles.css"` 는 매번 적는다.** 빠뜨리면 스타일이 하나도 안 나오고,
  증상이 원인을 안 가리킨다. 카탈로그의 첫 화면이 그걸 막는 자리다
- 명세 문서 경로(`docs/001_ui/components/*.md`)는 **적지 않는다.** 소비자에게는 없는 파일이다

### 스토리 설명은 "무엇을 보는지" 를 적는다

```tsx
/**
 * 크기는 두 가지로 정한다. `size` 를 주거나, 놓인 자리의 `font-size` 에 맡기거나.
 *
 * 윗줄은 셋 다 `<TxSpinner />` 이고 부모의 글자 크기만 다르다.
 */
```

두 번째 문단이 **이 화면에서 무엇을 봐야 하는지**를 말한다. 이게 없으면 그림만 남는다.

## 4. 손잡이는 살아 있어야 한다

**컨트롤을 두면 그 값이 실제로 먹혀야 한다.** 안 먹히는 손잡이는 없는 것보다 나쁘다 —
쓰는 사람이 컴포넌트가 고장난 걸로 오해한다. 파일럿에서 이 실패를 두 번 겪었다.

| 실패                                     | 증상                                  | 대응                                          |
| ---------------------------------------- | ------------------------------------- | --------------------------------------------- |
| `render: () => …` 로 args 를 무시        | 컨트롤을 돌려도 아무 일도 안 일어난다 | `Playground` 는 `render: (args) => …` 로 쓴다 |
| 비교용 스토리에 컨트롤이 켜져 있음       | 위와 같음                             | `parameters: { controls: { disable: true } }` |
| 타이핑한 Tailwind 클래스가 생성되지 않음 | **가끔 먹혀서** 고장난 줄도 모른다    | 아래 안전목록                                 |

```tsx
/** 컨트롤을 받지 않는 비교용 스토리에 붙인다. */
const noControls = { controls: { disable: true } };
```

### Tailwind 자유입력 컨트롤

Tailwind 는 빌드 때 소스 파일을 훑어 **거기 쓰인 클래스만** 만든다.
컨트롤에 런타임에 타이핑한 문자열은 어느 파일에도 없으므로 원칙적으로 생성되지 않는다.
`text-red-500` 은 먹히고 `text-red-400` 은 안 먹히는 일이 그래서 생긴다 —
**다른 컴포넌트 소스에 우연히 그 글자가 있느냐**의 차이일 뿐이다.

`apps/storybook/src/tailwind.css` 의 `@source inline(…)` 안전목록이 이걸 막는다.
**Storybook 앱만의 장치이고 배포물과 무관하다.** 색 팔레트를 늘려야 하면 거기에 추가한다.

### 눈에 안 보이는 prop 은 화면에 드러낸다

`decorative` · `aria-label` 처럼 시각적 결과가 없는 prop 은 컨트롤을 돌려도 확인이 안 된다.
스토리 안에 **읽히는 내용을 그대로 출력**한다.

```tsx
<p className="text-xs text-slate-500">스크린리더: {args.decorative ? "안내하지 않음 (aria-hidden)" : `"${args["aria-label"]}" 로 안내`}</p>
```

### CSS 변수는 스토리가 없으면 없는 기능이다

`--tx-*` 토큰은 autodocs props 표에 안 나온다. **토큰을 가진 컴포넌트는 토큰 스토리를 하나 갖는다.**
스토리에서는 인라인으로 주더라도, 설명에는 **실제 사용법(CSS 한 곳)** 을 적는다.
