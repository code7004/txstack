# 901 — Storybook

> **한 줄 정의**: `001 @txstack/ui` 의 **가이드**를 제공한다.

## 왜 만드는가

컴포넌트 라이브러리에서 "쉬운 사용법"은 문장으로 증명되지 않는다. **눈으로 보고 만져봐야** 증명된다.
Storybook 은 두 역할을 겸한다.

1. **소비자용 가이드** — 어떤 컴포넌트가 있고, props 를 바꾸면 어떻게 변하는지
2. **개발용 작업대** — 앱을 띄우지 않고 컴포넌트 하나만 격리해서 만들고 확인

두 번째가 첫 번째보다 먼저 온다. **작업대로 쓰이지 않는 Storybook 은 금방 낡는다.**

## 현재 코드 자산

- `apps/storybook/` (private, 배포하지 않음) — Storybook 10 + `@storybook/react-vite`
- `pnpm storybook:dev` (:6310) / `pnpm storybook:build`
- 스토리는 컴포넌트 폴더 안에 `*.stories.tsx` 로 둔다 — 일부 컴포넌트에만 존재
- `@storybook/addon-docs` 설치됨

## 상태

**미착수.** 문서 없음. 스토리 커버리지가 26종 중 일부뿐이다.

## 의존 관계

**`001` 의 커스터마이징 방식이 정해지기 전에는 스토리 양식을 확정할 수 없다.**
props 로 커스터마이징하는지, theme 객체로 하는지에 따라 스토리에서 보여줄 것이 달라진다.

→ `001_ui/20_design.md` 합의 후에 본격 진행한다. 그 전에는 요구사항만 정리한다.

## 컴포넌트 플로우에서의 위치

이 트랙은 **`S4` 단계의 양식을 소유**한다 → [06_COMPONENT_FLOW.md](../00_foundation/06_COMPONENT_FLOW.md)

- 컴포넌트별 스토리는 이 트랙에서 한꺼번에 만들지 않는다. **각 컴포넌트의 S4 에서 만든다**
- 내용의 원본은 `001_ui/components/<Name>.md` (S1) 다. 스토리는 그것을 실행 가능하게 보여줄 뿐이다
- 파일럿 1차(`TxSpinner`)에서 **스토리 양식의 최소 골격을 만들고**, 그것을 `20_design.md` 로 승격한다
