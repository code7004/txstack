# 4-3. `@txstack/network` 고도화

- 요구사항: [400 @txstack/network](../requirements/400_network_library.md) — N5
- 선행: 4-1 · 4-2
- 상태: 대기

## 목표

실전 기능의 **범위를 정한다.** 넣을 것과 안 넣을 것을 근거와 함께 확정하는 것이 목표이지,
전부 구현하는 것이 목표가 아니다.

| ----- | -------------------------------------------- | ---- | -------------------------------------------------------------------- |
| N3-01 | 재시도(retry) 지원 여부 판단                 | 🤝   | 넣으면 옵션 형태를, 안 넣으면 "소비자가 인터셉터로" 를 문서에 남긴다 |

## 검증

- `pnpm check`
- 결정 사항이 전부 문서에 남았는지 확인 — 이 트랙은 **코드보다 결정이 산출물**이다
- 결과는 `docs/verification/403_*.md`

## 비고

이 트랙의 판단 기준은 하나다 — **런타임 정책을 패키지가 결정하는가.**
결정하게 되면 옵션으로 뒤집을 수 있는지 보고, 못 뒤집으면 넣지 않는다.
`N3-04`(토큰 갱신)가 대표적으로 위험하다. 편하지만 앱의 인증 흐름을 라이브러리가 규정하게 된다.
