# 2-2. `@txstack/hooks` 문서

- 요구사항: [200 @txstack/hooks](../requirements/200_hooks_library.md) — H3
- 상태: 대기

## 목표

훅을 남이 쓸 수 있게 만든다. **훅은 Storybook 에 컴포넌트로 올릴 수 없어서** 문서 수단을 따로 정해야 한다.

## job

| ID    | job                                          | 담당 | 완료 기준                                                       |
| ----- | -------------------------------------------- | ---- | --------------------------------------------------------------- |
| H2-01 | 훅 문서 수단 결정                            | 🤝   | Storybook MDX / playground 화면 / README 중 택일. 근거를 남긴다 |
| H2-02 | `useUrlQuery` 문서 — 옵션표·타입 변환·주의점 | 🤖   | `defaults` 가 키 집합을 정한다는 점이 명시된다                  |
| H2-03 | `useStateForObject` 문서                     | 🤖   | `postParse` 가 초기값에도 적용된다는 점이 예제로 있다           |
| H2-04 | `useSafePolling` 문서                        | 🤖   | 스킵 가드 동작(느린 작업 시 tick 건너뜀)이 설명된다             |
| H2-05 | `useObjectChanged` 문서                      | 🤖   | 마운트 시 호출 안 함 · 얕은 비교가 명시된다                     |
| H2-06 | README 예제를 실제로 실행해 검증             | 🤖   | 복붙해서 도는지 확인. 안 도는 예제 0건                          |
| H2-07 | 서브패스 분리 이유 문서화                    | 🤖   | 왜 `useUrlQuery` 만 `/router` 에 있는지 소비자가 이해한다       |

## 검증

README 예제를 소비자 픽스처(`0-3`)에 넣어 **타입 인자 없이** 컴파일되는지 본다.

## 비고

`H2-01` 은 형식보다 **유지 비용**으로 판단한다. 문서와 코드가 갈라지지 않는 수단이 우선이다.
Storybook MDX 는 자동 생성이 안 되고, playground 화면은 실제로 동작하지만 props 표가 없다.
