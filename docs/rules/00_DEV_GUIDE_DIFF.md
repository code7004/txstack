# 00. dev-guide 와 다른 점

> 언제 보나: dev-guide 의 규칙이 이 저장소에서 그대로인지 확인할 때.

적용 버전: `@txstack/dev-guide` 0.4.1 (워크스페이스 — 이 저장소가 dev-guide 를 만든다). **여기 없는 것은 dev-guide 그대로다.**

| dev-guide 규칙                                                                                                   | 이 저장소                                                                                                          | 이유 · 결정                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| docs 여섯 칸 — `project · rules · requirements · plans · verification · reports` (process/docs-structure.md 1장) | 패키지 번호 폴더 `docs/00X_<패키지>/` (컴포넌트 · API 마다 한 장) + 상시 문서 `docs/NNN_*.md` · `reports/`         | 라이브러리 저장소라 문서의 단위가 작업이 아니라 공개 API 다. 소비자 AI 가이드가 이 폴더를 그대로 묶어 싣는다 |
| 지금 상태는 `CURRENT.md` (process/docs-structure.md 3장)                                                         | `docs/README.md` 의 진행 표가 갖는다                                                                               | 이식 단계부터 그 자리였다. 두 곳에 두면 갈라진다                                                             |
| 요구사항 → 계획 → 구현 → 검증 → 보고 (process/workflow.md)                                                       | 컴포넌트 하나를 이식 순서(S1 문서 → S2 구현 → S3 테스트 → S4 스토리 → 사용자 확인)로 끝까지 관통한다 — `CLAUDE.md` | 공개 API 를 예제 코드로 먼저 합의하는 것이 계획 문서의 몫을 한다                                             |
