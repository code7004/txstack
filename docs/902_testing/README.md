# 902 — Vitest / 테스트 방향

> **한 줄 정의**: **안정화된 테스트 방향**을 제시한다.

## 왜 만드는가

라이브러리는 앱과 다르다. **소비자가 우리 코드를 신뢰할 근거가 테스트뿐**이다.
동시에, 라이브러리 테스트는 쉽게 과잉이 된다 — 구현 세부를 테스트하면 리팩터링마다 테스트가 깨지고,
그러면 테스트를 지우게 된다.

그래서 이 트랙의 목표는 "커버리지 숫자"가 아니라 **"무엇을 테스트하고 무엇을 테스트하지 않는지에 대한 합의"** 다.

## 현재 코드 자산

- vitest `^3`, 설정은 루트 `vitest.config.ts` 가 소유
- 패키지별로 환경이 갈린다 — `network` 는 node, React 가 붙은 것은 jsdom
- `@testing-library/react` · `@testing-library/dom` · `jsdom` 설치됨
- 테스트 파일 **4개** (패키지당 1개)

| 파일                                    | 대상            |
| --------------------------------------- | --------------- |
| `packages/ui/src/tx-ui.utils.test.ts`   | ui 유틸만       |
| `packages/hooks/src/hooks.test.tsx`     | 훅              |
| `packages/route-meta/src/utils.test.ts` | route-meta 유틸 |
| `packages/network/src/client.test.ts`   | client          |

**컴포넌트 자체를 렌더링해서 검증하는 테스트는 없다.**

## 상태

**미착수.** 문서 없음.

## 컴포넌트 플로우에서의 위치

이 트랙은 **`S3` 단계의 양식을 소유**한다 → [06_COMPONENT_FLOW.md](../00_foundation/06_COMPONENT_FLOW.md)

- 테스트를 이 트랙에서 몰아 쓰지 않는다. **각 컴포넌트·기능의 S3 에서 쓴다**
- S1 명세에 적힌 "결함 목록" 이 그대로 회귀 테스트 항목이 된다. **고친 결함은 테스트로 못박는다**
- 파일럿 1차(`TxSpinner`)에서 **테스트 양식의 최소 골격을 만들고**, 그것을 `20_design.md` 로 승격한다
