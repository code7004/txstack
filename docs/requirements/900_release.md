# 900. 배포 (트랙 9)

- 로드맵: [ROADMAP](../ROADMAP.md)
- 하위 트랙: [9-1 사전 점검](../plans/901_release_preflight.md) · [9-2 알파 배포](../plans/902_release_alpha.md) · [9-3 역이식](../plans/903_backport.md)

## 배경 / 목적

npm 공개 registry 에 4종을 배포한다. **의도적으로 최하위 우선순위다.**

`npm publish` 는 되돌릴 수 없다. 같은 버전 번호를 다시 쓸 수 없고, unpublish 는 72시간 제한과
의존 파괴 문제가 있다. 되돌릴 수 있는 동안(= 배포 전) 최대한 다듬는 것이 트랙 0~4 의 목적이고,
이 트랙은 **그것이 끝난 뒤에** 연다.

## 요구사항 (수용 기준)

| ID  | 요구사항                   | 수용 기준                                                                |
| --- | -------------------------- | ------------------------------------------------------------------------ |
| P1  | 배포 전 관문을 통과한다    | 트랙 0~4 의 `-1`·`-2` 하위 트랙이 전부 닫혀 있다                         |
| P2  | scope 를 확보한다          | npmjs.com 에 org(또는 사용자명) `txstack` 이 있다                        |
| P3  | 알파로 시작한다            | `0.1.0-alpha.x` 를 `alpha` 태그로 배포한다. `latest` 를 건드리지 않는다  |
| P4  | 실제 설치가 동작한다       | 빈 프로젝트에서 npm 설치 후 빌드·타입체크가 통과한다                     |
| P5  | 원본 3개 저장소가 소비한다 | 최소 1개 저장소에서 `src/core` 삭제 후 빌드·타입체크 통과 (요구사항 002) |

## 영향 범위

- 외부: npm registry (**되돌릴 수 없음**)
- `packages/*/package.json` 의 version·CHANGELOG
- 9-3 에서만 원본 3개 저장소

## 제약 / 비고

- **`npm publish` 는 사용자가 명시적으로 요청할 때만 실행한다.** Claude 가 스스로 하지 않는다.
- scope 패키지이므로 `--access public` 이 필요하다.
- `@txstack` scope 가 선점돼 있으면 **패키지명 4개와 모든 문서의 import 예제가 바뀐다.** 9-1 에서 가장 먼저 확인한다.
- 9-3(역이식)은 **원본 저장소가 있는 PC 에서만 가능하다.**
