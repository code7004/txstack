## 배경 / 목적

라우트 정의 하나(`RouteTree`)에서 **라우터 · GNB 메뉴 · 현재 라우트 매칭**을 함께 파생시킨다.
같은 경로가 라우터 설정·메뉴 배열·링크에 흩어져 어긋나는 문제를 없애는 것이 목적이다.

네 패키지 중 **가장 의견이 강한(opinionated) 패키지**다. 정책이 코드에 박혀 있다:

- 모든 `RouteNode` 가 `path` 를 명시해야 한다.
- React Router 의 index route 를 의도적으로 쓰지 않는다.
- 권한 필터가 **문자열 하나**(`permission?: string`)만 받는다.

이 정책들이 범용 라이브러리로서 타당한지 재검토가 필요하다.

## 요구사항 (수용 기준)

| ID  | 요구사항                       | 수용 기준                                                               |
| --- | ------------------------------ | ----------------------------------------------------------------------- |
| R1  | 두 계층의 필터 규칙이 명확하다 | 실행(Router)과 네비게이션(GNB)의 차이가 문서와 테스트에 있다 (**완료**) |
| R2  | 정책이 문서화되고 근거가 있다  | index route 미사용·절대경로 강제의 이유가 문서에 있다                   |
| R3  | 권한 모델이 실제 쓰임에 맞다   | 다중 권한/역할 조합을 다룰 수 있거나, 못 다루는 이유가 문서에 있다      |
| R4  | 사용법을 문서에서 볼 수 있다   | RouteTree → 라우터 → 메뉴 파생 흐름이 예제로 있다                       |
| R5  | 도메인 가정이 없다             | 특정 앱의 메뉴 구조·권한 문자열에 기대지 않는다                         |

## 영향 범위

- `packages/route-meta` 전체
- `apps/playground` 의 메뉴·라우팅 전체 (이 패키지가 playground 골격을 만든다)
- 배포물: 정책 변경은 대체로 breaking 이다

## 제약 / 비고

- `react-router-dom` 은 **필수 peer** 다. 이 패키지의 존재 이유가 React Router 와의 결합이다.
- README 가 존댓말·`@txstack/` 접두 없는 제목 등 다른 패키지와 문체가 다르다 (3-2 에서 정리).
