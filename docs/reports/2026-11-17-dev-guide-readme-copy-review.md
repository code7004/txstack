# dev-guide README·사이트 소개 문구 수정안

기준일: 2026-11-17. 상태: 문구 제안 — **같은 날 README · 사이트 · `llms.txt` · 차이점 템플릿에 반영했다.**
코드 블록과 AI 지침 문단(명령형)은 이 보고서의 주의대로 그대로 두었다. npm 에는 다음 `dev-guide` 배포 때 실린다.

## 1. 검토 결론

`@txstack/dev-guide`는 프로젝트의 개발 규칙과 문서 작성 절차를 공유하는 패키지다.
현재 README는 내용보다 표현이 내부 작업 메모에 가깝다. npm에서 처음 보는 독자가
‘무엇을 제공하고 어디에 쓰는가’를 이해하도록 소개와 절차의 문장을 다듬는 것이 좋다.

비교한 문서:

- [ui README](../../packages/ui/README.md): 관리자 화면에 필요한 컴포넌트와 사용 편의성을 먼저 설명
- [axios README](../../packages/axios/README.md): 앱마다 다른 인증·응답 정책이라는 문제와 해결 방식 설명
- [fns README](../../packages/fns/README.md): 반복 작성하는 함수의 구체적인 예를 먼저 제시
- [hooks README](../../packages/hooks/README.md)·[route-meta README](../../packages/route-meta/README.md): 기능·사용법 중심 소개
- [dev-guide README](../../packages/dev-guide/README.md)·[사이트 DevGuide](../../apps/site/src/pages/DevGuide.tsx)

**정책이나 기능을 바꾸는 작업이 아니다.** 일반 사용자에게 노출되는 문장을 다른 패키지와 같은
‘습니다’체로 맞추고, 규칙 공유의 목적과 도입 방법을 설명한다.

## 2. 문장 수정 기준

- 첫 문장은 구호보다 패키지가 제공하는 것을 구체적으로 설명한다.
- ‘따른다’는 실제 AI 지침·규칙 문서에서 유지하되, 제품 소개의 핵심 표현으로 반복하지 않는다.
- ‘판’은 ‘버전’, ‘굴리다’는 ‘개발·관리하다’, ‘붙이다’는 맥락에 따라 ‘적용하다·추가하다’로 쓴다.
- 명사만 나열하거나 대시로 연결하기보다, 주어와 서술어가 있는 문장으로 설명한다.
- ‘설치만 하면 자동 적용된다’거나 ‘모든 프로젝트에 필수’라는 인상을 주지 않는다.
  설치 후 프로젝트 지침 연결과 정보 입력이 필요하다.
- 파일명·명령·버전 정책·예외 문서의 역할은 그대로 유지한다.
- 일반 소개와 복사할 AI 지침의 문체를 구분한다. AI 지침을 무조건 홍보 문체로 바꾸지 않는다.

## 3. README 첫 소개 — 교체 초안

```md
# @txstack/dev-guide

프로젝트마다 반복해서 정리하던 개발 규칙과 문서 양식을 한곳에 모은 패키지입니다.
실행 스크립트 이름, 코드 작성, 커밋 규칙과 함께 요구사항 정리부터 계획·구현·검증·보고까지
이어지는 작업 절차를 제공합니다.

새 프로젝트를 시작하거나 여러 저장소의 개발 기준을 맞출 때 사용할 수 있습니다.
공통 규칙은 설치된 패키지에서 확인하고, 프로젝트별로 다르게 적용하는 내용만 별도 문서에 기록합니다.
Claude Code나 Codex 같은 AI 코딩 도구에도 같은 기준을 안내할 수 있습니다.

마크다운 문서와 템플릿으로 구성되어 있으며, 런타임 코드나 의존성은 없습니다.
```

현재 첫 문장의 ‘참고한다가 아니라 따른다’는 사용자 이점보다 사용 태도를 강조한다.
위 초안은 제공 기능 → 사용 상황 → 공유 방법 → 패키지 형태 순서로 바꾼 것이다.

업데이트 안내의 ‘설치된 CHANGELOG’는 업데이트 전 설치본에 새 버전 기록이 없을 수 있다.
**업데이트 전에 저장소의 새 버전 변경 내역을 확인하고, 설치 후 해당 버전 문서를 확인한다**고
순서를 구분하면 정확하다. 문체 외에 의미를 보완해야 하는 부분이다.

예시:

> 업데이트할 버전의 CHANGELOG를 저장소에서 먼저 확인하세요. 프로젝트에 적용한 뒤에는
> 함께 설치된 CHANGELOG.md와 규칙 문서를 기준으로 변경 사항을 점검합니다.

## 5. 사이트 Dev Guide 문구 수정안

사이트는 README 전체를 렌더링하지 않는다. 코드 블록은 README에서 가져오지만 소개·설명·업데이트
문장은 [DevGuide.tsx](../../apps/site/src/pages/DevGuide.tsx)에 별도로 있어 함께 수정해야 한다.

### 페이지 소개(lead)

원문:

> 프로젝트를 굴리는 규칙입니다 — 실행 스크립트 이름, 커밋, 작업 공간, 코드, 그리고 …
> 새 프로젝트가 기존 프로젝트를 '참고' 하는 대신 이 패키지를 '따르게' 합니다.

추천:

> 프로젝트에서 공통으로 사용할 개발 규칙과 문서 템플릿을 제공합니다. 스크립트 이름과
> 코드·커밋 규칙을 정리하고, 요구사항부터 계획·구현·검증·보고까지 일관된 절차로 관리할 수 있습니다.

### AI Guide와의 구분

추천:

> Dev Guide는 프로젝트의 개발 규칙과 작업 절차를 다룹니다. @txstack/ui의 컴포넌트를
> 선택하고 사용하는 방법은 AI Guide에서 확인할 수 있습니다.

첫 화면에서 ‘쓰지 말 원시 요소’처럼 내부 규칙 용어를 설명할 필요는 없다.
‘UI를 무엇으로 짓든 모든 프로젝트에 붙입니다’는 필수 적용처럼 읽힐 수 있어 제외한다.

### 설치 설명

> 마크다운 문서와 템플릿으로 구성된 개발용 패키지입니다. 런타임 코드는 없으며,
> 설치한 버전의 규칙과 양식을 확인할 수 있습니다. 현재 사이트에서 제공하는 버전은 {VERSION}입니다.

사이트가 main 기준이라는 안내와 버전 표기를 함께 제공해 npm 최신 배포 버전으로 오해하지 않게 한다.

### 초기 설정 설명

> 저장소 루트에서 아래 명령을 실행하면 문서 폴더와 기본 파일을 생성합니다. 기존 파일은
> 덮어쓰지 않으므로, 출력된 경로를 확인하고 템플릿에서 필요한 내용을 반영하세요.

> `<…>` 표시를 프로젝트에 맞게 바꾸고, `00_DEV_GUIDE_DIFF.md`에 적용 버전을 기록하세요.
> 공통 규칙과 다르게 적용할 내용이 생기면 같은 문서에 예외와 이유를 추가합니다.

### AI 지침 설정 설명

> Claude Code는 CLAUDE.md, Codex는 AGENTS.md에서 프로젝트 지침을 확인합니다.

## 6. 적용 범위와 확인 항목

### 수정 대상

1. `packages/dev-guide/README.md` — 사용자 소개·설치·적용·업데이트·목차 설명
2. `apps/site/src/pages/DevGuide.tsx` — 별도로 작성된 사이트 설명 문구
3. `packages/dev-guide/llms.txt` — 사이트 문서 목록에 노출되는 요약
4. `apps/site/src/pages/DocsHome.tsx` — 필요하면 ‘스크립트 이름·커밋·문서 구조·작업 절차와 템플릿’으로 요약 통일

규칙 본문과 실제 AI 지침의 명령형 문체는 이번 수정에서 전면 교체하지 않는다.
`따르는 판`을 `적용 버전`으로 통일할 경우 해당 템플릿과 사이트 설명도 같은 용어로 맞춘다.

### 수정 시 주의

- `DevGuide.tsx`는 README의 명령 문자열을 검색해 코드 블록을 추출한다.
  `pnpm add`, `mkdir -p docs`, `docs/requirements/$n.md`, `## 개발 기준` 등 검색 기준을 보존한다.
- 소비자 검증도 README의 `sh` 코드 블록을 실행한다. prose 수정 때문에 코드 펜스 언어나
  초기 설정 절차를 임의로 바꾸지 않는다.
- 제목 번호를 바꾸면 앵커·테스트·사이트 추출 조건에 의존하는 부분이 있는지 확인한다.
- 문구 수정 범위라면 `scripts/dev-guide.test.ts` 검사와 사이트 타입·빌드 확인을 중심으로 검증한다.
  실제 명령을 바꿨다면 `pnpm verify:packages dev-guide`로 설치·초기 설정까지 확인한다.

### 완료 기준

- 처음 읽는 사람이 개발 규칙·작업 절차·문서 템플릿을 제공하는 패키지임을 알 수 있다.
- 다른 패키지 README와 같은 ‘습니다’체로 자연스럽게 읽힌다.
- 설치만으로 자동 적용되는 규칙이나 현재 없는 기능을 약속하지 않는다.
- README와 사이트에서 버전·템플릿·프로젝트별 예외를 같은 용어로 설명한다.
- README에서 가져오는 코드 블록·목록과 기존 초기 설정 검증이 유지된다.

이 보고서는 문구 검토 결과다. README·사이트·정책·배포 상태는 수정하지 않았다.
