# 0-3. 검증 자동화 (소비자 픽스처)

- 요구사항: [010 공통 인프라](../requirements/010_common_infra.md) — C4
- 원본: `001-2` I4
- 상태: 대기

## 목표

001 검증 §5 에서 손으로 했던 소비자 실검증을 **명령 하나**로 만든다.

이 검증이 중요한 이유는 `pnpm check` 가 잡지 못하는 것을 잡기 때문이다 — `exports` 맵 오류,
`.d.ts` 해석 실패, optional peer 가 실은 필수였던 경우, Tailwind purge. 전부 **설치해봐야** 드러난다.

## job

| ID    | job                                                 | 담당 | 완료 기준                                                  |
| ----- | --------------------------------------------------- | ---- | ---------------------------------------------------------- |
| C3-01 | pack → 임시 디렉터리 설치까지 스크립트              | 🤖   | 4종 tgz 가 빈 프로젝트에 설치된다                          |

| C3-08 | CI 편입 여부 판단                                   | 🤝   | 소요 시간을 재고, 매 push/야간 중 어디에 붙일지 정한다     |

## 검증

일부러 `packages/ui/package.json` 의 `exports` 에서 `./daypicker` 를 빼고 돌려 **실패하는지** 본다.
통과만 확인하면 검증이 실제로 뭔가 보고 있는지 알 수 없다.

## 비고

- **`npm publish` 없이 가능하다.** `npm pack` + `file:` 설치로 tarball 전개까지 동일하게 재현된다.
- 픽스처 설치는 `pnpm` 이 아니라 `npm` 으로 한다. 워크스페이스 링크와 pnpm 고유 호이스팅을 배제해야
  일반 소비자 환경이 된다.
- ⚠ 함정 — Tailwind v4 는 프로젝트 루트를 자동 스캔한다. 이전 빌드의 `dist/` 가 남아 있으면
  **그것까지 스캔해 결과가 오염된다.** 실제로 001 검증 중 겪었다.
