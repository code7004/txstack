# 3-2. `@txstack/route-meta` 문서

- 요구사항: [300 @txstack/route-meta](../requirements/300_route_meta_library.md) — R2 · R4
- 상태: 대기

## 목표

"이걸 왜 쓰는가" 를 먼저 이해시킨다. 이 패키지는 라이브러리라기보다 **패턴**이라,
API 나열보다 문제 정의가 중요하다.

## job

| ID    | job                                           | 담당 | 완료 기준                                                    |
| ----- | --------------------------------------------- | ---- | ------------------------------------------------------------ |
| R2-01 | README 제목·문체를 다른 패키지와 통일         | 🤖   | 제목이 `@txstack/route-meta` 이고 문체가 나머지 3종과 맞는다 |
| R2-02 | 문제 정의 절 작성 (같은 경로가 흩어지는 문제) | 🤖   | 이 패키지가 없을 때 무엇이 어긋나는지가 먼저 나온다          |
| R2-03 | RouteTree → 라우터 파생 예제                  | 🤖   | 복붙해서 도는 최소 예제                                      |
| R2-04 | RouteTree → GNB 메뉴 파생 예제                | 🤖   | `hidden`·`enabled`·`permissions` 필터 차이가 예제로 보인다   |
| R2-05 | 실행 계층과 네비게이션 계층의 차이 표         | 🤖   | 왜 `hidden` 라우트도 Router 에는 등록되는지 설명된다         |
| R2-06 | 정책 문서화 (3-1 결정 반영)                   | 🤖   | index route·절대경로·권한 모델의 근거가 README 에 있다       |
| R2-07 | playground `/route-meta` 화면과 문서 대조     | 🤖   | 화면 설명과 README 가 어긋나지 않는다                        |

## 검증

README 예제를 소비자 픽스처(`0-3`)에서 컴파일한다.

## 비고

`R2-05` 가 이 패키지 문서의 핵심이다. 두 계층의 필터 규칙이 다르다는 것이 설계의 요점인데,
모르면 "메뉴에 안 보이는데 URL 로는 들어가진다" 를 버그로 신고하게 된다.
