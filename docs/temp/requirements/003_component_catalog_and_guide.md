# 003. 컴포넌트 카탈로그 · 가이드 · 예제

## 배경 / 목적

`001` 로 4개 패키지를 뽑아냈고 `apps/playground` 12화면으로 실동작을 확인했다.
그러나 playground 는 **전시는 하지만 가르치지 않는다.** 화면에 컴포넌트는 떠 있는데
그것을 만든 코드가 보이지 않아 소비자가 복붙할 것이 없다.

특히 `@txstack/ui` 의 `Tx*` 27종은 **props 문서가 하나도 없다.** 어떤 prop 이 있는지 알려면
`dist/*.d.ts` 를 직접 읽어야 한다. npm 에 올렸을 때 이 상태면 아무도 쓰지 못한다.

세 가지가 각각 다른 질문에 답한다.

| 종류     | 답하는 질문                      | 현재 상태                         |
| -------- | -------------------------------- | --------------------------------- |
| 가이드   | 설치하고 첫 화면까지 어떻게 가나 | README 뿐, 화면 없음              |
| 예제     | 실제로 이렇게 조합해 쓴다        | playground 가 근사치, 코드 미노출 |
| 카탈로그 | 이 컴포넌트의 props 는 무엇인가  | **없음** — 27종 중 0개            |

## 요구사항 (수용 기준)

| ID  | 요구사항                                | 수용 기준                                                                    |
| --- | --------------------------------------- | ---------------------------------------------------------------------------- |
| R1  | 컴포넌트 카탈로그를 만든다              | `Tx*` 27종이 Storybook 에 등재되고, props 를 화면에서 조작할 수 있다         |
| R2  | props 문서가 소스와 자동으로 동기화된다 | 타입에서 argTypes/설명이 파생되어, 수동 표를 관리하지 않는다                 |
| R3  | 다크모드를 카탈로그에서 확인할 수 있다  | 툴바 토글로 라이트/다크를 전환하고, 소비자와 같은 방식(`html.dark`)으로 건다 |
| R4  | 서브패스 컴포넌트도 덮는다              | `TxAgGrid`(aggrid) · `TxDayPicker` 계열(daypicker)이 카탈로그에 포함된다     |
| R5  | 가이드 화면을 만든다                    | 설치 → Tailwind `@source` → 첫 컴포넌트까지의 경로가 화면으로 존재한다       |
| R6  | 예제에 소스 코드가 보인다               | playground 각 화면에서 그 화면을 만든 코드를 볼 수 있다                      |
| R7  | 정적 사이트로 배포 가능하다             | `storybook build` 산출물이 정적 호스팅(GitHub Pages 등)에 올라간다           |

## 역할 분담 (사용자 확정)

**분업** — 둘 다 유지하되 중복 전시를 걷어낸다.

- **Storybook** = 컴포넌트 카탈로그. 개별 컴포넌트의 props·상태·변형. `packages/ui` 전용.
- **playground** = 4개 패키지 **통합 연동** 예제 + 가이드 화면. 패키지가 서로 물리는 시나리오.

즉 "이 버튼의 variant 가 뭐가 있나" 는 Storybook 이, "route-meta 로 만든 메뉴에서 network 로
데이터를 받아 ui 로 그리는 흐름" 은 playground 가 답한다.

## 영향 범위

- **신규**: `apps/storybook` (비배포)
- **`packages/ui`**: `*.stories.tsx` 가 소스 옆에 추가된다. `dist` 와 `npm pack` 산출물에는 포함되지 않는다.
- **`apps/playground`**: R5·R6 단계에서 화면 추가·수정
- **배포**: npm 배포물에는 영향 없음. R7 에서 정적 사이트 호스팅이 새로 생긴다.

## 제약 / 비고

- 스토리는 컴포넌트 옆(`packages/ui/src/**`)에 둔다. 카탈로그가 컴포넌트와 같이 움직여야 갱신이 누락되지 않는다.
- Storybook 은 컴포넌트를 **직접** 진입점으로 삼는다. 배럴 진입에서만 통하던 코드는 여기서 깨진다
  (실제로 착수 즉시 순환 import 결함이 드러났다 — `001-2` 참고). 이는 부작용이 아니라 **검증 효과**다.
- 도구 의존(`storybook`·`@storybook/react-vite`)은 루트 devDependencies 에 둔다. vitest 와 같은 방침이다.
- 착수 순서는 **Storybook → 가이드 → 예제**. 구멍이 가장 큰 곳부터 메운다.
