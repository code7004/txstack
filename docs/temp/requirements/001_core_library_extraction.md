# 001. core 4종 범용 React 라이브러리 추출

## 배경 / 목적

`black-message`, `usertics`, `chain-wallet-service` 세 프로젝트가 각자 `src/core`(또는 `src/@core`)에
사실상 같은 코드를 **복사본으로** 들고 있다. 한쪽에서 버그를 고쳐도 나머지 두 곳에 반영되지 않아
현재 시점에도 컴포넌트별로 내용이 갈라져 있다.

이 공용 코드를 하나의 저장소로 뽑아 **npm 배포 가능한 범용 React 라이브러리**로 만든다.
이후 기존 3개 프로젝트는 복사본을 지우고 npm 의존성으로 소비한다.

## 요구사항 (수용 기준)

| ID  | 요구사항                                                  | 수용 기준                                                                                     |
| --- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| R1  | React 용 범용 라이브러리로 만든다                         | 특정 서비스 도메인(블랙/문자/지갑) 지식이 코드에 남아 있지 않다                               |
| R2  | `apps/frontend/src/core` 의 패키지들을 포함한다           | hooks / tx-ui / route-meta / network 4종이 모두 이관된다                                      |
| R3  | 세 저장소 중 **가장 최신 파일**을 베이스로 구현한다       | 모듈별 3-way 비교 결과가 문서로 남고, 채택 근거가 기록된다                                    |
| R4  | 4종을 각각 독립 배포 가능한 npm 패키지로 만든다           | `npm i @txstack/hooks` 만으로 tx-ui 없이 설치·동작한다                                        |
| R5  | 4종 모두 sample / storybook 형태의 테스트 페이지를 갖는다 | 로컬에서 실행 가능한 playground 앱에서 4개 패키지 모두 실동작을 확인할 수 있다                |
| R6  | `docs`, `CLAUDE.md` 를 black-message 기준으로 이식한다    | V 모델 문서 구조와 규약이 신규 저장소에서 그대로 통용된다                                     |
| R7  | 기존 3개 저장소가 이 라이브러리를 소비할 수 있다          | 최소 1개 저장소에서 `src/core` 삭제 후 빌드·타입체크가 통과한다 (별도 요구사항으로 분리 가능) |

## 영향 범위

- **신규 저장소**: `C:\America\Sources\txstack` (본 작업 전부)
- **프론트엔드(기존 3종)**: R7 단계에서만. 본 요구사항 범위에서는 **원본을 건드리지 않는다**
- **백엔드 / DB / 배포**: 영향 없음
- **외부**: npm registry 에 신규 scope `@txstack` 등록 필요

## 제약 / 비고

- 원본 저장소는 이 작업 중 수정하지 않는다. 복사(추출)만 한다.
- 배포 대상이 npm 공개 registry 이므로 사내 도메인/서버명/키 등이 코드·문서에 남으면 안 된다.
- tx-ui 는 Tailwind v4 클래스 문자열을 테마로 쓴다. 소비자 프로젝트의 Tailwind 설정 요구사항이 생긴다.
- React 19 / Node 24.14.0 / pnpm >= 10 기준.
