# 변경 사항 쌓아 두는 자리

**무엇을 바꿨는지는 코드가 아니라 여기에 적는다.** 커밋 메시지는 "왜 그렇게 했나" 를
남기고, 이 폴더의 파일은 **소비자에게 무엇이 달라졌는지**를 남긴다 — 둘은 읽는 사람이 다르다.

## 쓰는 법

```sh
pnpm changeset          # 무엇이 어떻게 바뀌었는지 적는다 (여기에 파일 하나가 생긴다)
pnpm changeset:version   # 쌓인 것을 모아 버전을 올리고 CHANGELOG 를 쓴다
```

`pnpm changeset` 은 세 가지를 묻는다.

1. **어느 패키지가 바뀌었나** — Space 로 고른다
2. **얼마나 바뀌었나** — `major`(깨짐) · `minor`(더함) · `patch`(고침)
3. **한 줄로 무엇이** — 이것이 그대로 CHANGELOG 에 실린다. **소비자의 말로 쓴다**

## 얼마나 바뀌었나

아직 `0.x` 다. **`0.x` 에서는 `minor` 가 깨지는 변경도 담는다** — semver 가 그렇게 정한다.
그래도 깨지는 것은 `major` 로 적어 둔다. `1.0.0` 이 되는 날 그 기록이 그대로 뜻을 갖는다.

| 무엇                          | 어느 것 | 예                                   |
| ----------------------------- | ------- | ------------------------------------ |
| 이름을 바꾸거나 prop 을 뺐다  | `major` | `TxBadge` → `TxTag`                  |
| 컴포넌트나 prop 을 더했다     | `minor` | `TxSwitch` 를 더했다                 |
| 동작을 고쳤다 (API 는 그대로) | `patch` | 다크에서 대비가 모자라던 것을 고쳤다 |

## 배포

**`npm publish` 는 사용자가 명시적으로 요청할 때만 한다.** 되돌릴 수 없다 —
`CLAUDE.md` 의 절대 규칙이다. 명령은 `pnpm release` 이고, 그 안에서 빌드가 먼저 돈다.
