# 사람과 AI 가 함께 일하는 법

> 언제 보나: AI 코딩 도구(Claude Code · Codex 등)에게 일을 맡길 때. AI 도구가 작업을 시작할 때.

## 1. 몫

| 누가 | 맡는 것                                                                                     |
| ---- | ------------------------------------------------------------------------------------------- |
| 사람 | **방향 · 우선순위 · 정책 · 판단.** 범위 합의 · 공개 API 합의 · 화면 확인 · 커밋 · 배포 요청 |
| AI   | 조사 · 초안 · 구현 · 테스트 · 검증 기록 · 문서 정합화                                       |

- **판단이 필요한 일은 사람의 승인 없이 넘어가지 않는다.** AI 는 근거와 추천안을 들고 멈춘다
- **첫 번은 사람이, 반복은 AI 가.** 새 패턴의 첫 구현은 사람이 하고, 그것이 본보기가 된 뒤의 반복 · 테스트 · 정리를 AI 가 맡는다
- 도구가 둘이면(예: Codex 가 문서, Claude Code 가 구현) 그 나눔을 프로젝트의 `00_DEV_GUIDE_DIFF.md` 에 적는다
- 한 폴더에서 두 도구가 같은 파일을 동시에 고치지 않는다

## 2. 그대로 따르지 않고 다시 제안한다

지시 · 계획 문서 · AI 의 이전 판단은 **출발점**이다.

- 지시한 방식이 낡았거나, 오류 · 보안 문제 · **사실과 다른 전제**가 있거나, 더 단순하고 안전한 길이 있으면 **구현 전에** 다시 제안한다
- 제안에는 문제 · 근거(읽은 코드 · 문서 · 실행 결과) · 대안 · 각 안의 영향(변경량 · 위험 · 되돌리기) · 추천안
- 사람이 알고 고른 방식이면 따르고, 결정과 날짜를 기록한다. 같은 제안을 이유 없이 되풀이하지 않는다
- 판단을 기다리는 동안 그와 무관한 일은 계속한다

## 3. 되돌리기 어려운 일은 요청할 때만

커밋 · 푸시 · 배포 · `npm publish` · 데이터 삭제 · 외부로 보내는 일(메일 · 문자 · 실제 API 호출).
프로젝트가 다르게 정했으면 `00_DEV_GUIDE_DIFF.md` 에 결정과 날짜가 있어야 한다.

- 기존 변경을 되돌리지 않는다. 관련 없는 파일을 건드리지 않는다
- 지우기 전에 무엇을 지우는지 본다

## 4. 증거로 말한다

- "됐다" 고 쓰기 전에 실행한다. 실행한 명령과 결과를 남긴다
- 통과 · 실패 · 미실행을 나눈다. 확인하지 못한 것은 그렇다고 쓴다
- 문서에 "구현 완료" 라고 쓰는 것과 실제로 구현 · 검증한 것을 구분한다
- 빌드가 만든 산출물 · 임시 파일이 작업 트리에 남지 않았는지 `git status` 로 본다

## 5. AI 도구의 시작 문장

```text
CLAUDE.md · CURRENT.md · docs/README.md 를 읽고, CURRENT.md 「다음 할 일」의 계획에서 다음 미완료 단계를 해줘.
지시나 계획에 낡은 기술 · 오류 · 틀린 전제가 보이면 구현 전에 근거와 대안을 들어 다시 제안해.
판단이 필요하면 멈추고 물어.
실행한 명령 · 결과 · 남은 결정 · 다음 할 일을 같은 번호 verification 에 남기고, CURRENT.md 와 README 의 명령을 맞춰.
커밋 · 푸시 · 배포는 내가 요청할 때만.
```
