# 작업 공간 · 의존성 · 환경 변수

> 언제 보나: 새 프로젝트를 만들 때, 앱 · 패키지 · 의존성 · 환경 변수를 더할 때.

## 1. 도구 — 고정한다

| 항목             | 규칙                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 패키지 매니저    | **pnpm 만.** npm · yarn lockfile 을 만들지 않는다. `packageManager` 필드에 버전을 적는다 |
| Node             | 버전 하나로 고정 — `.nvmrc` 또는 `.node-version` + `engines.node`                        |
| lockfile         | 커밋한다. CI · 서버는 `pnpm install --frozen-lockfile`                                   |
| lint · 포맷 설정 | **루트가 갖는다.** 앱 · 패키지에 따로 두지 않는다                                        |

## 2. 폴더 — 실행 단위와 재사용 단위

```text
apps/       실행 단위 — 혼자 실행 · 빌드된다
packages/   재사용 단위 — 둘 이상의 앱이 함께 쓰는 것
docs/       개발 문서 (process/docs-structure.md)
scripts/    배포 · 운영 스크립트
```

- **앱끼리 서로 import 하지 않는다.** 함께 쓸 것은 `packages/` 로 뺀다
- **쓰는 곳이 둘 생길 때 패키지를 만든다.** 미리 만들지 않는다
- 앱 이름은 짧은 한 낱말(`web` · `admin` · `api` · `frontend` · `backend`). 스크립트 이름의 대상이 된다 ([scripts.md](scripts.md))
- 사용자 화면과 관리 화면은 앱을 나눈다 — 관리 코드 · 무거운 의존이 사용자 번들에 섞이지 않는다

## 3. 의존성

- **새 라이브러리를 들이면 고른 이유를 그 작업 문서에 적는다**
- 무거운 선택 기능(표 · 달력)은 쓰는 앱에만 설치한다
- 다른 저장소의 패키지는 **npm 버전**으로 쓴다. 함께 고칠 때만 `link:` 로 잠시 덮고, 커밋 전에 되돌린다
  - `link:` 를 되돌릴 때 **선택 peer 의 버전을 다시 본다** — 링크된 쪽 `node_modules` 의 peer 를 쓰므로 틀린 버전이 가려진다
  - 링크하는 동안 React 가 두 벌 되지 않게 `resolve.dedupe: ["react", "react-dom", "react-router-dom"]` (Vite)

## 4. 환경 변수

| 어디       | 규칙                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 프런트     | **`VITE_*` 는 브라우저에 그대로 실리는 공개 값이다.** 비밀 · 키 · DB 주소를 넣지 않는다 |
| 서버       | 비밀은 서버에만. 시작할 때 필수 값을 검사하고 **없으면 바로 멈춘다**                    |
| 파일       | `.env.example` 에 키 이름과 예시 값을 둔다(커밋). 실제 값 파일은 커밋하지 않는다        |
| 로그 · Git | 비밀값을 남기지 않는다                                                                  |

**환경 이름은 `local` · `dev` · `live` 셋.** 스크립트 변형(`build:frontend:live`) · Vite 모드 · `APP_ENV` 가 같은 낱말을 쓴다.

## 5. 데이터

- 운영 DB 변경은 migration 으로만. 되돌리는 방법을 같이 검토한다
- 개발용 더미 데이터를 운영에 넣지 않는다
- 외부 서비스(문자 · 결제 · 외부 API)는 승인 전까지 **합성(가짜) 구현**으로 개발한다. 실제 호출을 켜는 스위치는 명시적으로
