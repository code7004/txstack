# 개발 용어

> 언제 보나: 문서 · README · 화면 문구 · 주석을 쓸 때. 개발 용어를 한국어로 바꿔 지어 부르고 싶을 때.

## 1. 개발 용어는 영어로 쓴다

**개발 용어는 영어 원어로 쓴다. 한국어로 풀어 새로 지은 말을 쓰지 않는다.**
지은 말은 처음 읽는 사람이 무엇을 가리키는지 알 수 없고, 검색 · 공식 문서 · 코드 이름과 이어지지 않는다.

| 쓰지 않는다                 | 쓴다                                          |
| --------------------------- | --------------------------------------------- |
| 부품                        | component                                     |
| 겹쳐 뜨는 것 · 위에 뜨는 것 | overlay                                       |
| 화면 껍데기 · 앱 골격       | app shell                                     |
| 이름표                      | badge · tag · label — 가리키는 것에 맞춰      |
| 펼침 · 펼침 목록            | collapsible · accordion                       |
| 고르기                      | select · picker · choice — 가리키는 것에 맞춰 |
| 배치 (화면 구성을 뜻할 때)  | layout                                        |

표에 없는 말도 같다 — **영어로 부르는 이름이 이미 있으면 그 이름을 쓴다.**

## 2. 이름 자리는 영어, 설명은 한국어

분류 이름 · 표 머리글 · 목차 항목처럼 **무엇을 부르는 자리**는 영어로 쓰고 첫 글자를 대문자로 한다.
그 뒤의 설명은 한국어로 쓴다.

```md
| Types   | Components                   |
| ------- | ---------------------------- |
| Input   | `TxInput` · `TxTextarea` · … |
| Overlay | `TxModal` · `TxDialog` · …   |

**Overlay** — 화면 위에 뜨는 것. 모달 · 다이얼로그 · 툴팁 · 토스트
```

## 3. 그대로 두는 것

- **굳은 음역은 본문에서 써도 된다** — 컴포넌트 · 토큰 · 훅 · 스토리 · 서브패스. 한 문서 안에서는 한 가지로 쓴다
- **일반 한국어 낱말 · 동사는 그대로다** — "입력한다", "고른다", "목록을 불러온다". 바꾸는 것은 개발 개념을 가리키는 이름이다
- **코드 식별자는 백틱으로 그대로** — `TxButton` · `onClick` · `--tx-color-primary`
- 커밋 메시지 · 문서 본문의 언어는 [commits.md](commits.md) · [../process/docs-structure.md](../process/docs-structure.md) 를 따른다 — 본문은 한글이다
